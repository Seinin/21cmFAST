## Purpose

给图谱加一层**全局标签**：图级注册的标签（id / 名称 / 说明），节点按 id 归属，并可以携带「这个标签在此节点上具体是什么」的明细。勾选标签后，有该标签的模块在画布左上角点亮小红点；点红点在属性面板展开明细。首个标签用于标记「哪些模块有用户参数 / 宇宙学参数参与（赋值、进入公式、当开关）」。

## Requirements

### Requirement: 标签注册表与节点标签归属

图谱 MUST 维护一份图级**标签注册表**：每项含 `id`、`name`、`description`，可选 `color`。节点 MUST 通过**标签 id** 关联标签（不是自由文本）；同一标签名 MUST 只对应一个注册项。改名 MUST NOT 影响任何节点的归属；引用未注册 id 的节点 MUST 被拒绝写盘或在校验时被清理并给出原因。从自由文本标签迁移而来的归属 MUST 全部保留（同名合并为一项）。

#### Scenario: 改名不影响归属

- **WHEN** 把标签「宇宙学」改名为「宇宙学参数」
- **THEN** 所有原本带该标签的节点仍带它，红点与明细都不变

#### Scenario: 未注册标签被拒绝

- **WHEN** 给节点写入一个注册表里不存在的标签 id
- **THEN** 服务端拒绝这次写入并指出是哪个 id

#### Scenario: 迁移不丢归属

- **WHEN** 把现有自由文本标签迁移进注册表
- **THEN** 每个原本带标签的节点仍带着同名标签，节点数、关系数与其它字段不变

### Requirement: 节点标签明细

节点 MUST 能携带**标签明细**：`tagId → 明细条目列表`，每条含 `label`（必填）、可选的 `kind`（该标签在该节点上的角色，如「赋值 / 入公式 / 开关」）、可选的 `note` 与可选 `ref`（源码文件 + 行区间 或 notes 文档锚点）。没有明细的归属 MUST 合法（只有归属、暂无名细）。明细 MUST 与归属解耦：删除明细 MUST NOT 删除归属，反之亦然。

#### Scenario: 有归属无明细

- **WHEN** 某节点带标签但尚无明细条目
- **THEN** 数据合法；画布照常亮红点，属性面板显示「暂无明细」

#### Scenario: 明细可点开出处

- **WHEN** 明细条目带有源码引用
- **THEN** 在属性面板点击该条目可以打开对应的源码预览（复用现有引用预览链路）

### Requirement: 顶栏标签勾选

顶栏 MUST 提供「标签」入口，列出全部已注册标签、每个标签的**命中节点数**与复选框。勾选状态 MUST 是纯视图状态：MUST NOT 进入撤销栈、MUST NOT 落盘。默认 MUST 一个都不勾选。存在被勾选标签时，界面 MUST 能看出当前勾了哪些（例如入口上显示计数）。

#### Scenario: 勾选后计数可见

- **WHEN** 打开标签入口并勾上「参数参与」
- **THEN** 该标签旁显示被标节点数，入口处能看到「已勾 N 个标签」

#### Scenario: 勾选不产生落盘改动

- **WHEN** 勾选或取消勾选任意标签
- **THEN** 图谱处于「已保存」状态（不标脏、不触发保存）

### Requirement: 画布红点标记

当至少一个标签被勾选时，**同时持有任一被勾选标签的模块** MUST 在**左上角**显示一个小红点；红点 MUST 随节点缩放与平移一起走（同一节点在任意缩放下红点都在左上角）。装饰容器 MUST NOT 显示红点（容器不参与标签，与「容器只作分组」一致）。没有任何标签被勾选时 MUST NOT 出现红点。

#### Scenario: 勾选后模块亮红点

- **WHEN** 勾选「参数参与」
- **THEN** 所有被标该标签的模块左上角出现小红点，未标该标签的模块与容器不出现

#### Scenario: 取消勾选即熄灭

- **WHEN** 取消勾选「参数参与」
- **THEN** 画布上不再有任何红点

### Requirement: 点红点看明细

点击红点 MUST 选中该节点，并让属性面板展开**该标签**的明细（标签名、说明与该节点的条目列表）。点红点 MUST NOT 触发拖拽、连线或移动节点。

#### Scenario: 点红点看参数明细

- **WHEN** 点某个模块左上角的红点
- **THEN** 该模块被选中，属性面板展开「参数参与」的明细（参数名 · 用法 · 出处）

#### Scenario: 点红点不误触其它手势

- **WHEN** 在红点区域按下并拖动
- **THEN** 节点不被拖动、也不进入连线模式

### Requirement: 属性面板标签区块与标签编辑

属性面板 MUST 有一个标签区块：列出当前节点的标签（名称 + 说明），并可按标签展开明细条目（条目含 `label`、`kind`、`note`、可点开的 `ref`）。标签编辑 MUST 从注册表里多选，并 MUST 支持新建标签（新建即写入注册表并归属到该节点）。自由文本标签输入 MUST 被移除（避免出现「注册表外的标签」）。

#### Scenario: 多选归属

- **WHEN** 在属性面板给节点多选两个标签
- **THEN** 两个标签都归属到该节点，画布上对应的红点图标随勾选状态出现

#### Scenario: 新建标签即注册

- **WHEN** 在属性面板输入一个注册表里没有的标签名并确认
- **THEN** 该标签进入注册表（带说明占位）并归属到当前节点；其它节点也可以再选它

> **注（标签命名与首个标签口径的取代关系）**：本能力原 delta 还有第 7 条需求「首个标签『参数参与』的数据形态与覆盖口径」，该口径已被后续变更 `graphify-param-only-tags` 取代，并落在主规格 `graphify-graph-annotations` 的「标签只服务参数」：标签注册表 MUST 只保留按参数名注册的参数标签（带 `group`），「参数参与」这类聚合标签与自由文本标签 MUST NOT 存在。故本条规格只收录前 6 条需求，历史原样见 `openspec/changes/archive/2026-09-30-graphify-global-tags/`。据此，上文中作为示例出现的「参数参与」SHALL 读作「某个已勾选的参数标签」（如 `tag:hlittle`），其明细条目 MUST 至少给出参数名、用法类别与出处。
