## Context

见 `proposal.md` 的 Why。这里只记与做法相关的现状与约束：

- 一级的块坐标现在由生成器按 `order` 铺 **y**（纵向一列），`GAP` 是唯一间距数（`docs/notes/graphify/G4-物理链.md` §一）。
- 分层模型（`crossLevel.levels` / `backbone` / `parentOf` / 边上的 `levelSpan` / `spanKind`）不产自文献，产自"没有布线手段时的替代品"：它让每条边都有一个层差，从而能判断"该不该鼓弧绕开"。**前端一处都不读它**（`Graphify/src` 里搜不到 `crossLevel`），消费者只有生成器（排成员坐标）与自检（十几条断言）。
- 线的样式集中在 `Graphify/src/graph/palette.ts`（档位表与人话标签）+ `styles.ts`（cytoscape 规则）。目前非实线有 `dotted`（宽 1.3，`cross-link` 与 `contradicts`）、引擎缺省 `dashed`（`relates_to` 与 `conditional` 共用、肉眼不可分）、`line-dash-pattern: [10,5]`（只有 `feedback` 写了）。图例样例的节奏（`EDGE_STYLE_DASH`）与样式表**不同源**。
- `data/graph.json` 里 `relates_to` / `contradicts` / `undirected` 各 **0 条**（只有 `depends_on` 31 + 4 条件、`derives_from` 16 + 8 条件）。
- 渲染层已有：端口吸附（`EdgePort` / `sourcePort` / `targetPort`）、`group` 装饰容器、`focusOnly` 的"静息不画、悬浮显现"、按元素报出"此刻真画出来的线型"（`presentEdgeStyles`）。

## Goals / Non-Goals

**Goals：**

- 让一级的**顺序**由摆放承担，不再靠"到终点的最长路径"分层来间接表达。
- 让"跨了几步"变成几何事实（道深），并从线型与颜色里彻底退出。
- 让线型与语义一一对应，且在最难的取景缩放下仍可辨。

**Non-Goals：**

- 不改 `src/py21cmfast/**`（不碰仿真代码）。
- 不改画布页已有 51 条边的内容，也不改画布页的排布模型（父→子层级连线照旧）。
- 不做自动避让/力导向：摆放是**确定性**的，不引入 dagre / elk 一类依赖。
- 不解决跨红移"6 条只画出 2 条"的历史欠账（`G4` §七 第 9 条，另一次改动）。

## Decisions

### D1 分层模型整体退场

`crossLevel` 全家与边上的 `levelSpan` / `spanKind` 删除。理由：它们的职责是给每条边算一个"层差"来安排箭头，而一级改成三段横排之后，块的先后由摆放读得出来、跨步依赖由悬浮箭头表达，层差不再承担任何事；深度这一维撤掉后，13 条「缺中间量」告警一并消失（它们全是"层差 > 1"的派生，其中 5 条是上一轮把 `perturb_field → dn_dm` 换源成 `initial_density → dn_dm` 的副作用）。

- 备选 A：只删成因分类、留层号——仍要维护层号，且"跨 9 层"那两条（`initial_density → zeldovich_velocity` 一类）照样留着。
- 备选 B：改分层算法（给没有下游的量按生产者定层）——改动面更大，而且还是在维护一棵不需要的树。
- 代价：`levels` 同时被生成器用来排**成员**坐标，所以成员排布要换判据（见 D5）。

### D2 一级改为三段 + 段内横排，`order` 语义随之变更

三段（预备 / 逐红移循环 / 收尾）自上而下竖摞，段与段之间让的是**段框**（框与框之间 = `GAP`）；**段内**按 `order` 沿 x 排开，同段同一条 y。`order` 的语义由"纵向位次"改为"**段内横向位次**"，数据字段不变（避免真源大改）。

- 备选（已弃）：段内保持竖排——那样"某一步在另一块之前"仍只能逐个悬浮去读，正是本变更要解决的问题。
- 影响：生成器的坐标部分要改写；自检现有"一级版面"那行输出仍有效，但要盯住**变宽导致的取景缩字**（见 Risks）。

### D3 分道用区间图着色，三级 tie-break 保证幂等

**（已作废：总线方案已撤，见 D1 与 tasks 1.10）** 块间交付边不分道，产物里没有道号，视图也不按道算偏移。

### D4 折线用 cytoscape 的 `segments`

**（已作废：同上）** 交付边不走折线，物理链的产物不写端口字段；端口吸附机制本身是画布页既有的能力，留着不动。

### D5 子图成员排布改判据：块内拓扑序

成员原按 `level`（层号）横铺（"同一深度等高"）。层号撤掉后，改用**块内边的拓扑序**（从入到出）定序，真源里块声明的对外输入灰显节点排在**最左**。

- 备选：按真源 `module.products` 的书写次序——那会把"为什么这个在左"变成不可解释的魔法；拓扑序能被自检从块内边重算。

### D6 线型收敛到两种，「条件 / 可选」改挂开关框

实线 = 交付（块间、块内；对外输入是更细更浅的弱化版），稀疏虚线 = 跨迭代（跨红移回流）。所有虚线 MUST 显式写 `line-dash-pattern`、首项 ≥ 8、线宽 ≥ 1.7，MUST NOT 出现 `dotted`。

- 机制理由：`line-dash-pattern` 的单位是**模型单位**，随缩放一起缩；取景 0.5× 时 `[4,4]` 变成 `[2,2]` 屏幕像素，渲染出来就是一条灰实线——"密虚线"这个选项在最需要读的缩放下必然消失，所以它不该存在。
- 条件改用**线上挂开关框**：线型只剩两种，没有余量给"条件"；且现行 G0「虚线只表示条件 / 可选」与新语义（虚线 = 跨轮）直接冲突，必须二选一，取新语义。字段与校验（`conditional` ⇔ 标题含可选字样）不变。
- 备选：保留"条件 = 虚线"、让交付边全用实线、跨红移用颜色区分——这样线型仍只有两种，但"虚线"这一通道被条件占住，而条件本身可由框表达，优先级更低。

### D7 关系类型枚举删到两种

`relates_to` / `contradicts` / `undirected` 从类型联合、外观档位、图例档名、新建边下拉与数据 schema 中删除。

- 证据：三者各 0 条；图例自上一轮起按"此刻真画出来的"派生，所以它们**从不显示**；留着只有三处死代码与一个洞（真新建一条 `contradicts` 没有外观，会落到兜底样式）。
- 取舍：将来真需要"相关/相斥"时再加回来的成本（改一个联合类型 + 一个档位）低于长期维护空档位的成本。

### D8 段用 `group` 容器承载，撤销 `band` 这一新种类

段标题与"哪些块在同一步里"需要一个看得见的框。上一版为此新立了一个非容器种类 `type: 'band'`（缎带）：透明底 + 虚边、尺寸由生成器算、渲染层为它单开一条"尺寸由数据给"的口子、再单写一条"悬停点亮同段"。改回 `group` 容器。

理由：容器这条路在本仓库里**已经是现成的**，画布页的层带用的正是它——compound 撑开尺寸（`measureGroupSize` 给下限、子节点撑开实际大小）、标题贴左上角且任何缩放下都留着（`applyLabelScale` 里对大框单独免除 LOD）、坐标由子节点包围盒推导（空框才吃存档坐标）、不进悬停 / 标签 / 关系 / 图例、不可进入。缎带比容器少一件事（不参与 compound），却多四处特判；更关键的是"这一段"只能靠悬停才看得出来，而容器是**把块装进去**——静息即读得出来。

- 备选（已弃）：`type: 'band'` 装饰节点。它要同时照顾类型表、样式规则、图例排除、命中排除四处，且与容器语义并存等于同一件事两套机制。
- 备选（已弃）：段不进数据、由视图按块坐标画叠加层——要新增"跟随平移缩放"的锚定机制（现有浮层都是屏幕锚定的），且"段"这件事没法被自检钉住。
- **两条断言的口径随之下移**：产物里不再禁止 `group`，改成「容器只许是四个段容器（`seg:*`），别处不得出现容器」。被挡的原意保留：不回到按**代码阶段**编号分层的阶段框——段是三段执行骨架（预备 / 逐红移循环 / 收尾）加两个横切层，与代码里的阶段编号无关。
- 代价：块的 `parent` 从顶层变成段容器。一级的可见集因此靠 `hierarchy.ts` 的"顶层 + 装饰容器后代（递归）"——容器与块可见、块的成员仍只在块自己的标签页里；容器不进悬停态（既有约定），"点亮同段"这个交互随之消失，段的范围改由**包含**表达。

## Risks / Trade-offs

- **取景变宽导致字号变小**：段内横排会让一级从"高瘦"变"宽扁"，而取景是按框取景的。缓解：自检那行「一级版面 宽 × 高：取景倍数 ≈ 画布高 / 高」在实施时逐次盯住；必要时压段内 `GAP`（已是唯一间距数，压一处即全局一致）或让段标题竖排贴段左缘。
- **断言总数会下降**：删掉整节「分层：骨干树 + 跨层成因」后，`check:chain` 的条数从 273 降到 259。缓解：在 tasks 里显式记下"删了多少、加了多少"，避免"数量掉了但没人说"；新增的那条（块行 x 序 = 主循环调用序）必须是**独立重算**式的可证伪断言。
- **"相关"与"条件"合并后信息丢失**：条件改挂框，若框在缩小后不显眼，区分度会掉。缓解：框本身带开关名（比一根虚线承载的信息更多）；若仍不显眼，回退代价只是改一枚图标。
- **回滚**：本变更只动图的数据与外观，不碰仿真代码；回滚 = 还原产物、视图与样式表三处（`git checkout` 相应文件即回到旧版面）。

## Migration Plan

按"先让数据与断言自洽，再改外观"的顺序做，否则图例会先跟画布脱钩：

1. 生成器：段内横排坐标、删 `crossLevel`、写红移内步序 → 重建产物；
2. 自检：删分层那一节，加"块行 x 序 = 主循环调用序"一条新断言；
3. 样式与图例：`palette.ts` / `styles.ts` 收敛线型、条件挂框、图例样例；
4. 数据 schema 与编写面：删三种关系类型（`types.ts` / `EntityDialogs` / `data/graph.json` / `check:graph`）；
5. 文档：G0（虚线语义整句改写）、G4（摆位、图例、§七 第 10 条）、`docs/DIRECTORY.md`。
