## ADDED Requirements

### Requirement: 一级按三段骨架与执行序摆放

物理链页一级 MUST 显示**三段骨架**：**预备（一次性）**、**逐红移循环**、**收尾**。段 MUST 由**摆放**表达——段标题 MUST 在静息状态下可读，MUST NOT 只在悬浮提示里说明，也 MUST NOT 依赖任何连线来划分段。

段在数据里 MUST 由**容器节点**承载（`type: 'group'`）：容器带段名，它的子节点就是该段的块——"哪些块在同一步"因此由**包含**表达，静息即读得出来。**循环段的那个容器 MUST 装下循环段的全部块**，且每个块 MUST 恰有一个段容器作父级。容器的口径与画布页的装饰容器同一套：MUST NOT 参与标签、MUST NOT 可进入、MUST NOT 带任何关系边、MUST NOT 进图例的「要素种类」、MUST NOT 进悬停态。产物里的容器 MUST 只有这些段容器（`seg:*`），MUST NOT 出现按**代码阶段**编号分层的阶段框——段是执行骨架，不是代码里的阶段号。

段内块的**横向次序 MUST 等于该段在代码里的执行序**：循环段的次序 MUST 与主循环（`drivers/coeval.py` 的 `_redshift_loop_generator` 里对 `compute_halo_grid` / `compute_xray_source_field` / `compute_spin_temperature` / `compute_ionization_field` / `brightness_temperature` 的调用序）逐条一致；块的位次 MUST 来自真源，视图 MUST NOT 自行排序。

一级 MUST NOT 画「下一步」连线：相邻步的先后 MUST 只由摆放表达。页面 MUST NOT 为此引入脊轨、步序刻度、圆圈数字或任何替代标记。一级静息时 MUST 只有块（与本页既有的两个横切层），MUST NOT 出现任何常显的依赖连线。

#### Scenario: 静息时只有块与段

- **WHEN** 打开物理链页，不动任何开关、不悬浮任何对象
- **THEN** 画面上只有块与两个层，加上四个段容器（段名常显）；没有任何依赖连线、没有脊轨、没有步序刻度

#### Scenario: 循环段的次序与代码一致

- **WHEN** 把主循环里两步的调用顺序对调后重建产物
- **THEN** 自检失败并指名是哪两块与它们各自的位次（块行的横向次序不再等于代码调用序）

#### Scenario: 段分界不靠连线也不靠悬浮

- **WHEN** 关掉所有可关的连线开关、并把指针移出画布
- **THEN** 仍能读出三段各自的标题、范围（哪些块在循环里）与先后

#### Scenario: 段是容器，不参与关系与导航

- **WHEN** 运行物理链自检
- **THEN** 四个段容器都在产物里、循环那个装下循环段全部块、每个块恰有一个段容器作父级；容器不带标签、不可进入、一条边都不相连，且产物里除它们之外没有任何容器（MUST NOT 有按代码阶段编号分层的阶段框）

#### Scenario: 段的范围由包含表达

- **WHEN** 静息查看画布（不悬浮、不点选）
- **THEN** 每个块的从属关系由它落在哪个容器里读出，不需要悬停或展开；容器不留悬停态（与画布页的装饰容器一致）

#### Scenario: 段容器不参与图例与标签

- **WHEN** 打开图例看「要素种类」，或在段容器上找标签红点与「进入子图」入口
- **THEN** 图例的要素种类里不出现段容器；段容器上没有红点、也没有进入入口（它不带标签、不可进入、一条边都没有）

## MODIFIED Requirements

### Requirement: 一级摆位的尺寸与距离同源

物理链页一级的摆位 MUST 由**两个数**决定，且只能是这两个数：**框的宽高**问尺寸口径（`src/graph/labels.ts`，与画布画框用的是同一套公式），**间距**是一个与框大小无关的常数（`GAP`）。生成器 MUST NOT 用写死的框尺寸去铺坐标（同一份"框有多大"不许有两套数）。

一级 MUST 按三段摆放（见「一级按三段骨架与执行序摆放」）：三段自上而下竖摞，**每一段内部**按块的位次**横向**排开——**段即一条水平带**，同段的所有块同一条 y。块的位次 MUST 取自真源，MUST NOT 由视图临时推断。

由此 MUST 成立四条：

1. **成比例**：块、块内成员、成员内步骤、框外带，一律按各自的实测宽高依次让开，间距恒为 `GAP`；每段的高度 MUST 取该段最高的块，**段与段之间让的是框**——让位 MUST 按段框算（框 = 本段块并集 + 上下各一圈容器内边距），**框与框之间**同样恒为 `GAP`。同一块的成员 MUST 仍与自己块同一条水平带（y 相同）。
2. **框装得住、也让得开**：段容器 MUST 装住本段的块，相邻两段的容器框 MUST NOT 相压——段的让位 MUST NOT 只按块高算（框会切过邻段的块与名字）。
3. **距离不过大**：任何相邻两框之间的空隙 MUST NOT 超过这两框里**较小的那条短边**（空的地方不许比实的地方还大）。
4. **全图一个间距**：同段的块、同块的成员、同成员的步骤、相邻两段（量**框到框**），量到的空隙 MUST 是同一个数（四处排法各自独立，但必须落在同一个间距上）。

尺寸口径在脚本侧 MUST 只有一份副本（`scripts/lib/boxSize.mjs`），且该副本与 `labels.ts` MUST 逐字同口径；脚本内部 MUST NOT 各自再写一份尺寸公式。自检 MUST 用**画布的口径**（真跑 `labels.ts`）量框，MUST NOT 抄一份公式来量。

容器框在块外占的那一圈也 MUST 同源：画布侧是样式表 `node:parent` 的 `padding`，脚本侧是 `boxSize.mjs` 的 `FRAME_PADDING`；自检 MUST 从样式表读它、MUST NOT 抄一份数，两份一旦漂移，「全图一个间距」当场失败。

#### Scenario: 框大，整片跟着大

- **WHEN** 某个块的名字变长（折成两行、框高从 38 变成 45）并重新生成
- **THEN** 它所在那一段的行高随之变成 45，下一段整体下移；**框与框之间**的空隙仍是同一个常数

#### Scenario: 写死步长会被当场抓住

- **WHEN** 把某一处的间距改回写死的坐标步长（如 300）并重新生成
- **THEN** `npm run check:chain` 失败，报出量到的两个间距值（如 `182.5 / 24.0`），退出码 1

#### Scenario: 距离不许比尺寸还大

- **WHEN** 生成物里出现一个空隙大于相邻两框较小的那条短边（如空隙 182.5、短边 38）
- **THEN** 自检报出这对框与两个数，失败

#### Scenario: 两份口径漂移会被发现

- **WHEN** 只改了 `labels.ts`（或只改了 `scripts/lib/boxSize.mjs`）的字号 / 内边距 / 折行规则
- **THEN** 生成物的坐标（按副本算）与画布尺寸（按 `labels.ts` 算）不再吻合，空隙不再是同一个数，`check:chain` 的「全图一个间距」断言失败

#### Scenario: 相邻两段的框不许相压

- **WHEN** 段的让位只按块高算（不给容器框在块外占的那一圈留余量）并重新生成
- **THEN** 画布上相邻两段的框在纵向叠进来（实测 `seg:layer` 压进 `seg:prep` 45.6），框线切过邻段的块；`check:chain` 的「相邻两段的框不相压」断言失败

#### Scenario: 不打开浏览器也能读到"字多大"

- **WHEN** 跑 `npm run check:chain`
- **THEN** 输出里有一行 `一级版面 <宽> × <高>（框 <宽域> 宽 × <高域> 高，空隙 <值>）：取景倍数 ≈ 画布高 / <高>，屏幕字号 = 13 × 那个倍数`

#### Scenario: 段内横排（同段同一条 y）

- **WHEN** 查看生成物里任意一段的块坐标
- **THEN** 同段所有块的 y 相同、x 依次递增且递增方向等于块的位次；段与段之间的 y 差 = 该段**框**高 + `GAP`（框高 = 该段块并集 + 上下各一圈容器内边距）

### Requirement: 反馈边必须上主图

代码里改写晕质量阈值的三条反馈回流 MUST 在一级可见：电离反馈（`ionisation_rate_G12` / `z_reion`）、LW 反馈（`J_21_LW`）、相对速度反馈（`lowres_vcb`），三者都回到源项块的 `M_turn`。页面 MUST NOT 因"一级只画自下而上"的美术约定丢弃这些反向边。

#### Scenario: 三条反馈边可见

- **WHEN** 在源项块上悬浮
- **THEN** 三条反馈各自以反向箭头显现，标签写明流过来的量与它的上游块

#### Scenario: 反向箭头有自己的样式

- **WHEN** 对照图例
- **THEN** 回流边与交付边是两种可区分样式（交付为实线、回流为稀疏虚线），图例写明两者的区别（「跨红移回流」与「同一红移内的数据流」两条各自成条）

### Requirement: 跨红移回流默认不画

物理链页的画布 SHALL 默认不呈现跨红移回流边。开关未打开时，画布上 MUST NOT 出现这类边；打开后 MUST 全部显现。哪些边属于跨红移回流 MUST 由生成物的字段决定（跨红移回流带独立种类标记），视图 MUST NOT 写死边的名单、条数或端点。

关闭状态下的主序图 MUST 无环：默认可见边构成的有向圈数 MUST 为 0；打开后回流边显现（"关＝无环、开＝回声"是可证伪的口径）。关闭 MUST NOT 变更任何数据、MUST NOT 挪动任何元素坐标、MUST NOT 触发重排、MUST NOT 让主序边消失或改样式。

跨红移回流边 MUST 显式表达"回流"：其箭头方向 MUST 与主序的摆放方向（段内自左向右）相反，且 MUST 带可读的物理标签（给出回流的两端量，如 `T_S(z)` 与电离率、`Q_HII(z)` 与电离率）。

本条的管辖范围 MUST 只由产物标记界定：只辖**已标为跨红移回流**的边（两端皆为一级块，今天 2 条）。子图里 MUST NOT 画这条块间弧（弧的两端是一级块），但 MUST NOT 因此丢掉这条关系：同一关系 MUST 在**弧两端块的子图里各落到成员级一次**——由产物所记的两端量（`fromNode` → `toNode`，即上一轮送出的量与这一步读它的量）派生成员级边，方向恒为 `fromNode` → `toNode`，对面的那个量 MUST 与块声明的对外输入同样灰显（收方块并进来处 `fromNode`、来源块并进去处 `toNode`，且 MUST NOT 与本块已声明的对外输入重复）。两侧的说法不同：收方块那侧读作"这一步把它读进来"（本块的对外输入），来源块那侧读作"上一轮把它送出去"（本块的对外输出）；只画一侧会让另一侧的读者看到一条与主图相反方向的边、或干脆看不到这条关系。

这两条成员级边各 MUST 只在**自己所声明的那一块**的标签页里显形，MUST NOT 出现在主图或别的块的子图里；一条弧在某一刻至多显形一条，MUST NOT 两端同时显形。它们与一级那条弧是同一件事的视图面，MUST **同进同出**：开关关闭时这些边与落点那些量 MUST 一起不画，打开时 MUST 一起显现，MUST NOT 出现一个显一个隐；开合 MUST NOT 改变样式与坐标，MUST NOT 增删元素。别的块的子图里若那两个量同场，画的 MUST 是那个块自己的关系（本块的那条边），MUST NOT 是这条落点。这条落点 MUST NOT 被弱化为"从对外输入指进本块"的那档灰细样式——同一条关系在一级与子图里 MUST 是同一档外观。

同一张子图里的边 MUST NOT 有两条同端点对（含反向）、又都走直线：直线画在同一个端点对上会完全叠住，读成"这里只有一条关系"，反向的那个箭头被盖掉。落点常与本轮的产物边**同端点对、方向相反**（`Ṅ_ion → Q_HII` 与落点 `Q_HII → Ṅ_ion`），而产物边走直线——所以落点边 MUST 走曲线并鼓开一格，MUST NOT 依靠渲染器的自动错开（自动错开只在同一种 `curve-style` 的平行边之间生效，产物边与落点边不同档，靠不住）。

其余带红移的依赖不属本条管辖，MUST NOT 因此新增边或标记：同一轮内带红移标签的依赖边（如 `ε_heat(z) → T_K(z)`）MUST 照常可见且不受开关影响；块内「读上一轮同名量」的累积（如 `ts_main` 的 `previous_spin_temp`）与方向顺向的上一轮输入（如 `ComputeIonizedBox` 的 `previous_perturbed_field`、`previous_ionize_box`）今天不是边，本条 MUST NOT 管辖它们，MUST NOT 借开关把它们画出来——把这类跨红移输入一并纳入开关，属于先建边、再统一标记的另一个变更。

#### Scenario: 默认关闭时画布上没有回流边

- **WHEN** 打开物理链页，不动开关
- **THEN** 画布上不出现任何跨红移回流边，且当前可见边构成的有向圈数为 0

#### Scenario: 打开后回流边显现

- **WHEN** 打开「跨红移反馈」开关
- **THEN** 产物里的每一条回流边都显现（条数与产物一致），箭头指向与主序的摆放方向相反，标签给出回流的两个端量

#### Scenario: 关与开都不动版面

- **WHEN** 记录当前各元素的坐标，关闭开关再打开再关闭
- **THEN** 往返之后所有元素的坐标与字样逐字不变，布局未重排

#### Scenario: 别的块的子图里开合不动版面

- **WHEN** 聚焦一个既不是落点收方块、也不是它的来源块的块，在它的子图里反复开合开关
- **THEN** 子图的可见边集合与各元素坐标逐字不变（开关在这张子图里没有可管对象）

#### Scenario: 收方块的子图里这条关系落到成员级

- **WHEN** 开关打开，进入回流的目标块（收方块）的子图
- **THEN** 画布上出现一条成员级边：由上一轮送出的那个量指向这一步读它的量，来处那个量灰显为对外输入
- **AND** 关闭开关后这条边与来处那个量一起不画，再打开时一并复原，各元素坐标逐字不变

#### Scenario: 来源块的子图里同一条关系换一侧讲

- **WHEN** 开关打开，进入回流来源块（上一轮送出那个量的块）的子图
- **THEN** 画布上出现一条成员级边：同一个端点对、同一个方向、同一档样式，去处那个量灰显为对外输入并在属性页写明"本块上一轮把它送了出去"
- **AND** 同一个块里 MUST NOT 同时出现收方块那一侧的边，关掉开关这侧与去处那个量一起不画、再打开一并复原
- **AND** 这条边 MUST NOT 挂着"从对外输入指进本块"的灰细样式

#### Scenario: 既不是收方块也不是来源块的子图里不出现这条落点

- **WHEN** 进入一个既不是收方块、也不是来源块的块的子图
- **THEN** 画布上不出现这两条成员级边；若那两个量在该子图里本来就在场，它们之间画的仍是那个块自己的关系

#### Scenario: 落点与本轮的产物边同端点对时两条分开画

- **WHEN** 开关打开，进入本轮的产物边与落点落在同一对量上的子图（如电离场里 `Ṅ_ion → Q_HII` 与落点 `Q_HII → Ṅ_ion`）
- **THEN** 两条边都画得出来且各自可辨（产物边走直线、落点边鼓开），两个箭头都看得见，MUST NOT 叠成一条
- **AND** 落的点两端量在该子图里也照常在场，灰显与成员状态不变，开合开关仍不动版面

#### Scenario: 同一轮内的红移依赖不受影响

- **WHEN** 打开物理链页，开关处于关闭态
- **THEN** 带红移标签但属同一轮内的依赖边照常可见，其线型与颜色与改动前逐字一致

#### Scenario: 口径改了视图不用改

- **WHEN** 在真源的回流段增删一条并重新生成
- **THEN** 画布与开关条数随之变化，页面代码无需改动
