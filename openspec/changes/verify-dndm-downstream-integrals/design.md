## Context

动机见 `proposal.md` — Why。这里只列决定做法的现状与约束。

上游事实（已入库）：

- P0 改动在 `src/py21cmfast/src/hmf.c`（条件路径不再乘 `dndm_FDM`）与 `src/py21cmfast/src/interp_tables.c`（条件路径第二变量改取 FDM sigma，`EvaluateSigmaConditional()`）。
- `dndm_FDM(M) = (1 + (M/M0)^HMF_FINDEX)^(-2.2)`，`M0 = 1.6e10 · m22^(-4/3)`，`HMF_FINDEX < 0`（`src/py21cmfast/src/fdm.c`）。它是**相对修正因子**，在质量区间上没有「积分等于 1」的解析归一化，因此自洽性检查只能与独立参照对照，不能写成归一化恒等式。
- 下游入口的调用面（`src/py21cmfast/wrapper/cfuncs.py`）：`evaluate_Nion_z` 与 `evaluate_SFRD_z` 需要逐红移的 `log10mturns` 数组且两者形状必须相等；`compute_luminosity_function` 需要 `mturnovers` / `mturnovers_mini`，并在内部按 `component` 分别调用 `ComputeLF(...,1,...)`（ACG，写入 `lfunc`）与 `ComputeLF(...,2,...)`（MCG，写入 `lfunc_MINI`）。
- `component="both"` 的合成方式在 Python 侧：把两个分量插值到共同的 `Muv` 网格后**在对数空间的线性量上相加**，插值用 `fill_value="extrapolate"`。因此「`both` = ACG + MCG」只在共同网格上、且不含外推主导的 bin 时才是可检验的。
- UV 亮度与 SFR 的换算在 `src/py21cmfast/src/LuminosityFunction.c`：`Luv_over_SFR = 1/1.15e-28`、`Muv = 51.63 - 2.5·log10(SFR · Luv_over_SFR)`。这是唯一一处可把 LF 与 SFRD 联系起来的关系式。

约束：

- 验证一旦往下游走一步，`sigma(M)` 插值表左端就落到 `M ≲ 2e5`，命中 FDM 舍入受限区。该处已按 `fdm-integral-robustness` 处理为「采用最佳估计继续」；cffi 直调入口也已按该能力建立了异常边界，失败表现为**非数**而非崩溃。**这改变了验证脚本的判定语义：调用返回不再等于通过，非数必须判失败**（spec 中「任一红移点非数即判失败」由此而来）。
- 当前工作区已提交干净，`git` 可用作对照实验的安全网。

## Goals / Non-Goals

**Goals:**

- 让 P0 改动的可观测后果（下游三条曲线）在仓库内、单命令、可复现地被测出并留档。
- 让「P0 前」与「P0 后」两条路径能在**同一次构建、同一进程**内切换，从而把两条路径的差异与「构建差异 / 插值表构建差异 / GSL 状态差异」分离开。
- 用一个默认关闭、默认路径逐位不变的开关承载对照，避免验证分支变成事实上的第二实现。

**Non-Goals:**

- 不验证再电离历史 Q(z) 的配平：那需要 lightcone / 电离盒运行，属另一层验证，本变更只在积分层做。spec 的第三项自洽性断言因此落在「LF 积分 ↔ SFRD 换算」而不是 Q(z)。
- 不复核 HMF 层与 Liu+25 的一致性（已完成，中位相对误差 3e-13）。
- 不改任何 Python 公共 API 签名，不把这些验证纳入 CI（运行成本为分钟级且含可选重建）。
- 不调整任何默认物理参数与既有数值行为。

## Decisions

**D1 — 对照开关放在 C 侧，且用「同进程可切换」而不是两次构建/两次检出。**
条件路径的差异发生在 `hmf.c` 的乘法与 `interp_tables.c` 的 sigma 选择，Python 侧无法在不另写一套积分的前提下重现旧路径。
备选：(a) 用 `git worktree` 检出旧提交跑两次——构建与表构建差异会混入对照，且成本翻倍；(b) 只在 Python 侧包一层开关——无法改变 C 侧条件路径的选择。
结论：开关必须是 C 侧状态，且切换只影响条件路径的分支选择。

**D2 — 开关默认关闭，且必须证明「关闭时默认路径逐位不变」。**
备选：不提供开关，靠 `git stash` 回退跑两次。否决理由：回退会同时改掉 C 侧的异常边界与积分鲁棒性处理，对照不再只反映 P0 这一处差异；而且「回退后跑，再恢复」会引入人为操作风险。
代价是验证用分支进入产品代码，因此把「默认关闭 + 逐位一致」写成了带回归锚点（CDM 汇总指纹 `abb32794530393dce3ed19c5048291ad`）的硬要求。该指纹在开关引入前采集、由仓库内脚本重新导出（`abb3279…` 目前只存在于本 change 的文档中，仓库内没有任何脚本产出它，因此 spec 明确要求它必须由脚本重算并写入结果文件，不允许作为手记常数存在）。

**D3 — 开关经由包内既有 cffi 句柄暴露，不新增公共 API 参数。**
脚本通过 `from py21cmfast.c_21cmfast import lib` 调用新增的 C 侧 setter（一个进程内全局标志），不经过任何公共包装函数。
备选：(a) 给下游入口加 keyword 参数——破坏「签名集合不变」；(b) 读环境变量——进程内无法在同一构建里来回切换，且污染全局环境。
代价：脚本依赖包内非公共模块名，需在脚本内集中一处导入并注释用途。

**D4 — 自洽性断言选三项，且都落在前述接口可观测的量上。**
(i) `dndm_FDM` 在积分区间的质量积分 vs 独立参照（解析闭式/独立高精度求积）——因为该因子是相对修正、无归一化恒等式（见 Context）；(ii) LF 积分得到的 `ρ_uv` 与 SFRD 按 `1/1.15e-28` 的换算，**并单独报告星等/质量区间截断残差**——否则很容易用收窄区间「凑」出一致性；(iii) `both` 与 ACG+MCG 的分量闭合，**并把外推主导的 bin 单独标注**——因为合成用的是 `fill_value="extrapolate"`，边缘 bin 的偏差是插值伪像而不是物理差异。

**D5 — 产物：JSON + 图，脚本只入 `scripts/`，不入 `tests/`。**
运行成本（多次积分调用、可选重建）不适合放进 test 套件；JSON 作为可 diff 的证据锚点，图用于人读。红移点数与 `m22` 列表参数化，并提供快速模式以便回归时不必全跑。

**D6 — 判定语义：非数即失败，且区分「定义域内应为正却非正」。**
这是对 `fdm-integral-robustness` 的直接后果：异常边界把失败转成非数，脚本若把非数当数值参与统计，就会把失败读成通过。因此汇总层必须先做有限性与符号检查，再做统计。

**D7 — 逐红移调用，不批量传入。**
`evaluate_Nion_z` / `evaluate_SFRD_z` 的缩放常数按传入数组的首个红移确定，一次传入整条红移数组会让整条曲线用单一红移的缩放常数，曲线形状失真。参考实现 `train/_sens_mcrit_kpg.py::per_z_vs_batch` 已经把这个现象测出来过（该文件属未入库产物，只作为现象来源，不作为依赖）。因此脚本 SHALL 逐红移调用。
备选：批量传入——快得多，但会静默产出失真曲线，否决。

## Risks / Trade-offs

- [验证开关留在产品代码里，可能随上游演进腐化] → 默认关闭 + 默认路径逐位一致的回归锚点；开关处注释引用本 change，验证归档后由后续变更决定删除（见 Open Questions）。
- [对照期间旧路径走的是「乘 `dndm_FDM`」分支，可能与上游其它改动耦合] → 对照只在条件路径分支上切换，其余输入（`m22`、`z` 网格、`Mturn` 表）逐项一致并写进结果文件，便于复核。
- [`ρ_uv` ↔ SFRD 一致性受星等区间截断主导] → 单独报告截断残差，容差按其量级设定，禁止用收窄区间提高一致性。
- [`both` 分量在边缘 bin 因外推而不可信] → 外推 bin 单独标注，不与内插区混合统计。
- [`m22 = 0.1` 时上游差异已达 1.5%，下游可能放大] → 逐 `m22` 阈值分流，超阈值必须标注「需追查」与超出倍数。
- [曲线级验证耗时，容易被跳过] → 不进 CI；提供快速模式；结果文件入库使结论可复核而无需重跑。

## Migration Plan

无数据迁移。落地顺序：

1. C 侧加开关（默认关闭）→ `build_cffi.py` 重建 → 同步新 `.so` 到 `src/py21cmfast/`。
2. 跑 CDM 回归锚点，确认汇总指纹仍为 `abb32794530393dce3ed19c5048291ad`（若不符，先停，不进入下一步）。
3. 加 `scripts/verify_dndm_downstream.py`，先出「P0 后」曲线，再出对照。
4. 更新 `docs/FDM.md`，替换指向 `train/` 的引用。
5. 归档本 change。

回退：开关保持关闭即回到现行路径；删除脚本与文档段落即完整回退，无残留状态。
