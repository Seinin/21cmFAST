## REMOVED Requirements

### Requirement: 默认使用内置层级布局

**Reason**: 该需求要求默认使用 cytoscape **内置**的层级布局，与本次「自研的自顶向下树形排布」直接冲突；且它与后加入的「布局方式按标签页独立」（要求新标签页以「手动摆放」起步）在「新标签页的起步布局」上互相矛盾，两条并存时无法同时满足。

**Migration**: 由新增的「默认使用树形排布」承接，其中保留原需求仍然有效的约束：打开（含刷新）时按所选布局排布一次、工具条保留布局切换且重复选择同一方案也重排一次、层级布局始终可选、重排坐标属本机未保存改动、不新增第三方布局依赖。

## ADDED Requirements

### Requirement: 默认使用树形排布

打开图谱（含刷新页面）时，画布 MUST 排成**自顶向下的多叉树**（见「自顶向下多叉树排布」）；MUST NOT 因沿用历史存档坐标而呈现非树形的构图。新打开的**标签页** MUST 以「手动摆放」起步——它的位置已由整理产出，MUST NOT 被自动布局冲掉（与「布局方式按标签页独立」一致）。工具条 MUST 保留布局算法切换；切换后 MUST 立即按所选算法重排；重复选择「当前已选」的方案 MUST 同样触发一次重排与取景，MUST NOT 因所选方案未变化而什么都不做。树形排布 MUST 始终可选。重排产生的坐标属于**本机未保存改动**：SHALL 只改本机并标记为未保存，MUST NOT 自动写盘。为满足该要求 MUST NOT 新增任何第三方布局依赖（不得引入 dagre、elk 等扩展）。

#### Scenario: 打开即为树形排布

- **WHEN** 打开图谱（含刷新页面）
- **THEN** 画布上是一个自顶向下的多叉树：顶层节点在上、其直接子节点在其正下方一层，同一父节点的子节点横向依次排开

#### Scenario: 打开时不沿用非树形的历史坐标

- **WHEN** 存档中的节点坐标并非树形排布的结果（例如早期力导向或手工摆放得到的错落坐标）
- **THEN** 画布按树形排布重排一次，打开后的画面即为树形；重排结果作为本机未保存改动（不自动写盘）

#### Scenario: 新标签页以手动摆放起步

- **WHEN** 从主图进入一个子图标签页
- **THEN** 该标签页以「手动摆放」起步，沿用已整理好的位置，不被自动布局冲掉

#### Scenario: 仍可切换其它布局且重复选择同一方案也重排

- **WHEN** 从工具条切到力导向（或已是树形排布时再次选择该方案）
- **THEN** 画布立即重排并取景，状态条布局名称随之更新，不因所选方案与当前一致而跳过

#### Scenario: 不新增布局依赖

- **WHEN** 检查依赖清单与构建产物
- **THEN** 依赖中没有 dagre、elk 等层级布局扩展

### Requirement: 自顶向下多叉树排布

每个标签页的可见内容 MUST 排成自顶向下的多叉树：

- **父在子上方**：一个节点与其直接子节点 MUST 分属相邻的两层，父节点所在的一层在上，其全部直接子节点位于该层之下；不同层 MUST NOT 在纵向上交错。
- **子并排**：同一父节点的子节点 MUST 沿水平方向依次排开，两两 MUST NOT 重叠。
- **顺序即语义**：同一层内兄弟节点的顺序 MUST 沿用可读的逻辑顺序——带步骤序号的（①→⑦）按序号，层带按 ①→⑤；MUST NOT 为减少连线交叉而打乱该顺序。
- **深度跟随真实层级**：树的层数 MUST 跟随真实的父子层级深度，MUST NOT 把任意一层压平、合并或省略。
- 装饰容器 MUST 继续自动合围其子节点；该排布 MUST NOT 改变节点的父归属，也 MUST NOT 改变容器 / 模块的角色。
- MUST NOT 新增第三方布局依赖。

#### Scenario: 主图按逻辑顺序排成树层

- **WHEN** 在主图标签页触发排布
- **THEN** ① 入口层在最上、⑤ 输出层在最下，五条层带自上而下分属五个层级；每条层带里的模块作为该层的子节点横向依次排开

#### Scenario: 子图排成概念与子概念的层级

- **WHEN** 在 `compute_initial_conditions` 标签页触发排布
- **THEN** 五个块（前置 / 产物与收尾 / 密度链 / 速度链 / vcb 链）作为**概念层**横向排开，块内的过程作为**子概念层**位于各自概念的正下方

#### Scenario: 入口 B 的三个 lane 为概念层

- **WHEN** 在「入口 B」标签页触发排布
- **THEN** E1 / E2 / E3 三个 lane 作为概念层横向排开，各自的步骤作为子概念层位于对应 lane 的正下方

#### Scenario: 模块的子模块再下一层

- **WHEN** 某个模块自身还带有子节点（例如 `prepare_ics` 下的若干过程）
- **THEN** 这些子节点位于该模块的下一层，而不是与它同层或与它的兄弟混在一起

#### Scenario: 兄弟顺序不被交叉优化打乱

- **WHEN** 一层内带步骤序号的模块本按 ③ → ④ → ⑤ 排列，而按连线走向重排能少几根交叉线
- **THEN** 仍保持 ③ → ④ → ⑤ 的顺序，流程不会被打乱

#### Scenario: 装饰框随子树自动合围

- **WHEN** 树形排布完成
- **THEN** 每个装饰容器的尺寸与位置恰好合围自己的子节点加统一内边距，框之间不重叠

## MODIFIED Requirements

### Requirement: 标签页内按层整理布局

「整理布局」动作 MUST 只作用于当前激活标签页所呈现的可见内容，并 MUST 产出**自顶向下的多叉树**排布（见「自顶向下多叉树排布」）：自底向上——先把各装饰容器（层带 / E lane / S09 框）内部的模块排好并令框自动合围，再把该标签页的顶层节点与容器按层级自上而下排列；MUST NOT 移动其它标签页的节点。主图标签页 MUST 把五条层带按 ①→⑤ 自上而下排成树层、每条带内的模块作为该层的子节点横排；其它标签页沿用同一套树形骨架，MUST NOT 排成「若干并列的块」。整理完成后 MUST 自动取景使本层内容完整可见；整理 MUST NOT 改变节点的 parent 归属或容器 / 模块角色。

#### Scenario: 只整理当前标签页

- **WHEN** 在「④红移循环」标签页触发整理布局
- **THEN** 仅该层 7 个步骤节点被重新排列，主图与其它子图的节点坐标不变

#### Scenario: 主图保持层带竖排

- **WHEN** 在主图标签页触发整理布局
- **THEN** 五条层带按 ①→②→③→④→⑤ 自上而下排列成五个树层，每条带里的模块作为该层的子节点横排（超过 7 个才折行），带框恰好合围自己的模块

#### Scenario: 子图排成概念树而非并列块

- **WHEN** 在 `compute_initial_conditions` 标签页触发整理布局
- **THEN** 五个块作为概念层、块内过程作为子概念层自顶向下排布，不呈现为若干彼此不相干的并列方块

#### Scenario: 装饰框自动合围

- **WHEN** 在「入口 B」标签页触发整理布局
- **THEN** E1/E2/E3 三个 lane 各自的步骤先在框内排齐，lane 框恰好合围其步骤（无重叠、无过大空隙），三个 lane 再整齐排列
