## Context

物理图谱页（第三页）现在的结构（`Graphify/src/generated/physics-chain.json`，52 节点 / 32 边）：

| 层级 | 内容 | 机制 |
| --- | --- | --- |
| 一级 | 7 个 `stage:S*`（`type: group`，`layer: process`）复合框 + 6 个漂在一级的驱动量（`fstar`/`zeta`/`tvir_min`/`lx`/`k_target`/`tgamma`） | 容器把 18 个物理量圈在里面内联展开 |
| 二级 | 9 个"模块"（`dtb`/`ts`/`tk`/`eps_heat`/`jalpha`/`scaling_relations`/`source_grid`/`phi_uv`/`tau_e`）各挂 21 个 `step:S*`（`method`） | `graph.subgraphs[id].steps` → 双击进入 |

共享机制已经就位：`TabBar` + `GraphCanvas` 的 `onEnterSubgraph` / `focusId`（焦点标签页只显示焦点的直系子节点，容器递归内联），见 `openspec/specs/graphify-subgraph-tabs/spec.md`。

本次要换掉的是**一级的划分依据**：从"代码阶段"换成"天体物理过程"。动机见 `proposal.md - Why`；本文只讲怎么落。

## Goals / Non-Goals

**Goals**

- 一级只剩 10 个块，块内成员与块间接口都只由生成物说话。
- 每个天体物理过程进得去、且进去以后能**独立读懂**（内部推导链完整 + 外部输入可见）。
- 分档、档位、坐标都不携带逻辑含义。

**Non-Goals**

- 不动画布页（`Graphify/data/graph.json` 的 atlas 图谱）与它的一级层带。
- 不删渲染层的 compound 能力（画布页仍在用），只是物理链页不再产生 compound 实例。
- 不改物理内容：等式、`dependsOn`、参数、文献都不动，只补两条缺失边与新增块声明。
- 物理链页的子图标签**不与 URL 同步**（现状如此，另案）。

## Decisions

### D1：块是数据节点，成员靠 `parent` 指向块

块在生成物里是 `type: 'process'` 的普通节点（不是 `group`），块 id 形如 `block:ionization`；24 个物理节点的 `parent` 从 `stage:*` 改指向 `block:*`。

- 为什么不是容器：`graphify-subgraph-tabs` 的「容器不参与关系」明确禁止任何边以容器为端点，而本次**必须**画块间接口边（20 条，见 D5）。
- 为什么改 `parent` 而不是新增 `node.block` 字段：焦点标签页的可见集 = 焦点的直系子节点，这条机制已经在跑。改 `parent` 后主图**天然**只剩 10 个块（块是"模块"，子节点不同屏），子图**天然**显示成员，一行渲染代码都不用改。
- 备选：前端硬编码 10 个块 —— 违反"视图只读生成物"（现有 spec 的可证伪条款就靠这个）。

### D2：块声明写在真源 `chain.json` 的 `blocks` 段

`docs/notes/physics-chain/chain.json` 增 `blocks: [{ id, label, members: [...], kind }]`；生成器只搬不动。

- 为什么不像 `physicsStages.mjs` 那样放在脚本侧：阶段是**代码归属**（脚本/数据分级是工程概念），过程是**物理事实**（哪些量写进同一组等式）。物理事实必须随真源走，否则同一件事有两处声明，改一处就漂移。
- `physicsStages.mjs` 因此整体退场（它的消费者只有 `build-physics-chain.mjs` / `check-physics-chain.mjs` / `Graphify/src/lib/physicsChain.ts`）。
- 块的 `tier`（档位）也写在这里 —— 它是**因果层级**（哪一步推哪一步），属物理事实，生成器只搬不算。

### D3：`enterable` 由自检按连通性判定

生成器为每个块算块内边并给 `enterable`：成员非空且块内连通分量 = 1 → 可进入。⓪环境/给定与 ⑨观测量内部各有 3 个连通分量（`T_γ`/`f*`/`k` 互不相连；`φ`/`τ_e`/`P_21` 各挂各的上游），标记为不可进入。

- 备选：让它们也进得去 —— 摊开三个互不相连的孤立节点，读者什么也读不出来，等于把"带"伪装成"过程"。
- 连通性必须由自检算，标记只是结论的落盘；否则把 `T_K` 挪出 ⑤ 之后没人会发现 ⑤ 散了。

### D4：分档只定 y

档位 = 真源手写的**因果层级**（`tier` 0–7，见映射表），生成器只搬不算，只用于算块的 y 坐标。实测 24 条跨块依赖（落成 20 条接口边，见 D5）**全部自下而上**（`Q_HII → ε_heat` 是 ④→⑤ 向上，不是反馈回边；`T_K → x_c` 是 ⑤→⑦ 向上），所以没有回边要特殊处理，长边（⓪→⑨、③→⑨）照画照标。

- 备选：按块级拓扑深度算（BFS）—— 实测算出来 ⑤ 与 ③ 同档、④ 落在 ③ 上方，箭头来回折返、像 bug；已否。
- 备选：按档位做筛选/渐进披露 —— 正是上一版被否掉的"深度带逻辑绑定"。

### D5：块内边只在子图画，块间边只在主图画

块内边 10 条（`ζ→Ṅ_ion`、`Ṅ_ion→Q_HII`、`L_X→ε_heat`、`ε_heat→T_K`、`J_α→x_α`、`x_c→T_S`、`标度关系→ρ̇*`、`标度关系→源项的实现`、`质量函数的算法→dn/dM`、`T_vir^min→M_min`）与 24 条**跨块依赖****互补且不重叠**（10 + 24 = 34 = 总边数）。主图每条边的标签 = 跨界流动的量名。**静息不画箭头，悬浮块时显现它两端的接口边**（用户口径 2026-09-30）——这样既保住了你 2026-09-30 记在 `build-physics-chain.mjs:894-897` 的那条口径的意图（一级不要一堆乱箭头），又让接口随时可查。

**实现期修正（2026-09-30）：24 条跨块依赖按「块对」合并成 20 条接口边。** 同一对块之间常有两条以上依赖（如 ④→⑧ 与 ④→⑤ 都靠 `Q_HII`、③→⑥ 与 ③④ 之间的 `ρ̇*` 与 `源项的实现`）——不合并在画布上就是两条平行的同向箭头、标签互相压住，读者还得自己数。合并规则：`(source 块, target 块)` 唯一一条接口边，标签 = 跨越这一对的**量名并列**（`源项的实现、ρ̇*(z)`）；块间送了什么读边标签（悬浮块即显现），成员明细在两端块的属性页。块内 10 条 + 跨块依赖 24 条 = 34 这条守恒断言不变，变的只是"画出来多少条边"（20）。

### D6：补两条缺失边

`k_target → p21`（Eq.11）与 `hmf_impl → dn_dm` 在数据里不存在，两个端点因此是零边孤立节点（`crossLevel.levels` 给 0）。不补则 ⓪→⑨ 与 ①内部都不连通，块划分也会缺角。补在真源 `edges` 里。

### D7：折叠条退场，工程项成为块成员

「旁路」（原 S04 = `phi_uv`/`tau_e`）与「实现细节」（`source_grid`/`hmf_impl`）都是阶段概念。按过程归位后：`phi_uv`/`tau_e` → ⑨观测量，`source_grid` → ③，`hmf_impl` → ①。一级只剩块，没有"要收起的一层"，`COLLAPSED_TOPIC_IDS` 的一级过滤与底部折叠条一并退场。工程项在块内用 `engineering` 的暗色呈现，与物理量一眼可分。

## Risks / Trade-offs

- [子图里 `dtb` 等成员自己还有子节点，标签条会到第三层] → 属于既有机制（模块→步骤），标签条第一项恒为「物理链」，随时一键回主图；本次不限制层数。
- [20 条接口边在手摆坐标下可能交叉] → 复用 `ordered.ts` 的重心法排序；若仍不理想，退路是只画接口不写全标签（标签改为悬浮显示）。
- [灰显上下文节点与主图是同一个 id，有"一个量两处可编辑"的风险] → 上下文节点标 `context: true`，页面把编辑类回调一律接成只读提示（现有的 `readOnlyNotice` 已在跑），选中后属性页显示"这是外部输入"。
- [块级硬数字（10/8/24/10/34）写进自检，物理内容一改就得同步] → 守恒类断言（覆盖 100%、块内 + 块间 = 总数）与"口径快照"断言分开写，快照数字集中在一处，改口径时只改那一处。
- [删除 7 个 `stage:S*` 会让别处引用它们的代码失效] → 已确认消费者只有 `build-physics-chain.mjs` / `check-physics-chain.mjs` / `Graphify/src/lib/physicsChain.ts`（`physicsStages.mjs` 的全部消费者）；块级 `parent` 改指后 `graph.subgraphs`（模块→步骤）不受影响。

## Migration Plan

1. 真源：`chain.json` 加 `blocks` 段、补 `k_target → p21` 与 `hmf_impl → dn_dm` 两条边。
2. 生成器：`build-physics-chain.mjs` 产出 `graph.blocks`（含 `members` / `enterable` / 档位）、把 24 个物理节点的 `parent` 改指块、删掉 7 个 `stage:S*`、按档位算块坐标；`physicsStages.mjs` 删除。
3. 自检：`check-physics-chain.mjs` 的阶段断言换成块断言（成员覆盖率、块内连通性、块间 + 块内 = 总数、块级快照）。
4. 页面：主图块口径（图例、检索标注、状态条）、子图的上下文节点、块属性页、折叠条退场。
5. 文档：`docs/notes/graphify/` 与 `docs/DIRECTORY.md` 补记口径转换。

回滚：生成物与页面同批改动，回滚 = `git revert` 该批提交后重新 `node scripts/build-physics-chain.mjs`。
