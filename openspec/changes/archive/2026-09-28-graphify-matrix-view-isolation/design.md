# Design

## 背景

矩阵视图与画布视图共享同一份"应用外壳"：同一个顶栏、同一个状态条、同一个全局快捷键 Hook。矩阵视图**不渲染**画布与检查器（`view === 'matrix'` 时整行——notes 面板 + 画布 + 检查器——都不挂载），但外壳仍然按画布的口径在说话。于是出现"画布不在了、选中还在"的错位。

## 决策

### 1. 清空选中，而不是保留并标注

**选择**：切到矩阵视图时把选中、连线模式、引用拖拽、搜索框内容一并清掉。

**理由**：矩阵页没有检查器，选中状态在那里**没有任何展示出口**——保留它只会让状态条继续断言"已选中节点"。而且选中是**可操作对象**：删除、连线、连带整条撤销栈都按它工作，留在那里就是一把没插电却通着电的开关。清空之后"进入矩阵 = 干净的一页"这件事变得无需解释。

**代价**：从矩阵切回画布要重新点一次节点。可接受——切视图本来就是换任务。

### 2. 快捷键禁用，而不是"自动切回画布再执行"

**选择**：矩阵页只留 `Ctrl/Cmd + S` 与 `?`，其余画布专属动作不注册。

**理由**：键盘是**盲操作**，在矩阵页按 `Delete` 的意图绝不可能是"删掉那个我看不见的选中节点"。让快捷键"先切回画布再执行"更糟：视图会在手上自己跑，人被带走；而且用户按 `L`（重排）时并不知道自己即将改的是另一页的坐标。禁用是唯一不会意外改数据的选项。

### 3. 状态条按视图双口径，用回调上报，而不是共享 store

**选择**：矩阵视图统计（参数数、过程数、有色格数、当前动作）由 `MatrixView` 通过 `onStatus` 回调上交给 `App`，再传给 `StatusBar`。

**理由**：矩阵模型是 `buildMatrix()` 的产物、只存在于矩阵视图里（数据源是 `src/generated/physics-graph.json`，与画布那份图无关），塞进画布 store 会让"两份互相独立的数据"这条边界变浑。回调 + `view === 'matrix' ? status : null` 的写法还顺手解决了"切回画布后残留旧统计"的问题：一旦不是矩阵视图，就根本不显示。

**被否方案**：让 `MatrixView` 自己渲染一条自己的状态条——会和全局那条并存，底部出现两条状态条。

### 4. 顶栏隐藏而非禁用

**选择**：矩阵页把搜索框、撤销/重做、布局、话题、标签、导入、图谱统计整块隐藏。

**理由**：禁用的按钮会留下"这里能做点什么，只是现在不行"的暗示，而事实是在矩阵页**这些概念不存在**（话题、标签、布局都是画布的组织方式）。隐藏让顶栏只剩矩阵页真正能用的东西。

**偏差说明**：用户点名隐藏的是布局、话题、标签、导入；这里额外隐藏了三个——搜索框（它只搜画布节点与关系）、撤销/重做（用户已明确要求"不响应"）、**图谱统计**（`GraphStatsPopover` 统计的是工程视角那份图，在物理视角页看它是错位的；矩阵自己的规模信息由状态条给出）。这三条在任务清单里单独记了一笔，便于回退。

### 5. Esc 由矩阵视图自己处理

**选择**：`MatrixView` 在详情打开时挂一个 `keydown` 监听，按 Esc 关掉详情。

**理由**：抽屉用的 `Sheet` 是仓库自造的组件，**不处理 Escape**（全仓 `src/components/ui/*.tsx` 里没有任何 Escape 处理）。而全局那个 `onEscape` 在矩阵页被有意关掉了（它做的是"取消连线 / 取消选中"，都是画布语义），所以关详情这件事必须由矩阵视图自己负责。

## 风险与回归

- 唯一有数据风险的行为是"矩阵页误按 Delete"，本次把它堵掉；断言用真实 snapshot 数 + 节点数来验证（不是只看界面）。
- 切视图本身不写盘：切换前后快照数与工作文件 `updatedAt` 必须一致。
