## Context

动机见 `proposal.md - Why`。这里只记与实现有关的现状与约束。

**数据面已备齐，本变更不碰它。** 真源 `docs/notes/physics-chain/chain.json` 有独立的 `feedback` 段（2 条，各带 `codeRef` 与 `note`）；生成器 `scripts/build-physics-chain.mjs` 把它们烘成带全套标记的边：`kind: "feedback"`、`spanKind: "feedback"`、`levelSpan` 为负（−2 / −3）、`crossLink: true`、`surface: true`、`focusOnly: false`，并在自己的断言里要求"回流层的层差必须为负"。所以缺的只是**视图的开关与样式**。

**渲染模板是两页共用的。** `GraphCanvas` 从 `GraphSourceProvider` 取数据：画布页给服务端图 + 共享 store，物理链页给生成物 + 本地只读 store。边字段 → cytoscape 类名的映射在 `src/graph/cytoscapeSetup.ts`（今天只映射 `conditional` 与 `crossLink`），样式在 `src/graph/styles.ts`。

**仓里已有三条可复用的先例。**

- `edge[?focusOnly]`：接口边**静息不画**，只在两端块被聚焦时显现——"某类边默认不画"在样式层已有成熟做法，且 cytoscape 的 `display: none` 元素不参与命中，关闭态"不占位、不命中"由它免费拿到。
- `hiddenRelations`：模块关系收起是**纯视图状态**，记在本机（`src/lib/viewPreferences.ts` 的字符串数组读写对 + store），不进图谱数据、不进撤销栈。
- `show-label`：`GraphCanvas` 已有 `toggleClass('show-label', …)` 这类"按状态切换类名"的写法，开合不需要重建元素。

**缺口三处。**

- `src/lib/types.ts` 的 `spanKind` 联合写的是 `sibling | coarse | bypass | gap`，产物实际还会写 `'feedback'`。
- 同文件里 `levelSpan` 的注释写"源层号 − 目标层号（≥1）"，而回流边恒为负——注释口径与产物不符。
- 同文件里 `GraphEdge` 没有回流所记的两端量（`fromNode` / `toNode`），也没有"这条边只属于哪个块的标签页"的位置——子图里的落点要用它们（D10），否则视图只能自己猜端点；`GraphNode` 也缺"这个量是哪些块读的上一轮那份 / 送出去的那份"（`feedbackInputOf` / `feedbackOutputOf`），落点两端没法按当前块认出来。

## Goals / Non-Goals

**Goals:**

- 关闭态：画布上无回流边，默认可见边**无有向环**；打开态：产物里的每条回流边都显现。
- 两种状态都不动数据、不动坐标、不触发重排；开合往返逐字复原。
- 开关一份（浮层控件是共用组件，画布页不传因此不出现）、状态记在本机；关闭态下这条知识仍有只读入口，从入口点中即显现。
- 进入**弧两端块**（收方块 / 来源块）的子图后，这条关系各落到成员级一次（同一端点对：上一轮送出的量 → 这一步读它的量），并与一级那条弧同进同出——开关一并开合这些视图面；这是"一级讲回声、进块里指着两个量说"。
- "哪些边默认不画"只有一份声明（产物的边种类字段），生成器、自检、视图三条腿共用。

**Non-Goals:**

- 不改真源、生成器、生成物，不改回流边的条数与端点。
- 不做更大的视图分层（主序视图 / 依赖视图 / 只看回流），那是另一个变更。
- 不改造工程图谱（画布页）——它没有回流边，本变更对它零改动。
- 不做回流动画，也不手工布"绕回上一轮"的路径走线；本次只定样式与箭头方向。

## Decisions

**D1 过滤放在样式层，不放在装配层。** 新增一个边类名（`feedback`），由开关状态切换一个"关闭态"类（与 `show-label` 同一套 `toggleClass` 手法），关闭态下该类边 `display: none`。
理由：不动元素集合就不动坐标与布局，开合往返天然逐字复原；与 `edge[?focusOnly]` 同源。备选——装配时跳过这类边：需要在开合时增删元素或重建实例，会碰到坐标、视野与"进入子图"的可见集，代价与风险都更高，否决。

**D2 状态由物理链页本地持有（`useState`），落盘走 `viewPreferences` 新增的布尔读写对**（键 `graphify.showCrossRedshiftFeedback.v1`）：挂载时读一次本机偏好，切换时写回。
理由：**这一页不碰画布的共享 store**——`check-physics-chain.mjs` 的「视图纪律」断言 `PhysicsChainView` 不 import `useGraphStore`（数据各用各的正是这一页的设计），而开关只有它一个消费者，放进共享 store 就要让这一页去依赖那份共享状态，与断言直接冲突。落盘口径与 `hiddenRelations`、面板宽度一致——只存界面偏好，不进图谱数据、不进撤销栈、不被"保存"带进产物；"刷新 / 切页保持"由**挂载时重读偏好**满足，不靠状态驻留内存。备选——放共享 store：与上述断言冲突，且没有第二个消费者，否决；写进生成物：那是视图口径不是物理事实，否决。

**D3 默认关。** 跨红移回流是**跨迭代**关系（上一轮红移 → 下一轮），默认不该与同一轮内的主序抢位置；且"关＝0 环"本身是可以拿来自证的口径。这是本变更唯一改变默认视觉的地方，回滚即恢复旧观。

**D4 控件挂在画布浮层，按可选 prop 惯例。** `CanvasOverlays` 已有的 `onToggleEdgeLabels?` 就是"不传就不画"；物理链页传，画布页不传。理由：浮层正是"视图口径"该出现的位置，且画布页一行都不用改。

**D5 控件文案带条数：「跨红移反馈 · 2 条」。** 关闭态下不能只靠"有个开关"暗示这件事存在；条数从产物算出，产物里没有回流边时写明原因而不是渲染一个永远为空的开关。

**D6 只读入口点中即开开关，不做"例外显现"。** `PhysicsChainView` 已经为 `focusOnly` 写过同类处置（从属性页点中静息不画的接口边时，顺手把两端块悬起来，否则会出现"选中了一条看不见的边"）；回流边沿用同一套，只是动作换成"自动打开开关并定位"。
备选——让被点中的那条边单独例外显现：会留下"开关关了却有一条线在"的困惑；直接开开关语义更明确（正在看回流），否决。

**D7 类型与注释补齐。** `spanKind` 联合加 `'feedback'`；`levelSpan` 的注释改成"层差 = 源层号 − 目标层号，主序为正、跨红移回流为负"。不动 `kind` / `surface` / `focusOnly` 等未声明字段的现状——它们是产物专用字段，本变更不扩这个口子。

**D8 "默认不画"的声明只有一处。** 生成物边上的种类标记（`kind: "feedback"`）就是唯一声明：视图按它渲染，自检按它重算。
自检因此可以在 Node 里把"关＝无环、开＝回声"钉死：按同一字段把边分成"默认可见"与"开关打开才可见"两组，独立重算强连通分量——默认组必须 0 环，加回回流组的必须恰好 1 个环簇（今天 4 个块）。这比"把条数写死"更能抓漂移。

**D9 管辖范围只认产物标记：开关管一件事的全部视图面——一级的弧，以及它在弧两端块子图里的落点。** 开关管的是"已标为跨红移回流"的边，即层差为负、两端皆为一级块的那 2 条。弧的端点是一级块，进任一子图（块的成员层）都画不出它——逐块核对过：每个块的子图可见边 0~6 条，其中回流弧 0 条、有向环 0 个（回流边两端 `parent` 为空，见任务 4.4）。
但"子图里没有这条弧"不等于"子图里不该讲这件事"：两端块各有一半事实。收方块那侧，这一步真的读上一轮的那个量（`ComputeHaloBox` 收 `previous_spin_temp` / `previous_ionize_box`）；来源块那侧，上一轮的它真的被送了出去（`UpdateSpinTemperature` 算的 `T_S`、`ComputeIonizedBox` 算的 `Q_HII`）。所以关系要在**两端块各落到成员级一次**：由产物记的两端量派生 `fromNode → toNode` 的成员级边，方向恒定，对面的那个量一并灰显。四级口径因此分开：
- **一级**：块 → 块的弧（默认藏，打开时显现）。
- **收方块的子图**：量 → 量的边（`spanKind: 'feedback-input'`）与落点那个**来处**的盒子，讲"这一步把它读进来"。
- **来源块的子图**：同一条弧再派一条同端点对、同档样式的边，与落点那个**去处**的盒子，讲"上一轮把它送出去"。
- **别的视图**：不画这两条落点（主图与别的子图都不画）。

为什么来源块那侧也要画：只画收方块那侧，来源块的读者看到的是本轮的 `Ṅ_ion → Q_HII`（正向依赖，与回流反向），读不出"上一轮的 `Q_HII` 被送走了"；而 `Ṅ_ion` 在气体热与自旋温度块的子图里压根不在场，连"把 `T_S` 送出去"这件事都没得画。两侧各画一条同端点对、同档样式的边（靠 `subgraphOf` 分别只在自己那一块显形），读的人在第一级那条弧的两端都能落到同一个端点对上。

为什么落点也归开关、而不是"关掉之后照旧列着"：开关声明的是"跨红移回流这件事显不显示"。若一级藏、子图显，读者在子图里看到一个孤立的盒子加一条边，既认不出它与被藏起来的那条弧是同一件事，也没法用一次开合把这件事看全——旋钮的语义会从"这件事显不显示"滑成"按视图面各藏一半"。而"这一块读了上一轮的什么、上一轮送出去的是什么"仍可从只读入口读到（关系列表 + 点中即开，见第三条要求），所以藏起来不等于把这件事实抹掉。

投影与开关状态无关（D1 的手法原样套在这一层的三样上）：落点边与两端盒子**始终**在页面交给画布的那份图里（`subgraphOf` / `feedbackInputOf` / `feedbackOutputOf`），开关只切类名（`feedback-off`），开合因此不增删元素、不动坐标。

不纳入开关的三类"跨红移"：①同一轮内带红移标签的依赖边（`ε_heat(z) → T_K(z)` 这类，标签里的 `(z)` 只说量随红移变，边本身在同一轮内）；②块内「读上一轮同名量」的累积——`ts_main(..., TsBox *previous_spin_temp, ...)`，块级是自环；③方向顺向的上一轮输入——`ComputeIonizedBox(..., previous_perturbed_field, previous_ionize_box, ...)`，顺向边在视觉上与普通依赖同构。②③今天根本不是边（真源没有对应条目），把它们纳入需要先建边并给统一标记，属另一个变更（见 Non-Goals）。

**D10 落点由视图按产物派生，产物与生成物一个字节不动。** 派生四件事，全落在视图侧：
- `fromNode` / `toNode`（产物那条弧上记的两端量）进 `GraphEdge` 类型；`feedbackInputOf` / `feedbackOutputOf`（这个量是哪些块读的上一轮那份 / 送出去的那份）进 `GraphNode`；
- 每条弧派生**两条**成员级边（同一个端点对、同一档样式），`id` 以 `#input` / `#output` 区分，各声明给弧的一端块；
- 派生边带 `spanKind: 'feedback-input'`（与一级那档**同一样式**，让人一眼认出是同一条关系）、类名 `feedback-input` 与一级那档的 `feedback` 分开（只为区分谁在一级、谁在子图）——「关着就不画」那一条规则共用，选择器同时列出 `edge.feedback`、`edge.feedback-input` 与落点那些盒子的 `node.feedback-context`；
- 边带 `subgraphOf`（收方块那条＝弧的 `target`、来源块那条＝弧的 `source`），渲染器按它收口：一条弧在某一刻至多显形一条，别的视图一律 `display: none`（沿用 `focusOnly` 那档"整条不画"的手法，不增删元素）；
- 两端块的 `contexts` 分别并进对面那个量（收方块并 `fromNode`、来源块并 `toNode`）：复用既有的对外输入口径（灰显 + 属性页那一句身份说明），不新造灰显机制；并进去前按本块已声明的 `contexts` 去重（电离场声明了 `Ṅ_ion`，同时上一轮又把 `Ṅ_ion` 送了出去）。

理由：真源增删一条回流，弧与落点一起变，页面不写死块名、量名与条数。备选——把落点写进生成物：那是"同一件事实的多份落点"，而产物里弧的两端块 + 两端量已经说全了这件事，派生是纯函数、可被判据重算，多存一份反而要多守一处一致性；备选——子图里画块 → 块的弧：块是 compound 容器，在子图里不参与绘制，画不出来；备选——来源块只把 `toNode` 灰显而不画边：读的人看不出这两个量之间隔着一次跨红移，且那条灰显的盒子与它周围没有任何连接，像漏画。

**D11 别的块子图里两端同场时不画落点。** 判据是"这条关系属于哪一块"，不是"两端是否都在场"——今天两端同场恰好只发生在弧的两端块（收方块 `block:halobox` 与来源块 `block:thermal` / `block:ionization`），别处没有这种情形。之所以不按"两端是否都在场"判：在那些块里，这两个量之间画的是**那个块自己的关系**（若将来出现在电离史子图里就是 `Ṅ_ion → Q_HII`，本轮的正向依赖，方向与回流相反），把落点按"同场"铺过去会往那些块里塞一条方向相反的假关系。所以自检查的是反面——凡两端同场却**不是**弧的两端块时，那里 MUST 已经有一条本块自己的边连着它们（不靠这条回流，也不是两个孤盒）；今天这条断言以"零例"通过，且判据随数据增删自动收紧。

**D12 落点边鼓开一格：同一张子图里不许有两条同端点对、都走直线的边。** 弧的两端量在同一张子图里往往**本来就有本轮的产物边连着**：`Ṅ_ion → Q_HII` 是网格化源项里算 `Ṅ_ion` 时读 `Q_HII`，而落点讲的是"上一轮的 `Q_HII` 被送了过来"——同一个端点对、方向相反。逐块核对过：这种叠法今天恰好 2 处（`block:halobox` 与 `block:ionization` 各一处，都是这一对端点），主图没有。
- 为什么叠住：cytoscape 的自动错开（`control-point-step-size`）只在**同一种 `curve-style`** 的平行边之间生效。产物边那档走基础档的 `straight`（两框中心连线，方向可预读），落点边若只沿用一级那档的 `bezier`，它是那一对端点之间的**唯一**一条 bezier，控制点落在中点、画出来仍是直线——两条完全重合，读成"这里只有一条关系"，反向的那个箭头被盖掉。
- 手法：给 `edge.feedback-input` 单起一档，显式换成 `unbundled-bezier` 并给固定控制点偏移（`bezier` 的控制点是算出来的只读值，手动指定必须走这一档）。产物边照旧走直线，两条一弯一直分开。偏移量与一级那条弧同一量级（那里 `control-point-step-size: 140`；子图里落点两端通常就是两个相邻盒子，取 80）。
- 为什么不让两条边都弯：只有落点边是我们派生的新东西，产物边的直线是既有视觉语言（"两框中心连线"），动它会连带改掉所有子图的观感。
- 守在哪：数据侧断言"子图里没有两条同端点对、**都是产物边**的边对"（那种叠法没有曲线可用，得回样式表再弯一条；"产物边 + 落点边"是正常且必需的分开画法）；源码侧断言"`edge.feedback-input` 那档确实设了 `unbundled-bezier` 与 `control-point-distances`"。两条都以今天的 2 处叠法为准通过并报告数。

## Risks / Trade-offs

- [关闭后"看不见"被读成"不存在"] → 开关报数 + 检查器关系列表照常列出（含代码落点与"来自上一轮红移"）+ 点中即开（弧与落点都当场打开开关）；三条路都在 spec 的验收里。
- [落点跟着开关藏，子图里读不出"这一块读了上一轮什么 / 送出去的是什么"] → 只读入口仍列出这条关系并写明两端（关掉开关也能读到这条事实），且从入口点中即打开开关并在它声明的那一块里定位；开关的数目与文案说清它管着哪几个视图面。
- [落点看起来像"两个块之间又有一条线"] → 每条只在**自己所声明的那一块**里显形（一条弧在某一刻至多显形一条），且与一级那档同一样式（同一档视觉语言）；别的块里那两个量同场时画的仍是本块自己的关系，自检按"关系属于哪一块"收口并断言"两端同场处必有一条本块自己的边"。
- [来源块那侧的落点被"灰细"样式压掉，两处看起来不像一件事] → `context-edge` 那档（从对外输入指进本块）显式排除 `feedback-input`，自检按源码断言守；样式表把这条排除写在注释里说明理由。
- [落点与本轮的产物边同端点对（`Ṅ_ion ↔ Q_HII`），两条直线完全叠住、反向箭头被盖掉] → 落点那档显式换 `unbundled-bezier` 并给固定控制点偏移（产物边照旧走 `straight`）；自检按数据侧断言守"子图里没有两条都是产物边的同端点对"，并按源码断言守"落点边确实换了曲线"（D12）。
- [样式规则顺序] → cytoscape 后写的规则胜：关闭态那条必须写在本文件既有的 `edge[?focusOnly]` 之后，否则会被它盖掉；自检与实走都要检查"关闭态没有可见回流边"。
- [两页共用模板，加 prop 可能牵动画布页] → 走可选 prop，画布页不传；门禁用 `tsc -b` + `check:copy`，并在实走里逐字比对画布页的可见边与样式。
- [本变更改变默认视觉（回流边从"默认可见"变成"默认隐藏"）] → 刻意取舍：换来默认主序图无环；回滚 = 还原代码，偏好键默认值即旧观。
- [`levelSpan` 为负会让"跨层"的既有读法更难懂] → D7 把注释改成含负值口径；不新增字段，避免两套层差语义。
