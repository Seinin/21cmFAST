## Context

见 proposal.md - Why。现状约束：
- 节点上已有自由文本 `tags: string[]`（18 种，图集导入时打的），**话题**（`meta.topics` + `node.topics` 存 id）已经跑通了「注册表 + id 引用 + 顶栏勾选」这套模式，可以直接照搬；
- 画布上已有「悬停放大 + 其余虚化」「标签开关」「子图标签页」等机制（见 graphify-tabbed-subgraphs），红点必须与它们共存：不能新增 DOM 覆盖层去抢指针事件（拖拽、连线、引用拖放都在画布上）；
- 服务端 zod schema 会**剥掉未知字段**，新增字段必须同时改 `server/lib/schema.mjs` 与 `server/schema/graph.schema.json`，并且**只读校验发生在每次 GET**——写坏的数据会让页面读到空图（本项目已有教训）。

## Goals / Non-Goals

**Goals:**
- 一套「注册表 + id 引用」的标签模型，把现有自由文本标签无损迁进来；
- 标签明细可承载「参数名 · 用法 · 出处」，出处能点开源码对照；
- 勾选 → 红点 → 点红点看明细这条链路闭环，且不干扰画布上已有手势；
- 首个标签「参数参与」的明细**可机器核对**（来自节点引用的源码区间，而不是凭印象写）。

**Non-Goals:**
- 不做标签继承 / 层级标签 / 标签着色之外的可视编码（红点是唯一新增视觉）；
- 不做按标签筛选可见集（勾选只加红点，不隐藏任何节点——隐藏节点是「话题」的职责）；
- 不在本期补齐所有节点的参数明细（只做引用齐全的那批）；
- 不改 LLM 导入草案的既有 tags 契约（草案仍按**名字**写标签，合并时登记或匹配注册表）。

## Decisions

### D1: 注册表放在 `meta.tags`，节点存 id；`node.tags` 直接改变含义（一次迁移）

`meta.tags: TagDefinition[] = { id, name, description, color? }`；`node.tags: string[]` 从「自由文本」改为「注册 id 列表」，服务端按「必须已注册」校验（与 `node.topics` 同一套交叉校验，报错指名节点）。迁移脚本把现有 18 种文本按原名登记并把节点里的文本替换为 id；同名合并为一项。

- 备选 A（新增独立字段 `globalTagIds`）：不动现有数据与导入契约，但会留下两套「标签」概念——Inspector 里两个输入框、图例里两种说法，长期成本更高，被否。
- 备选 B（把明细塞进 `tags` 的自由文本里，如 `参数参与:DIM=赋值`）：解析脆弱、无法校验、改名即失效，被否。

### D2: 明细单独一列 `node.tagDetails`，与归属解耦

`tagDetails: Record<tagId, TagDetailItem[]>`，`TagDetailItem = { label, kind?, note?, ref? }`（`ref` 复用现有 `GraphRef` 结构：`file` + `line`/`endLine` 或 `docId` + `anchor`）。归属与明细独立增删：只有归属时属性面板显示「暂无明细」；明细不写就代表「暂未整理」。

理由：明细的形状因标签而异（参数参与是「参数表」，别的标签可能是「子过程清单」），用「条目列表 + 可选 kind」这种最小通用结构即可，不必为每种标签建表。

### D3: 红点用 cytoscape 节点背景位图（不是 DOM 覆盖层）

把小红点画成节点样式里的第二层 `background-image`（内联 SVG 圆点 data URI），配合：

```
'background-fit': 'none', 'background-width': 10px, 'background-height': 10px,
'background-position-x': '0%', 'background-position-y': '0%', 'background-clip': 'none'
```

挂在一个状态类 `node.tagged`（由渲染器在「勾选了标签且该节点命中」时切换）上。

- 备选（HTML 覆盖层，像连线手柄那样夹紧定位）：N 个节点就要 N 个 DOM 元素 + 每帧跟随视口重算，且要自己处理指针命中与层级；现有手势（拖拽、连线、引用拖放）都挂在画布上，覆盖层很容易抢事件，被否。
- 代价：红点尺寸是**屏幕像素**（不随缩放变大变小）——正好是我们要的（缩小时也看得见）。
- 容器不挂这个类：容器不参与标签（与「容器只作分组、不参与关系」一致）。

### D4: 点红点 = 选中节点 + 属性面板展开该标签明细

命中判定放在渲染器的 `tap` 回调里：若命中点在节点**左上角的小方区**（以渲染坐标算，约 16×16 px）内、且该节点持有被勾选标签 → 回调 `onOpenTagDetail(nodeId, tagId)`；上层选中该节点并把属性面板的「标签区块」展开到该标签（面板新增 `activeTagId` 视图状态）。红点区域内的 `tap` 不再走「选中/连线/拖拽」原路径（`grab` 也不在红点上开始——红点区域是节点边缘，改为在 `tap` 阶段拦截即可满足「点了不拖动」）。

### D5: 勾选状态是纯视图状态，放在 store（不进撤销栈、不落盘）

与 `hiddenTopicIds` 对称：`activeTagIds: string[]` 放在 `graphStore`，仅用于渲染红点与顶栏计数；刷新页面后回到「一个都没勾」。理由：勾选是「当前看什么」的临时状态，不属于图谱内容；进撤销栈会让一次「勾标签」占据一次撤销位，很烦。

### D6: 首个标签的明细由脚本从源码引用提取，先覆盖引用齐全的节点

`scripts/tag-parameters.mjs`：
1. GET 全图，读出每个节点的 `refs`（`file` + `line`/`endLine`）；
2. 只处理**有源码引用**的节点，按行区间读仓库源码；
3. 用上游权威参数表（`src/py21cmfast/inputs.py` / C 侧 `InputParameters.c` 的字段名 + 宇宙学参数名）在区间里匹配标识符出现；
4. 按出现形态分类：`X = ...`（赋值）/ `if ... X ...`（开关）/ 其余（入公式）；
5. 生成「参数名 · 用法 · 出处（file:line）」的明细，**先打印一份清单**（节点 × 参数 × 用法 × 行号）供人工核对；
6. 核对通过后再 PUT 写回（脚本支持 `--dry-run` 默认开、`--apply` 才写）。

理由：参数参与是**可核对的事实**，从源码区间提取能给出出处，比手写更容易复核；先只覆盖引用齐全的节点（用户已选此口径），其余留空待补。

## Risks / Trade-offs

- [迁移把现有 tags 写坏（评审看到的是空图）] → 迁移在同一个脚本里完成并先写快照（服务端每次 PUT 自动存）；脚本内置断言：迁移前后「带标签的节点数」不减、节点/关系数不变；先 `--dry-run` 打印差异。
- [`node.tags` 语义变更会影响老数据 / 老标签页] → 服务端校验会指名失败节点；刻意保留「导入草案按名字」的宽容路径，避免 LLM 端口失效；旧页面必须硬刷新（本仓库已多次踩到「旧页面自动保存覆盖新数据」）。
- [红点看不出来或太扎眼] → 红点 10px、白色描边 1.5px；尺寸与颜色都在样式表一处可调（`styles.ts`），`check:canvas` 加断言守住「命中标签才挂类」。
- [参数提取噪音大（同名局部变量、宏名）] → 只认上游参数表里的名字；清单先人工核对；明细写「出处行号」，有疑问可直接对照源码。
- [明细条目过多撑爆属性面板] → 明细按「用法」分组、默认折叠，只显示计数与参数名列表；展开才看逐条出处。
