## Context

见 proposal.md 的 Why。要动的是三处现状：

1. `src/hooks/useGraphSync.ts` 是唯一的服务端同步层：`AUTOSAVE_DELAY = 650` + `debouncedPersist` + 一个"`dirty` 即写整图"的 effect；`undo`/`redo` 直接整图 PUT；`saveNow`（Ctrl+S）也是整图 PUT。
2. `server/lib/store.mjs` 的写盘模型是"先快照旧数据、再原子替换工作文件"（`writeGraph`），轮转上限 50 份（`SNAPSHOT_LIMIT`）；`snapshot()` 产出的文件名是 `graph-<ISO 时间戳>.json`，文件内只有 `reason` / `savedAt` / `graph`。
3. `server/lib/paths.mjs` 的 `DATA_DIR` 写死为 `<项目根>/data`，断言脚本无法在临时目录里隔离运行。

约束：不引入新依赖；工作文件（`data/graph.json`）仍是唯一持久化文件；命令行脚本已经有三类写盘通道（直改文件 / `PUT /api/graph` / 进程内 `writeGraph`），"前端不再整图 PUT"不得误伤它们。

## Goals / Non-Goals

**Goals:**

- 前端整图替换工作文件的能力彻底消失；"保存"= 另存一份保留副本 + 先把本机坐标批量写回工作文件。
- 保留副本与自动快照同目录、可回滚，但不参与轮转、可单独删除。
- 只存在于本机的改动全程可见（脏标记）且离开页面被拦截。
- 服务端机制尽量不动：快照、回滚、护栏、串行写队列、原子写全部保留。

**Non-Goals:**

- 不改工作文件的路径（`data/graph.json` 仍是唯一持久化文件），不做多图谱/多文件工作区。
- 不给工作文件加锁或做多标签页协同（本次只把"覆盖"这条通道关掉）。
- 不改命令行脚本的写盘通道（它们仍可整图写入）。
- 不顺手清理既有的临时诊断块（`App.tsx` 与 `POST /api/graph/_diag`）与死字段（`graphStore.saving`/`setSaving`）。

## Decisions

**D1：保存 = 两步，"先批量写坐标、再另存副本"。**
替代方案：(a) 只另存副本、完全不碰工作文件——被否，因为拖拽坐标永远不会进工作文件，刷新页面后位置全丢；(b) 保存即整图覆盖——正是本次要禁止的。两步严格有序，否则副本与工作文件不一致。

**D2：保留副本的标记用"文件名后缀 `-keep` + 文件内 `pinned: true`"双写。**
轮转只需按文件名过滤即可跳过，不必为每一份快照读盘；文件内字段供历史面板显示徽标。替代方案：只靠文件内字段（轮转要读全部文件）、放进独立目录（历史面板要两套数据源）。

**D3：另存的正文用"本机整图"，而不是"服务端当前文件"。**
只有本机整图包含撤销后的状态，才能兑现"把我现在看到的存一份"。因此另存端点接收 body 里的 graph，但只把它写进历史目录，绝不替换工作文件；它仍走 `parseGraph` 严格校验（坏数据不许进档案），但**不加** PUT 的破坏性护栏——护栏是为"覆盖会丢数据"设的，另存不覆盖任何东西。

**D4：坐标回写走新端点 `POST /api/graph/positions`，一次请求一次写盘。**
替代方案：逐节点复用 `PATCH /graph/nodes/:id`——拖 20 个节点就是 20 次写盘 20 份快照，会把 50 份历史刷满坐标噪声；整图 PUT 则是被禁止的通道。

**D5：重命名走新端点 `PATCH /api/graph/meta`。**
`App.tsx` 的 `renameGraph` 目前"本地改 meta.name 后调 `saveNow()`"，也就是借整图 PUT 写一个字段。前端既然不再整图 PUT，就必须给它一条增量通道。替代方案：只改本地不写服务端——工作文件里的名称会与界面长期不一致，且刷新即回退。

**D6："只存在于本机的坐标"由 store 里的待写集合跟踪（`pendingPositionIds`）。**
拖拽落点收集被改过的节点 id，保存时只提交这些节点；保存成功或重新加载时清空。替代方案：保存时做整图坐标 diff——要在前端对两个大对象逐节点比较，且容易与服务端响应交错出错。

**D7：离开拦截用浏览器原生 `beforeunload`，不做自有弹窗。**
原生确认无法被忽略，且零 UI 成本；自有弹窗需要额外的对话框与状态，超出本次范围。

**D8：数据目录支持 `GRAPHIFY_DATA_DIR` 覆盖（默认值不变）。**
否则断言脚本只能在真实 `data/` 里跑，会污染工作文件与历史。这是让"保留副本不参与轮转"可被自动验证的前提。

**D9：`PUT /api/graph` 保留、但更新注释与护栏说明。**
脚本仍在用（`scan-param-tags.mjs`、`classify-params.mjs`、`restructure-tabs.mjs`、`normalize-layout.mjs`、`reset-atlas-nodes.mjs`、`import-atlas-graph.mjs`、`prune-tags.mjs` 默认模式）。护栏（单次删 >55% 节点拒绝）对"脚本误用"仍有价值，保留；只把注释从"前端整图 PUT"改为"前端已不再整图 PUT，这道护栏现在防的是脚本与外部调用"。

## Risks / Trade-offs

- [忘记保存会丢本机改动（尤其拖拽坐标）] → 脏标记常显（顶栏 + 状态条）、离开页面原生确认、README 与帮助写明"坐标手动保存"；这是用户明确接受的代价。
- [整理布局/打开时重排的坐标只在本机，刷新后会回到上次保存的位置] → 同上；规格里已把该行为写成明确契约（canvas-layout delta），避免被当成 bug。
- [两步保存非原子：坐标写进去了、副本没生成] → 如实报错、保持未保存状态、允许重试；不谎报"已保存"。
- [保留副本不轮转 ⇒ 无限增长] → 历史面板给保留副本单独的删除入口（只对保留副本开放，自动快照仍受轮转约束）。
- [撤销后本机与服务端不一致（工作文件仍是"已执行"的状态）] → 撤销语义写成"只作用于本机会话"，界面与文档如实说明；要留存就另存副本。
- [旧快照里的 `graph:autosave` / `history:undo` 理由标签不再产生] → 历史面板标签表删掉这几项，遇到未知理由回退显示原始字符串（既有 `reasonLabel` 行为），旧快照照旧可回滚。

## Migration Plan

无数据迁移：工作文件与既有快照格式不变，保留副本只是多了一种带标记的快照。上线顺序 = 服务端（新端点 + 保留副本 + 目录覆盖）→ 断言脚本 → 前端（删自动保存、保存改两步、离开拦截）→ 文案与文档。回滚策略：前端回退即恢复自动保存；服务端新增端点与字段是纯增量，旧前端不受影响（唯一不可逆的动作是前端不再整图 PUT，回退版本即可恢复）。
