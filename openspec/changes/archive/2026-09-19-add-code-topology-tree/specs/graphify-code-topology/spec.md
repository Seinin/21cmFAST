## Purpose

把 21cmFAST 的核心计算链自顶向下拆成一棵逻辑拓扑树：每一层只给该层最粗糙的框架、下一层用同一逻辑继续拆，繁琐细节一律压到树的最末端，使读代码可以从「阶段骨架」逐级下钻而不是沿调用链平铺地看。

## ADDED Requirements

### Requirement: 递归同构的分层口径

树的每一层 MUST 用同一逻辑拆解：先给出该层最粗糙的框架、说明本层在做什么以及下一层把它交给谁，再对下一层的每个节点重复同一动作。上层节点 MUST NOT 出现函数名、参数值、行号、具体数据结构字段等技术细节，这些细节 MUST 只出现在该分支的最末层。节点摘要 MUST 交代「为什么这样分」，MUST NOT 退化为下级的清单。

#### Scenario: 顶层只给阶段骨架

- **WHEN** 逐条阅读顶层阶段节点的标签与摘要
- **THEN** 每条只说清「这一阶段做什么、下一层拆成哪几块」，不出现函数名、参数值或行号

#### Scenario: 细节只出现在末端

- **WHEN** 检查某个分支的中间层
- **THEN** 中间层不出现只有该分支末层才应有的关键函数名与参数，最深一层才允许给出这些内容

#### Scenario: 同一逻辑可递归套用

- **WHEN** 从任意一个节点出发向下审视其子树
- **THEN** 它的子树与整棵树呈现同一种「先骨架、后细节」的分层形态，不出现某一层突然变成平铺的函数清单

### Requirement: 顶层按代码执行阶段切分并覆盖范围内的全部计算单元

顶层节点 MUST 与 C 端计算链的执行阶段对应（输入与全局配置、宇宙学背景、初始条件、微扰场与速度、结构形成、天体物理源、电离与复合、热与自旋温度、亮温输出，光子守恒等横切内容单列）。纳入扫描范围的计算单元 MUST 各自在树中有明确归属，MUST NOT 有计算单元无处可寻；MUST NOT 把计算单元堆成一份无祖先结构的文件清单。

#### Scenario: 范围无遗漏

- **WHEN** 把纳入扫描范围的计算单元清单与树中各节点的归属逐项比对
- **THEN** 每个计算单元都能在某条从根到叶的路径上找到，不存在只出现在清单里、不在树上的单元

#### Scenario: 阶段与文件对应

- **WHEN** 查看任一个顶层阶段的子树
- **THEN** 该阶段声明的职责能对上一个或多个明确的计算单元，不出现某阶段下挂着与它职责无关的单元

#### Scenario: 不堆成文件清单

- **WHEN** 检查任一个阶段的子树
- **THEN** 其下是「子过程 → 由谁负责」的层级，而不是一串平铺的文件名

### Requirement: 不等深的三至五层

树 MUST 允许不等深：结构简单的分支拆到「这件事由哪个计算单元负责」即可收尾（自根算起 3 层），结构复杂的分支（质量函数、电离、热化学等）MUST 允许继续深到关键过程与关键量（自根算起至多 5 层）。MUST NOT 为了对齐深度而插入不承载信息的填充节点。

#### Scenario: 简单分支三层收尾

- **WHEN** 查看一个结构简单的阶段分支
- **THEN** 它到第 3 层即已是「由哪个计算单元负责」这一粒度，不再继续下钻

#### Scenario: 复杂分支深到五层

- **WHEN** 查看质量函数、电离或热化学这类复杂分支
- **THEN** 它在第 4、第 5 层给出关键过程与关键量，且第 5 层的深度不超过声明的上限

#### Scenario: 无填充节点

- **WHEN** 检查任一只有单个子节点的连续层级
- **THEN** 这些层级各自都承载了独立的分解信息，不出现纯粹为了拉长深度而存在的空壳节点

### Requirement: 阶段话题切分与画布可见预算相容

图谱的话题注册表 MUST 按顶层阶段切分话题，话题数量 MUST NOT 超过注册表上限；任取一个话题，其成员数量 MUST 落在画布单次可展开的范围内，使打开该话题即可看清它的整体骨架。当某个阶段的成员数超出该范围时 MUST 继续细分为多个话题，MUST NOT 依赖用户手动逐层收起来回避超限。

#### Scenario: 单话题一次展开可见骨架

- **WHEN** 切换到任一话题并逐层展开
- **THEN** 不需要收起别的分支就能看到该话题的完整骨架，不出现「已到可见上限」的拦截

#### Scenario: 话题数量受上限约束

- **WHEN** 统计话题注册表的条目数
- **THEN** 条目数不超过注册表允许的最大话题数

#### Scenario: 跨阶段耦合不重复建节点

- **WHEN** 某个计算单元同时服务于两个阶段（例如源项盒子的产物既被电离阶段读取、又被热与自旋温度阶段消费）
- **THEN** 它只在一个话题里有一个节点，跨阶段耦合写在该节点的摘要与文档附录的耦合速查里，不复制成两个节点、也不靠关系边暗示

### Requirement: 文档章节与树节点一一对应且锚点零失配

每个节点 MUST 锚定到框架文档中与它同名的标题，使点击节点能直接跳到对应章节。节点的引用 MUST 只写标题文本或正则，真实锚点 MUST 由生成器用文档标题索引回填；MUST NOT 手写锚点。被引用的标题 MUST NOT 在生成器之外被单独改名或删除，改名时 MUST 与大纲同批更新。

#### Scenario: 每个节点都可跳转

- **WHEN** 逐个点击树中的节点
- **THEN** 都打开框架文档中对应章节，不出现引用为空或跳到错误位置

#### Scenario: 标题与大纲不一致时报错

- **WHEN** 大纲中的某个引用指向文档中不存在的标题（或改名后未同步大纲）
- **THEN** 生成器报错退出并指出该引用所在的节点，不产出草案

#### Scenario: 不手写锚点

- **WHEN** 检查大纲中引用的写法
- **THEN** 只出现标题文本或正则，不出现形如 `#some-slug` 的手写锚点

### Requirement: 一条命令可重建主图

以框架文档为唯一人工来源（大纲与草案都由它派生），MUST 能用「导出大纲 → 生成草案 → 覆盖导入」一条命令重建整棵主图。覆盖主图前 MUST 自动留存快照，使被替换的旧主图可被恢复。

#### Scenario: 从文档重建

- **WHEN** 依次运行生成器与覆盖式导入
- **THEN** 主图被重建为与大纲一致的内容，节点、层级与话题归属完全对应

#### Scenario: 旧主图可恢复

- **WHEN** 覆盖后需要回到覆盖前的主图
- **THEN** 可从导入时自动留存的快照恢复，或由旧主图自己的大纲与生成器一条命令重建
