## Context

见 proposal.md 的 Why。与做法相关的现状与约束：

- 该功能已实现并验证过：数据里 13 个节点带标记（全图 59 节点 / 54 关系），前端 9 个文件、服务端 4 个文件、脚本 2 个文件（审计脚本 + 一段画布自检断言），并有 8 条 requirement 已写入三份主规格。
- 未归档的 `openspec/changes/graphify-shared-utilities/`（24 项任务未勾选）描述的就是这套功能。
- **必须原样保留**（与本次无关）：初始条件子图三块骨架的全部产物（`scripts/lib/ic-blocks.mjs`、`scripts/restructure-initial-conditions-blocks.mjs`、三个工具脚本的三块口径、`check-canvas.mjs` 的三块骨架断言块、README 子图说明、`docs/notes/INITIAL_CONDITIONS.md` §8、已归档的 `2026-09-27-graphify-ics-three-blocks`）；以及画布上「数据同步后 / 就绪后 / 勾选标签后」各补一次浮层刷新的三处通用改进（它们顺带修好了红点陈旧）。
- 备份与历史快照只读：`data/graph.before-*.json`、`data/history/` 不得改动（它们仍含该字段，见风险条）。
- 服务端 schema 里该字段是 `z.boolean().default(false)`：**运行中的进程每次读盘都会把键补回来**，因此「清数据」必须在「改 schema + 重启」之后做，否则清完又长出来。

## Goals / Non-Goals

**Goals:**

- 数据、代码、脚本、文档、规则五层同时去掉该功能，且规格与实现重新一致。
- 移除过程可验证、可回滚，且不误伤与它无关的近期工作。
- 全仓不残留任何对已删符号的引用（可编译、可运行、无悬空注释）。

**Non-Goals:**

- 不做「默认关闭但保留代码」的开关——用户明确要彻底移除，留开关等于留死代码。
- 不重命名或重构相邻概念（`conditional`、话题过滤、红点标记一概不动）。
- 不清理备份与历史快照里的旧字段（只读，恢复时另见 Migration 说明）。

## Decisions

**D1：整体删除，而不是加开关或只关界面。**
用户已确认「连数据一起撤」。开关会留下两套状态与一处永远走不到的分支；只关界面则数据里留着无人消费的字段。

**D2：执行顺序 = 先改 schema → 重启服务 → 再清数据 → 回读验证。**
字段的 `default(false)` 会在服务端读盘时把它补回来。反过来做（先清数据）会出现「清掉 13 个、回读又全变成 false」的假失败。因此清数据前必须让服务端先不认识这个字段。

**D3：自检断言整体删除，而不是改成「断言标识不存在」。**
本次是撤回一个能力，保留反向断言等于永久钉住一个不存在的概念。删除时要连同它引用的常量与注释一起走，留下引用已删符号的代码会直接编译失败。

**D4：把「与本次无关的改进」明确列出并保留。**
三处浮层刷新与初始条件三块骨架都产出于同几段时间里，容易被顺手删掉。实现时按文件逐个核对：只删与该功能语义相关的片段。

**D5：未归档变更目录直接删除（用户决定）。**
`graphify-shared-utilities` 视为从未立项；其历史在本变更的 REMOVED 段里留有记录（8 条规则 + 原因），可追溯「为什么不再有这个能力」。

**D6：delta 用 `## REMOVED Requirements`，逐条带 Reason 与 Migration。**
归档会把这些 REMOVED 内联同步进主规格；Reason/Migration 是给后来的读者解释「为什么撤、要怎么办」的唯一载体。

## Risks / Trade-offs

- [数据「清完又长出来」] → 严格按 D2 的顺序执行，并在重启后回读 `/api/graph` 确认该键不再出现；若仍出现，视为服务未加载新 schema，不得继续。
- [历史快照与备份仍带该字段] → 它们只读不动；**恢复这类文件前先删掉该键**（节点 schema `additionalProperties: false` 会拒绝未知字段）。这条会写进 REMOVED 的 Migration 里。
- [用户浏览器里打开着旧页面，会把旧图写回] → 上一轮已经踩过（旧页面每 10–30 秒覆盖一次数据）。实施前先请用户刷新/关闭页面；数据写完立刻回读核对。
- [漏删某处引用导致编译失败或残留死代码] → 用语义检索（LSP 的引用查找）扫字段名、隐藏集合、标记上报方法、调色常量、store 动作；`tsc` 与 `eslint` 兜底。
- [误删三块骨架相关产物] → 实现时逐文件核对「本次要删的片段 vs 上一轮产物」，`check-canvas` 的三块断言块必须原样保留。
- [主规格撤完出现空 `## Requirements`] → 三份主规格各自还剩多条其它 requirement，不会出现空段；归档后 `openspec validate --specs` 必须仍 12/12。

## Migration Plan

1. 立项（本变更）→ 三个 delta 写 8 条 REMOVED；删除旧的 `graphify-shared-utilities` 变更目录。
2. 服务端四处去字段 → 重启 dev 服务 → 用审计脚本的清理模式清掉 13 个标记 → 删除审计脚本 → 回读 `/api/graph` 确认字段消失。
3. 前端逐个文件拆除（类型 → 调色 → 渲染器 → 画布 → 菜单 → 面板 → 顶栏 → 图例 → store），同步清理调用点。
4. 删自检断言块与 README 整节。
5. 验证：`tsc` / `lint` / `check:canvas` / `check:styles` + 语义检索 + 无头探针（四个入口消失、三块骨架仍在）。
6. 归档变更（内联同步主规格）→ `validate --specs` 仍全绿。

回滚：数据有写前备份与服务端快照；代码为纯删除，`git` 回退对应提交即可；规则可用 `git` 还原三份主规格。
