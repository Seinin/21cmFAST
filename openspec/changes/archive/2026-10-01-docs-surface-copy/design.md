# 设计：文档表面与命名纪律

## 背景

站点面向其他用户，表面文案里却混着"只该对我说的话"。根因是**没有纪律**：每轮口径变更都把"用户口径 + 日期 + 变更名"写进正文与注释，表面越积越脏，文件名也长出 `PLAN` / `DIGEST` / `_plan`。

## D1 「表面」的边界

| 层 | 例子 | 处理 |
| :-- | :-- | :-- |
| 站点直接渲染 | `docs/notes/**`、`Graphify/src/**` 的渲染字符串与注释、生成物散文 | **必须清** |
| 仓库内被外部读到 | `Graphify/README.md`、`Graphify/docs/DESIGN.md`、`docs/DIRECTORY.md` | 清"用户口径 / 应某问"式引用，**保留日期与结论** |
| 过程工作区 | `openspec/**`、`.codebuddy/**` | **不适用**（本职就是记录过程） |
| 历史生成快照 | `docling-graph/outputs/**` | 不动（含旧文件名，是某次运行的事实产物） |

## D2 什么算"废话"

判据一条：**这句话是写给"读者"的，还是写给"我"的？**

- 写给"我" → 禁：第二人称对话、「用户口径 / 用户明确 / 你说过的 / 按你说的」、记账（`本轮` / `本次变更` / `待补名单` / `只列不改` / `先记账` / `需你…`）、变更名、"日期 + 口径变更"。
- 写给"读者" → 留：技术状态（`未实现`、`本仓无此符号`、`代码不产出它`、`上一快照`）、规格用词（MUST / MUST NOT）、文献年份与数据快照日期。

**关键区分**：`待补` 作为数据字段语义（`algorithmPending`）或算法状态留；作为施工进度（"待补名单为空"）删。这一条靠白名单显式登记落地，避免门禁退化成一刀切。

## D3 命名清单

| 旧名 | 新名 | 理由 |
| :-- | :-- | :-- |
| `physics-chain/PLAN.md`（「施工计划与效果预览」，开头「给评审用」） | `physics-chain/design.md`（「物理链页：设计口径与实现」） | `PLAN` 与“施工计划”是过程词；正文进度叙事一并内容化 |
| `DEEPWIKI_21CMFAST_DIGEST.md` | `upstream-wiki-report.md` | 文件名带内部工具名与“摘要”过程词；工具名只留在正文“来源”里 |
| `FDM_nebrin_mcrit_plan.md`（「值不值得当基准？」） | `FDM_nebrin_mcrit.md`（「Nebrin+23：作为 CDM 基准与 FDM 改造依据的评估」） | `_plan` + 问句标题 |
| `FDM_code_migration_plan.md` | `FDM_code_migration.md`（「从 CDM 迁移到 FDM：代码改动方案」） | `_plan` |

两个 `README.md`（`atlas/`、`physics-chain/`）保留：目录级导览用 `README` 是文档惯例，标题本身已内容化，只清正文措辞。

## D4 门禁形态

`Graphify/scripts/check-copy.mjs`，与既有 `check-*.mjs` 同形（`ok(...)` 断言 + 计项）：

- 扫四处：`docs/notes/**`（md + json）、`Graphify/src/**`（含生成物）、`Graphify/README.md` 与 `Graphify/docs/**`、`docs/DIRECTORY.md`。
- 模式（四类）：`用户\s*20\d\d-\d\d-\d\d|用户口径|用户明确|用户要求|用户反馈|用户点名`、`按你说的|你说过的|你点名的|应「…」之问|给评审`、`本轮|本次变更|只列不改|待补名单|先记账|后决定`、`待你确认|需你实走|等你定|施工计划`、`变更 \`×\``，外加第二人称 `你|您`（先抹白名单片段）。
- 白名单（片段级，现三条）：`迷你晕` / `你晕`（物理名词）、`你是 Graphify 的建图助手`（写给模型的提示语）；新增须写明理由。
- 文件名检查：`docs/notes/**` 与 `Graphify/docs/**` 禁 `PLAN|TODO|DRAFT|WIP|TEMP|NOTES|DIGEST|_plan|备份|新版|最终`。

## D5 未采纳：内部施工文档整体移出站点文档库

`physics-chain/README.md`、`design.md`、`graphify/G0–G4` 都是开发过程文档，严格说站点读者不需要。但它们承载口径、已被 `docId` 与目录文档当文档库成员。**本变更只清措辞、不动位置**；"是否整体移出（如挪到 `Graphify/docs/`）"单列，需口径。

## Risks / Trade-offs

- [改名 → 引用断链] → 一次改全（目录文档、跨文档链接、`docId`）；验收按"旧名 0 命中（历史快照除外）" + `check:chain` 全绿。
- [清过头，把技术事实也删了] → 白名单机制 + 每条改写**只动措辞、不动断言内容**。
- [规则太严，以后没法记口径变更] → 变更记进 `openspec/**` 与 `docs/DIRECTORY.md` 变更表，不写进被读者读的正文。
- [门禁模式误伤] → 模式尽量窄（`你(?!晕)`）；误伤走白名单并写理由，而不是放宽模式。
