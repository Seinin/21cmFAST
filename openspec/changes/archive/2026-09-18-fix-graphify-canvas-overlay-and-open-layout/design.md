## Context

见 proposal.md - Why。当前状态与约束：

- `Graphify/src/components/GraphCanvas.tsx` 用一个 `relative` 根容器承载 cytoscape 画布与两个 `absolute z-20` 浮层按钮（连线手柄 `:428-442`、展开/收起键 `:444-470`），按钮位置直接写成 `left: 节点渲染坐标 + 20 / + 18`，没有任何边界夹紧；根容器既不建立层叠上下文也不裁剪。
- 键的可见性仅由 `refreshHandle`（`:184-221`）决定：焦点取「悬停节点 ?? 选中节点」，并有 `zoom < 0.6` 的绝对门槛；收起/展开在层级布局下会走整树重排（`cytoscapeSetup.ts:329-353`），而这条重排路径的布局选项带 `fit: true`（`layout.ts:78`），会重新取景。
- 展开集合是可见性的单一来源（`applyVisibility`），节点上限受 `MAX_VISIBLE_NODES` 约束，切话题只切可见性不重排（`GraphCanvas.tsx:252-264`）。
- 存档坐标来自旧力导向布局，`sync()` 只在「新增节点缺坐标」时才重排（`cytoscapeSetup.ts:438-447`）。
- 约束：不新增依赖（层级布局必须继续用 cytoscape 内置 `breadthfirst`）；不改变话题切换的位置稳定性；不引入 `data/graph.json` 之外的数据契约变更。

## Goals / Non-Goals

**Goals:**

- 浮层按钮始终落在画布矩形内，并在弹层/抽屉打开期间完全不绘制。
- 展开与收起入口都在悬停/选中/点击粘住时稳定出现，不受缩放级别影响，且可以反复使用。
- 展开与收起重排不改变缩放、不把被操作节点挪出原有屏幕位置。
- 打开画布时按当前布局算法重排一次，不再沿用与当前布局不一致的历史坐标。

**Non-Goals:**

- 不改层级布局算法与工具条选项集合（`breadthfirst` 仍是默认，切换逻辑不变）。
- 不改可见性派生方式、节点上限、超限拒绝语义。
- 不改节点/连线样式、右键菜单内容、拖放引用与连线创建流程。
- 不做移动端/触屏的专项适配（沿用现有指针语义）。

## Decisions

### 1) 浮层约束用「容器裁剪 + 坐标夹紧」，而不是调 z-index

- 决策：根容器加 `isolate` + `overflow-hidden`；两个按钮的实际定位改为经 `placeOverlay(node, size, viewport, gap)` 计算的 `bx/by`（右侧空间不足翻到节点左侧，再不足夹紧到边界内侧；垂直同样夹紧；节点中心出视野则返回 `null` 不绘制）。
- 理由：用户报告的两类现象是「越出画布压住面板」与「透过半透明阅读抽屉显影」。前者是缺裁剪与层叠上下文，后者是 `.glass-panel` 的半透明玻璃把下层辉光透出来 —— 单单抬高 z-index 只会让按钮真正盖在阅读器上，更糟。
- 备选：给侧边栏加 z-index 或给按钮加 `clip-path`。前者解决不了阅读抽屉的显影，后者在下游需要维护两套几何；都不如容器裁剪 + 夹紧直接。

### 2) 弹层/抽屉打开期间由 `App.tsx` 传 `overlayOpen` 直接停画浮层

- 决策：`GraphCanvasProps` 新增 `overlayOpen?: boolean`，值为 `reader.open || nodeDialog.open || edgeDialog.open || importOpen || historyOpen || helpOpen || !!confirm`；为真时不渲染两个按钮、清空连线预览与「点击粘住」状态。
- 理由：阅读抽屉 portal 到 `document.body`，画布里的元素无论如何调层级都在它下面，遮蔽它只能靠「不画」；同时「不画」也顺带避免用户对着看不见的画布元素操作。
- 备选：让画布监听弹层的 `open` 事件或查询 DOM 判断是否有弹层。传递布尔值更符合现有单向数据流，也便于后续新增弹层时显式登记。

### 3) 展开/收起入口统一按焦点显示（悬停 / 选中 / 点击粘住）

- 决策：只在焦点节点旁画一个键，语义随该节点状态切换——收起态（有未展开的直系子节点）显示带 `+N` 的展开键，展开态显示收起键；两个状态都只由「悬停 → 刚移开指针的 200ms 宽限内 → 点击粘住 → 选中」这条焦点链驱动，位置同样经 `placeOverlay` 夹紧。
- 理由：画面最省，且「用过一次就找不到」的三个成因都被单独解决——绝对缩放门槛被删掉（键只在焦点节点移出视野时才不画）、指针从节点移向键的途中由宽限期兜住、点过之后键粘住并跟随节点，因此收起后同一位置立刻可再点。用户明确选择悬浮可见（先前的「收起态常显」方案被否）。
- 备选：收起态常显（曾实现，画面明显变密，用户改回悬浮可见）；或把键做成固定工具条，缺点是与节点失去空间关联，展开哪个分支要额外确认。

### 4) 展开/收起重排走「不取景」路径，并做锚点平移补偿

- 决策：模块级 `runLayout` 增加 `fit` 覆盖参数；`GraphRenderer.runLayout(kind, { fit, anchor })` 在 `fit: false` 时记录 `(zoom0, pan0, 锚点模型坐标 m0)`，布局结束（`layoutstop`）后保持 `zoom0` 不变，并把 `pan` 设为 `pan0 + (m1 − m0) * z0`（由 `rendered = m*z − pan` 推出），使被操作节点屏幕位置不变。只有「打开图谱、切换布局、工具条重排、布局失败兜底」使用 `fit: true`。
- 理由：重排本身是必要的（层级位置就是语义），问题只在「顺带重新取景」：它把缩放拉低（触发旧的缩放门槛）并把画面整块换位，让用户失去方位，也让指针底下的那个键消失。锚点补偿同时满足「不跳视野」和「可连续点按」两个目标。
- 备选：`fit: false` 但不做平移补偿。缺点是重排绕原点展开时，被点节点仍会移走，键离开指针位置，连续操作体验不成立。

### 5) 「打开即重排」用一次性标志，由数据与话题两条时序共同消费

- 决策：`GraphRenderer` 增加构造即为 `true` 的 `pendingInitialLayout` 与 `layoutIfPending(): boolean`（仅当存在可见节点时才消费标志并重排）。接线两处：`sync()` 末尾、以及话题过滤 effect（`layoutIfPending()` 返回真则跳过 `fit()`）。
- 理由：数据与话题可见性是两条独立到达的路径，无论谁先到，都要收敛到「打开后恰好重排一次」。用「无可见节点不消费」保证先到的一方不会把重排浪费在空画布上。
- 备选：在 `App.tsx` 里用一个 `hasLaidOut` state 控制。缺点是把画布的时序知识搬到外层，且开发模式下 effect 重跑容易重复触发。

## Risks / Trade-offs

- [打开即重排会覆盖用户手动拖过的节点坐标（上一次会话的位置）] → 用户已明确选择「打开即重排一次」，并在追问答里确认；重排写回走 `history: false`，不污染撤销历史。
- [键只在悬停/选中时出现，指针恰好扫不到就不好发现] → 删掉绝对缩放门槛（键不再因缩小而整体消失）、指针离开节点后仍保留 200ms 宽限、点过一次后粘住并跟随节点；需要总览时仍可用工具条「展开到上限」。
- [`fit: false` 后新出现的子节点可能落在可视区之外] → 锚点补偿保证树根方向不跳；确实超出时可点工具条「取景」。这是「不跳视野」的必然取舍，spec 已把重新取景限定在显式动作上。
- [anchor 补偿与布局动画叠加导致视觉抖动] → 补偿必须在 `layoutstop` 之后执行，且 `fit: false` 下布局不动 zoom/pan，补偿只做一次平移。
- [键的 `pointer-events` 干扰 cytoscape 的节点拖动] → 键与画布是兄弟节点、事件不会落到 cytoscape 的画布元素上，并沿用现有的 `stopPropagation`；键的矩形仍在节点之外。

## Migration Plan

1. 先改 `layout.ts` / `cytoscapeSetup.ts` 的布局路径（不取景 + 锚点补偿 + 一次性初始布局），再改 `GraphCanvas.tsx` 的浮层与键显示，最后接 `App.tsx` 的 `overlayOpen`。
2. 校验：`npx tsc -b`、`npx eslint src scripts`、`npm run build`；重启开发服务后按 delta spec 的 Scenario 逐条目视回归（含阅读抽屉、贴边节点、收起后再展开、切话题位置不变）。
3. 回滚：改动集中在四个文件的少数函数内，若需回退可直接还原这些函数；数据侧只需重新拖一次节点或点工具条「重排」即可覆盖写回的位置。
