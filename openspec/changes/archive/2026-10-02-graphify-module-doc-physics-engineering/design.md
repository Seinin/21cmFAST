## Context

现在的形状：真源 `docs/notes/physics-chain/chain.json` 里每个块的 `module` 是 `inputs` / `algorithm` / `products[].note` 三份字段；渲染器 `Graphify/scripts/build-physics-chain.mjs` 的 `buildModuleDocs()` 把它摊成 `## 输入` / `## 算法` / `## 产物`，产物节里逐成员 `###` 带一句话说明与代码落点、逐步骤 `####` 带落点；闸门 `Graphify/scripts/check-physics-chain.mjs` 有三组断言钉住这副形状（形状、两节齐 + 覆盖 + 幂等、禁用措辞）。

真源约束：`module` 散文**只**用于文档——生成物 `Graphify/src/generated/physics-chain.json` 里没有它，应用视图也不读它。因此改结构只牵动文档链路：真源、渲染器、闸门、12 篇生成物、形状文档与规格。

另有两处硬约束必须在改形状时一起守住：成员与步骤的小节标题**就是锚点**（别处的「文献」引用靠它定位，`slug` 口径同 `Graphify/src/lib/slug.ts`），锚点必须唯一；物理链的规模数字（12 篇、39 个成员、21 条接口边、2 条回流边）不因文档改形状而变化。

落点现状：真源 `codeSites` 已逐条核定成员的核心行（`{file, symbol, line, endLine, needles}`，一个成员 1–2 条），渲染器 `sitesOf()` 以它为准，只在真源没给时才回落到 atlas「承担者」的函数体。但**步骤那一侧只有回落**：`####` 小节直接列 atlas 的整函数区间（`UpdateXraySourceBox` 751-798、`OneAnnularFilter` 650-747 这种），于是 `thermal.md` 一篇 23 条落点、`ε_heat` 一个成员挂 9 条；13 个 atlas 单元核不到函数体，其中 3 个（`thermal` 2、`galaxy` 1）成了只有标题的空壳小节，而这些标题正被别处当锚点引用（`thermal.md#thermochemc-率系数` ×3）。

## Goals / Non-Goals

**Goals：**

- 每篇文档先一段可独立通读的**纯物理**（有公式、无代码），再一段贴着它的**工程**（哪个成员、哪一步 → 哪个文件哪几行 → 输入什么、产出什么）。
- 真源一条字段对一段正文：物理条目、成员的输入与产出各自可逐条对拍，不含第二种口径。
- 锚点不丢、不重名：原来靠成员 / 步骤小节标题定位的引用一律照旧可点开。
- 工程节的每条引用都是**核心行**：一段能算出该量的行区间，不是碰过的整个函数；成员 1–2 条，没有只有标题的空壳小节。

**Non-Goals：**

- 不动一级块数、成员数、接口边与回流边，不动视图代码。
- 不改画布「源码」标签页与产物图自身的落点口径（那里仍可用整函数区间兜底）；收紧的只是**模块文档**这一侧。
- 不重写 atlas、论文出处与参数表；物理一节不新增未经核实的公式或数值。

## Decisions

**D1 骨架与锚点归属**：`#` 块标签 → `## 物理` → `## 工程`。成员 `###` 与步骤 `####` 的小节标题**只出现在工程节**，物理节用编号条目 + 独立成行公式、不设小节标题。理由：两节各放一份同名标题会让第二个拿到 `-1` 后缀，引用定位就漂了；锚点集中在工程节，slug 与现在逐字相同，引用表不用改。

**D2 真源字段**：`module.physics: string[]`（纯物理条目）+ `module.products: [{id, note, in, out}]`。`inputs` 与 `algorithm` 合并进 `physics`（输入本身就是"读进哪些物理量"，属物理）；`products[].note` 保留为成员的物理一句话，渲染成物理节末尾的物理量清单（符号 + 一句话，**不设标题**，所以不产生锚点）；`in` / `out` 是新增的工程口径字段，逐成员必填。替代方案：把 `note` 拆进物理叙述——否，会让 39 条一句话说明散在散文里，没有清单可对拍。

**D3 工程节的条目形状**：`### <成员标签> · \`file.c:123-145\``（**核定的核心行**写进标题，一眼看到"哪一块、哪一行"）+ `输入：…` / `产出：…` 两行；其下 `#### <步骤标签>` 给出该步骤所在函数的核定核心行。步骤不另写输入产出——步骤的输入产出去重后由成员级承担，避免同一件事写两遍。

**D4 物理节的禁代码判据**：自检扫物理节正文，命中文件名后缀（`.c` / `.h`）、`src/`、行号形态（`:数字`）、反引号片段或已核定的函数名，即失败。物理节里的参数名一律换成物理语言（如"转移函数的取法"而不是参数标识）。

**D5 闸门改口径**：形状断言改为 `#` 块标签 + `## 物理` / `## 工程` + 逐成员 `###` + 逐步骤 `####`；新增「物理节无代码痕迹」「工程节逐成员有落点且 `in` / `out` 非空」「落点必须是核定的核心行」「不许空壳小节」四组断言；保留两节条数对拍真源与磁盘 = 重新生成。替代方案：只改渲染器不改断言——否，那样形状回退不会被发现。

**D6 形状文档同步**：`docs/notes/physics-chain/README.md`（§模块文档）、`docs/notes/graphify/G4-物理链.md`（要素表与逐块读法）、`docs/DIRECTORY.md`（要素表与变更记录）、`docs/notes/physics-chain/design.md` 里描述文档形状的段落，以及任何仍写"输入 / 算法 / 产物"的地方，逐处按新形状改写。

**D7 迁移方式**：真源字段一次性改名，不留兼容层——仓库内 `module` 的消费者只有渲染器与闸门两处，一次改齐即可。

**D8 落点只写核心行**：工程节的代码引用一律取真源逐条核定的 `codeSites`（`file` / `line` / `endLine` / `needles`），渲染器只渲 `source === 'chain'` 的那部分，**丢掉 atlas 回落的整函数区间**。步骤不逐步骤各列一遍碰过的函数，而是按 `symbol` 复用同一条核定；成员级 1–2 条。为此把 13 个尚未核定的单元补齐（清单见 proposal「Impact」），核不出来的不许留空壳——闸门直接判失败（沿用"待补不许静默"，但从"报出来"收紧为"必须补齐"）。理由：冗余不在"步骤多"，而在"列的是碰过的整个函数、而不是算出它的那几行"。替代方案：① 文档里不列步骤落点、只留标题——否，步骤标题承载 72 处引用的锚点，标题下空着正是当下要修的病；② 继续列整函数区间、只去重——否，"哪一行"照样答不出来。

## Risks / Trade-offs

- [物理与工程的边界在个别量上模糊（如"电离效率是输入参数"这类口径）] → 判据落在自检而不靠人工：物理节禁代码标识，工程节的 `in` / `out` 只写读进来的量与算出去的量，输入参数写在 `in` 一侧。
- [成员小节标题从产物节挪到工程节后锚点变化] → 标题文字逐字不变，slug 因此不变；自检原有的"每条笔记引用能在文档里定位到小节"继续跑。
- [重写 39 个成员的输入产出可能引入未核实的说法] → `in` / `out` 只写该成员读入与输出的量名，来源限于已核定的落点与既有散文；核不到的成员保持现状不写新事实。
- [步骤级核心行要新核定 13 个单元，可能与既有成员核定重叠或冲突（同一函数被多个量引用）] → 先按 `symbol` 复用同一函数的核定；同一函数里两个量落在不同行时各给各的区间，冲突以读源码为准，并把该区间必须出现的标识写进 `needles`。
- [物理节公式从行内改独立成行可能被 `check-latex` 判错] → 逐条跑 `check-latex`，公式只做搬运与排版调整，不新增未核实的式子。
- [12 篇一次性重写，风险集中在可读性回退（条目变清单、公式堆砌）] → 每篇物理节按"读了什么 → 按什么公式 → 得出什么"分条，公式独立成行但每条只给一个主公式；最长篇 `thermal.md` 与最短篇 `const.md` 先各出一篇看样，再铺开。

## Migration Plan

1. 补核 13 个单元的核心行，写进真源 `codeSites`（逐条读源码，`needles` 写该区间必须出现的标识）。
2. 改真源 `module` 字段（12 块），物理条目与成员 `in` / `out` 一并写好。
3. 改渲染器：`buildModuleDocs()` 出两节，落点只取核定的核心行（步骤按 `symbol` 复用）。
4. 改闸门：形状、两节齐 + 覆盖 + 幂等，并新增物理节禁代码、工程节 `in` / `out` 非空、落点来源为真源核定、无空壳四组。
5. 重建 12 篇生成物，跑 `check:chain`、`check:copy`、`check:latex`。
6. 同步形状文档（D6 清单）。
7. 回滚：真源、渲染器、闸门、生成物与形状文档一起还原即可，无数据迁移、无外部依赖。
