## REMOVED Requirements

### Requirement: 模块文档写输入算法产物

**Reason**：三节把物理与工程混在同一处——算法一节既写公式又夹代码落点，产物一节把符号、物理一句话与文件行号混在一起。要"只读物理"或"只看某几行代码的输入产出"都得在同一段里自己挑。

**Migration**：改用下面的「模块文档分物理与工程两节」：`## 输入` + `## 算法` + `## 产物` 合并为 `## 物理`（纯物理、给公式、禁代码）与 `## 工程`（逐成员逐步骤的代码落点 + 输入产出）。旧小节的锚点不再存在，指向它们的引用改指工程节里同名成员与步骤小节。

## ADDED Requirements

### Requirement: 模块文档分物理与工程两节

每个块 MUST 有一篇模块文档，结构固定为 **物理 / 工程** 两节，物理在前。物理一节 MUST 只讲物理：读进哪些物理量、按哪些公式算出哪些物理量，该给公式的地方 MUST 给出公式。物理一节 MUST NOT 出现代码标识——文件名与目录名、函数名、参数名、行号，以及任何反引号包裹的代码片段——MUST NOT 写计算效率、并行分块、内存拷贝、构建与打包这类实现细节。工程一节 MUST 贴着物理一节逐条对齐：物理里的哪个成员、哪一步，落在哪个文件的哪几行，**输入什么、产出什么**；成员与步骤的小节标题仍承载锚点，逐个成员 MUST 给出代码落点与它的输入、产出。工程一节里的每条代码引用 MUST 是**核定的核心行**——一段真的算出该量的行区间；MUST NOT 罗列碰过的整个函数体或整文件，成员 MUST 只给核定的那几条（至多两条），步骤 MUST 复用其所在函数的核定区间。承载锚点的步骤小节 MUST NOT 只有标题：核不到核心行的 MUST 判为失败。文档 MUST 由真源生成，MUST NOT 手改生成物。文中 MUST NOT 出现施工说明、进度叙述、面向作者的口径说明、对话口吻或第二人称叙述。

#### Scenario: 两节齐全且物理在前

- **WHEN** 打开任意一篇模块文档
- **THEN** 物理、工程两节都在、物理在前，且工程一节逐条覆盖该块全部成员的代码落点与输入产出

#### Scenario: 物理一节无代码与工程内容

- **WHEN** 通读某篇模块文档的物理一节
- **THEN** 讲的是这个块读了哪些量、按哪些公式算出哪些量；MUST NOT 出现代码标识、FFT、并行分块、内存布局、构建流程这类内容

#### Scenario: 工程一节只讲落点与输入产出

- **WHEN** 通读某篇模块文档的工程一节
- **THEN** 每个成员与步骤都给出代码落点，以及它的输入与产出；MUST NOT 展开效率、并行、内存与构建这类枝节

#### Scenario: 落点只给核心行

- **WHEN** 通读某篇模块文档的工程一节
- **THEN** 每条引用都是一段能算出该量的核心行区间（含该区间内必须出现的标识），不是整个函数体、也不是整文件；一个成员至多两条

#### Scenario: 核不到核心行不许留空

- **WHEN** 某个成员或步骤没有核定核心行，而生成器照样写出了它的小节
- **THEN** 自检失败并指名该块与那个成员 / 步骤

#### Scenario: 改了真源没重新生成

- **WHEN** 真源里的成员或散文改了、生成物没跟着重建
- **THEN** 自检失败并报出该模块文档与真源不一致

#### Scenario: 禁用措辞被拦下

- **WHEN** 文档里出现对话口吻、施工痕迹或第二人称
- **THEN** `npm run check:copy` 失败并指名文件与行

## MODIFIED Requirements

### Requirement: 笔记引用指向真实存在的文档

每个对象带笔记引用时，其 `docId` MUST 是**相对 `docs/notes/` 的 POSIX 路径**，且该文档 MUST 在仓库里真实存在、能被文档阅读器打开；指向不存在文档的笔记引用 MUST 判为失败。为了让这条纪律当下就能成立，每个块（10 个过程块 + 2 个横切层）MUST 有一篇**模块文档**：`物理 / 工程` 两节，加逐成员与逐步骤的小节（小节即锚点）。模块文档 MUST NOT 只是空文件：它 MUST 给出标题与它承载哪些成员、哪些步骤。

#### Scenario: 点开笔记引用能读到文档

- **WHEN** 在物理链页点某个对象的「文献」标签并点击其中一条
- **THEN** 文档阅读器打开该文档，且停在引用指定的锚点上；停在文档顶部（锚点无效）或报「未找到文档」都算不通过

#### Scenario: 指向不存在的文档即失败

- **WHEN** 运行物理链自检，而某条笔记引用的 `docId` 在 `docs/notes/` 下找不到文件
- **THEN** 失败并报出该 `docId` 与引用它的对象 id

#### Scenario: 模块文档先搭好框架

- **WHEN** 打开某个块的模块文档
- **THEN** 看到该块的标题，以及它承载的每个成员 / 步骤的小节标题（小节可被锚点定位），`物理 / 工程` 两节齐全

#### Scenario: 补写内容不需要改页面代码

- **WHEN** 往模块文档的小节里补正文
- **THEN** 物理链页无需任何改动，引用照样点得开、定位得到
