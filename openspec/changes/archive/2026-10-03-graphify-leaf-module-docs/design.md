# 设计

## 目标与非目标

**目标**：图上不再有第三级——**最底层就是物理量与物理过程**，函数的子图整层删掉；模块文档改成与 `parent` 关系同构、**一个对象一篇**，并让每个对象的笔记引用指向它自己那篇。物理一节从编号条目改成成段叙述 + 不编号小标题，**每个成员恰好给一个公式**。

**非目标**：不动一级的形状（12 个块）与块间关系（21 条接口、2 条回流）；不动引用汇总的算法（`refs(块) = 成员并集`，只是最深一层的定义变了）；不动共享内核层成员的归属；不改实现步骤的核定数据（`stepSites` 照旧是唯一产地，只是它不再产节点）。

## 现状（实测 2026-10-02）

| 事实 | 数 |
| --- | --- |
| 块（一级） | 12（10 个过程块 + 2 个层） |
| 图上节点 | 39 个成员（含 5 个驱动量）+ 12 个块 + **18 个实现步骤** = 69 |
| 带子图的成员 | 6（`scaling_relations` 2 步、`source_grid` 3 步、`eps_heat` 5 步、`tk` 2 步、`jalpha` 3 步、`ts` 3 步） |
| 层成员 | `const` 1 个（`tgamma`，是量）、`kernel` 16 个（头文件名，不是量） |
| 现有模块文档 | `docs/notes/physics-chain/modules/` 12 篇，一篇一个块 |
| 成员带公式 | 39 个成员里 14 个有 `formula` |
| 步骤数据 | `chain.json` 的 `stepSites`：`file / line / endLine / symbol / needles / note`，**没有** `formula` |

改完之后：图上 **51** 个对象（12 块 + 39 成员），文档 **67** 篇（12 篇块 + 39 篇成员 + 16 篇头文件成员），其中 **55 篇叶子要逐段写**：

- 39 篇成员：25 篇缺公式要新写，其余 14 篇把公式与叙述补齐
- 16 篇共享内核层的头文件成员：不给公式，写"承载什么物理、被哪些块引用"

## 决策

### D1 图的层级到此为止：块 → 成员

物理链的底是**物理量与物理过程**。一级是块，二级是块的成员，没有第三级。判据只有一处：块 `enterable`、成员的子节点数恒为 0。函数怎么切、怎么调是实现细节，它回答的问题是"这个量由哪几行算出"，归代码落点管，不归图层管。

删掉的东西：

- 产物里 18 个 `step:*` 节点、`graph.subgraphs` 里「成员 → 步骤」那 6 条索引、`subgraphNodes` 的位置计算；
- 自检里"子图至少两个步骤""步骤节点必带 refs"这类断言；
- 视图侧"成员可进入"那条分支（双击成员不再换画布焦点）。

**保留**的是 `stepSites`：它仍是实现步骤落点的唯一产地，只是下游从"喂节点"变成"喂它所属成员"。

### D2 路径键的取法

| 对象 | 键 | 例 |
| --- | --- | --- |
| 块 | `id` 去掉 `block:` 前缀 | `thermal.md` |
| 成员 | `id` | `thermal/eps_heat.md` |
| 层里的头文件成员 | 文件名本身 | `kernel/cosmology.h.md` |

没有第三级，所以不再需要给步骤起文件名——`S14.3.1` 这类单元号因此没有机会进目录。

标题沿用现有口径：H1 = 对象标签逐字，锚点 = H1 的 slug。文件名与标题不同源是允许的（路径键回答"文档放在哪"，标题回答"这一段叫什么"）。

### D3 块那篇 = 成员并集，不写只属于块一层的散文

块那篇的正文由**它的成员**重算出来：物理一节 = 各成员物理环节按成员次序并集，工程一节 = 各成员落点并集（去重、按文件与行号排序）。块这一层除了"它有哪些成员"没有别的信息，写出来必然是重复或空话。

这让"上级必须是并集"这条既有纪律从**引用**推广到**正文**：一条落点、一句话都只有一处产地。

### D4 成员那篇 = 成段叙述 + 恰好一个公式；工程一节逐步骤

一篇成员写一个量：读进哪些量、依据什么物理推出公式、这个公式算出什么、算出来的量给谁用。公式写成独立成行的 `$$...$$`，**恰好一条**——多于一条说明这个成员其实该拆，一条都没有说明这一段没写。共享内核层的头文件成员是唯一例外：它不是可求值的量，物理一节写"它承载什么物理、被哪些块引用"，不给公式。

工程一节里，**实现步骤各占一个小节**（标题 = 函数名），每条落点给核定的核心行区间 + 一句说明（"这一行在算什么"），末尾给出该成员的输入与产出。这是"函数那一层只活在成员的代码与文档里"的落点：步骤名不上图，但读文档的人在工程一节里逐个看得到。

编号条目（`1. 2. 3.`）退场：它把"物理环节的顺序"与"渲染顺序"绑在一起，读起来是清单不是推理。

### D5 引用：块与成员各指自己那篇；步骤落点并进成员

- **笔记引用**：每个对象指向**它自己那篇**，锚点就是那篇的 H1。判据从"锚点落在一篇存在的文档里"收紧成"每个对象都有一篇自己的"。
- **代码引用**：成员的直接引用 = 它自己核定的落点 ∪ 它全部实现步骤的核定落点（去重、按文件与行号排序）。这一步是"删掉第三级"必须付的账——原先靠子节点汇总上来的落点，现在要显式并进成员自己。

汇总算法一个字不改：`refs(块) = 去重排序(块自身 ∪ 各成员)`。改动只在"最深一层"的定义：从 `step:*` 变成成员。

### D6 真源的形状

- `blocks.items[].module`（块级 `physics` 编号条目 + `products`）退场；
- 新增 `chain.docText`：键 = 对象 id，值 = `{ physics: [段落…], formula: '…' }`；层里的头文件成员用 `file:<文件名>` 当键。
- 落点仍旧只认 `stepSites`（步骤）与 `nodes[].codeSites`（成员）里的**核定**条目；`docText` 不放落点，落点与散文分家。
- 自检核 `docText` 的键集合 = 图上对象 ∪ 层成员，**不重不漏**；缺一篇、多一篇都失败。

散文与结构数据分开的原因：`nodes[].sections` 现在承载的是结构信息，把逐段散文塞进去会让"结构"这个字段同时承担两种读取方式；头文件成员在图外没有 `nodes[]` 条目，也需要一张统一的表。

### D7 路径规则两处各实现一遍，再对拍

与「引用去重与排序」同一种做法：生成器按 D2 算出路径写文件，自检**独立**沿 `parent` 链重算一遍并与磁盘逐条对拍——多一篇、少一篇、位置放错都失败。规则越简单（父目录 + 本对象键）越容易两处写成一样；一旦有人改了命名又想只改一处，对拍会当场报出来。

### D8 视图与旧文档的处置

- **视图只删不加**：`refs` 的出口形状不变（相对 `docs/notes/` 的 POSIX 路径 + 标题 slug 锚点），文档换路径只是数据变了；「进入子图 ↗」的判据改由数据侧给出（成员恒 0），视图侧删掉"成员可进入"那条分支。
- **旧文档删除**：`docs/notes/physics-chain/modules/` 下 12 篇扁平的块文档随新树一同落盘；`noteDoc` 字段从真源退场——路径现在由 D2 推导，不再逐块手写。
- 真源自己的 `docs/notes/physics-chain/README.md` 与 `design.md` 里讲模块文档形状与子图层的段落同步改。

### D9 两个名字带「（子图）」的工程项：先改名，是否合并待定

`hmf_impl`（`halocat` 的成员，label = `质量函数的算法 · 把 dn/dM 算出来（子图）`）与 `source_grid`（`halobox` 的成员，`把源项的积分算出来（子图）`）是这次删掉的那一层的产物——名字里直接写着「（子图）」，指着一个不再存在的机制。

本变更里**只做改名**（去掉「（子图）」后缀），不合并、不删节点：把它们并进 `dn_dm` / `nion` 会让 `halocat` 与 `halobox` 的成员数变化，牵连 21 条接口边与成员覆盖核对，风险大于收益。改名后它们是两个普通的工程项成员（仍挂在「实现细节」话题下、默认收起）。

**待定**：如果"工程项不该占一个底层节点"这个口径也成立，下一步再把它们并进各自产出的量，届时成员数 39 → 37。

## 迁移

分两步落，避免一次动 55 篇：

1. **先落结构**：删子图层（节点、索引、视图分支、自检断言）、D2 的路径规则、生成器写 67 篇、真源 `docText` 的空骨架、引用改为自指 + 步骤落点并进成员、自检的两处对拍与键集合核对。
2. **再逐块补散文与公式**：按块推进，一块一次（`const` → `kernel` → 10 个过程块），每块补完那几篇的叙述与公式，`npm run check:chain` 与 `npm run check:copy` 全绿再进下一块。

第 1 步做完之前，第 2 步的每块产物都不完整——所以第 1 步必须先把"缺散文 / 缺公式"变成**可指名**的自检失败，而不是静默写空文件。

## 风险

- **25 条新公式的物理正确性**：自检只能核"恰好一条"、核不了"推导对不对"。这一半要靠逐条对论文等式（成员的 `eq` / `page`）与代码实现复核。
- **删掉第三级会让成员的落点清单变长**：`eps_heat` 的「源码」标签从"自己的几行 + 5 个步骤框"变成一条清单里的全部行区间。归并规则（按文件归并）仍在，但要盯住它别把步骤的落点挤没——自检要单独断言"步骤落点一条不少"。
- **耦合面扩大**：改一个对象标签，过去只影响那一篇里的小节标题，现在同时改锚点与**目录名**。规则本身简单（D2），但 67 篇里任何一处标题没跟着改都会让引用点不开——这正是 D7 对拍要兜住的。
- **块那篇会很长**：`thermal.md` 要并进 6 个成员的全部环节。这是"自顶向下读一遍"的代价；成员那篇才是读细节的地方。
- **16 篇头文件成员的散文最容易写成废话**：它们不是可求值的量，写不出推理链。判据（D4）只要求"承载什么物理、被哪些块引用"，但要盯住它别退化成文件清单。
