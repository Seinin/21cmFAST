## Context

见 proposal.md - Why。现状：单一 `graph.json` 文档内用 `parent` 表达层级；渲染器以 focusPath + expandState 支持原地展开/下钻；当前数据有 33 个孤儿节点（用户手动拖拽拆解所致），`图一`/`图二`/`初始条件（S09）` 三个根层大框处于半拆解状态。用户已确认组织语义：**大框 = 装饰容器**（子节点直接画在框内，框不可进入），**模块 = 导航单位**（紧凑呈现，双击/按钮进入其标签页）。

## Goals / Non-Goals

**Goals:**
- 装饰容器/模块双语义落地：节点以 `frame: true` 标记装饰容器；可见性规则 = 焦点子节点 + 装饰框递归内联、模块紧凑（每个渲染器实例焦点固定，静态判断）。
- 数据重构脚本一次性完成：孤儿归位、解散 `图一`/`图二` 外层大框（S09 框保留为装饰容器）、模块归属调整、容器关系清理、要素分类、产物并入边标签、各层带重排。
- 不丢任何内容节点/边/源码引用；服务端快照历史继续有效。

**Non-Goals:**
- 跨层边的画布可视化（portal/ghost 节点）——本期只在属性页可见。
- 多文档（每模块一个 json 文件）拆分——继续单文档 + parent 层级即可支撑标签模型。
- 空白装饰框（不含任何子节点的纯视觉分组框）——本期的装饰容器均有子节点，空框留待后续。
- 服务端 API 变更。

## Decisions

### D1: 单文档 + parent 层级，而非多文档拆分

子图 = 某模块节点的可见内容集合，无需拆文件。理由：现有 /api/graph、校验、快照、撤销全部零改动；跨层关系天然保留在同一文档里。代价：标签页不是「独立文件」，但对用户不可见。备选（多文件 + graphId 链接）被否：要改 API/历史/同步层，收益不明显。

### D2: 每个标签页一个独立的渲染器实例（隐藏切换），而非单实例重建

App 为每个打开的标签页挂载一个 GraphCanvas（非激活的 `display:none`）。理由：缩放/平移/选中状态天然逐标签保留，无序列化/恢复视口的易错代码；焦点固定使渲染器可删去 focusPath/expandState 整套机制。代价：同图多实例的内存开销——节点总量 ~69，实例数受标签数（个位数）限制，可忽略。备选（单实例 + 视口快照）被否：切换时要重建元素并恢复视口，代码更复杂且易闪动。

### D3: 装饰容器沿用 `type === 'group'` 承载，不新增字段

`type` 为 `group`（大框）→ 装饰容器：渲染为复合节点（cytoscape compound parent），子节点直接画在框内，不可进入；非 `group` 且有子节点 → 模块：紧凑节点 + `· N` 徽标 + 光晕，可进入。可见性算法（焦点 F）：可见集 = F 的直系子节点 ∪ 其中装饰容器的后代（递归）；模块的后代不可见。理由：`group` 在本项目里本来就定义为「只作分组、不参与语义」的大框，语义与装饰容器完全一致；服务端 zod schema 会剥掉未知字段，新增 `frame` 字段还要改 schema；五个层带从 `group` 改为 `section` 即完成「框 → 模块」的角色转换。模块标记不用虚线（虚线专属于条件/可选，check:canvas 有断言守着）。

### D3b: 要素种类（复核后追加）

| 要素 | 类型 | 颜色 | 例子 |
| :--- | :--- | :--- | :--- |
| 函数 / 过程 | `method` | 紫 | `compute_halo_grid`、`_redshift_loop_generator` |
| 驱动 / 入口 | `driver` | 蓝 | `cli`、入口 A、入口 B |
| 参数 / 变量 | `variable` | 青 | `InputParameters`、`evolve_input_structs`、`GlobalEvolution` 容器 |
| 数据 / 场 | `dataset` | 天蓝 | δ_k、密度场、速度场（保留类型；本图数据多已文本化为边标签） |
| 交付产物 | `artifact` | 品红 | Coeval 快照 / LightCone / GlobalEvolution、OutputCache 落盘 |
| 装饰容器（含五个层带） | `group` | 墨绿 | ①入口层…⑤输出层、初始条件（S09）框、E1/E2/E3 lane |

新增 `driver` / `variable` / `artifact` 三型：前端 `lib/types.ts` 与后端 `server/lib/schema.mjs`、`server/schema/graph.schema.json` 的枚举同步扩（`section` 仍是「章节」，供文档骨架图用，不挪作他用）。图例只渲染当前图谱出现过的类型；服务端改动需要重启 dev 服务才生效。

**层级语义（复核后修正）**：**层带是容器**（`group`，带内直接放这一层的模块框），**模块 = 类 / 函数**；只有带子结构的模块（`compute_initial_conditions`、`入口 B`）可进入子图，层带不可进入。曾经把层带当成「可进入的模块」是理解反了，已纠正。

### D3d: 容器不参与关系（含悬停反馈的分工）

关系只发生在**模块**之间：容器（层带 / S09 框 / E lane）不连线。层与层的先后由「自上而下的排列 + 模块级流向」表达——主图里本来就有 18 条跨带模块边（`cli → 入口 A`、`_setup_ics… → compute_initial_conditions`、`perturb_field → 每轮入口`、`⑥ Coeval 装配 → Coeval 快照/LightCone/GlobalEvolution`…），它们已经读得出完整链路，因此早期在层带之间补的 4 条「主链」边一并撤掉并在断言里封死。

悬停反馈按「有没有信息量」分工：模块与关系有放大突出（模块按自身基准放大 1.18 倍 + 描边加深 + 光晕；关系加粗 + 箭头变大 + 显示关系名），容器没有任何悬停特效（大片背景变色即难看又无用，还会顺带触发邻居高亮把别的元素压暗）。渲染器侧在 `setHoveredId` 就把容器当作「未悬停」，样式表里也不留规则。

### D3c: 交付产物用边标签承载，不用节点

产物（种子池、P(k)、δ_k、HIRES_box_saved、hires/lowres 密度、ZA 速度、vcb、φ₂、2LPT、微小扰动场…）MUST 解散为节点、名称转写到「生产步骤 → 消费步骤」的边标签上。理由：图纸里产物本来就是箭头上的青色 chip；把每个中间数组都做成方框会让层内节点数翻倍、把「谁调用谁」的主线淹掉。代价：产物不再可单独选中/编辑，读法改为「悬停连线看文本」；为此新增工具条「显示边标签」开关，需要一次读全部产物时打开。

### D4: 数据重构走服务端 API 的一次性脚本

`scripts/restructure-tabs.mjs`：GET 全图 → 内存重构 → 整体 PUT（70→69 节点，仅删「图二」一个空壳大框；降幅 <50% 不触发同步护栏）。脚本幂等，可重复执行（归位规则按 id 前缀，能把后续被拖走的节点也收回来）。重构内容：
- `图一`、`初始条件（S09）`、E1/E2/E3 保持 `type: 'group'`（装饰容器）并保留；`图二` 解散（E lanes 改挂「入口 B · 三个顶层驱动」）；
- 五个层带从 `group` 改为 `section`（成为模块）；入口 B、compute_initial_conditions 获得子节点（compute_initial_conditions ← ic-frame；入口 B ← E lanes）；
- 归位按 id 前缀规则：`ic:*`（除 art-inputs）→ ic-frame；`atlas:fig2:eN:*` → 对应 E lane；`atlas:fig1:<lane>:*` → 对应层带；
- 补 ①→②→③→④→⑤ 模块级流向边；清理 source/target 指向「图二」的边并打印清单；
- 布局：主图五层单列竖链（x 对齐、均匀纵距、统一紧凑尺寸）+ 图一框合围；入口 B 三条 lane 横带竖排、步骤按序号横排一行；ic-frame 网格；其余各层网格。

### D5: URL 深链只记当前焦点（`?g=<nodeId>`），不持久化标签列表

刷新/新窗口恢复「主图 + 当前子图」两页即可满足「复制链接还原现场」；标签列表持久化（localStorage 或多参数）留待后续。非法 id、叶子节点、装饰容器 id 一律回退主图。

### D6: 进入子图的两个入口 + 一个隐式提示

双击（cy 容器上原生 dblclick + 命中测试）与属性页「进入子图 ↗」按钮，仅对模块生效；模块悬停时显示 ↗ 提示（复用现有悬停机制）。装饰容器与叶子双击不导航。单击一律保持纯选中。

## Risks / Trade-offs

- [重构脚本把节点挂错位置] → 归位规则可机器校验（脚本内断言：无孤儿；根层恰为 `图一` 且其内恰五层；各容器子数白名单：入口 B=3、ic-frame=24、E lanes=5/6/7、五个层模块的子数符合预期表），失败则不 PUT；服务端每次 PUT 自动快照，可回滚。
- [用户页面上有未刷新的旧标签，之后写回旧结构] → 已知风险同前；交付时提示刷新；服务端保留最近快照可手工恢复。
- [删除「图二」节点时误删引用它的边] → 脚本对 source/target 指向被删节点的边一律丢弃并打印清单，人工核对。
- [多渲染器实例下「添加节点/边」作用域混乱] → 添加操作落到激活标签页：若当前选中装饰框则新节点 parent=该框，否则 parent=激活焦点。

2. 前端改造（渲染器 → store → App/Inspector/工具栏）。
3. 浏览器实测：主图五层在图一框内、逐模块进入、装饰框内联渲染、标签切换/关闭、URL 还原、布局无重叠。
4. 更新 Graphify/README.md 的导航说明。
