## Goals / Non-Goals

**Goals**

- 右侧栏只剩两类**点得开**的证据（代码引用 / 笔记引用），不再有点不开的摘要。
- 「引用」这件事有**唯一真源口径**且可证伪：叶子最细，祖先 = 自己的 ∪ 后代的，模块 = 成员的并集；自检独立重算对拍。
- 12 个模块当下就**两类证据都不空**（骨架先说清楚"这里将来写什么"，正文可后补）。

**Non-Goals**

- 不替骨架文档写正文（用户口径：内容后续补，本次只给框架）。
- 不改叶子/成员引用的**来源口径**（仍来自真源 `code.sites` 与 `reviewSection`），本次只补缺口与做汇总。
- 不引入"引用可以手写在生成物里"的口子——生成物仍是纯产物，手写内容一律落真源或笔记文档。
- 不重排一级布局、不改检索、不改状态条。

## Decisions

### D1 只撤展示，不撤数据（撤的边界画在"展示"上）

撤掉 `Inspector` 三个口子与 `PhysicsChainView` 两处拼装；`codeAnchor` / `stages` / `stage` 三个字段**原样保留**，自检里断言它们存在的那些项（`:249-264` 一族）**保持通过**。

**Alternatives considered**：连字段一起删（"既然不用了就别留"）→ 否决，会同时打掉两样在用的东西：①「代码锚可证伪」这条规格失去判据；②按 `S14` 检索这条要求失去数据。

### D2 汇总的最小定义

**叶子判据**：图上**没有子节点**的节点（用 `parent` 反向表算，实测恰好是 21 个 `step:*`）。不另立"层级"概念——`parent` 是图已有的字段。

**汇总规则**（一处函数，生成器与自检各自独立实现同一句话）：

```
refs(节点) = 去重排序( 自身引用 ∪ ⋃ refs(直接子节点) )
refs(模块) = 去重排序( 模块自身引用 ∪ ⋃ refs(它的每个成员) )
```

块的成员取自 `blocks.items[].members`（唯一归属来源，已在用）；成员以外的节点走 `parent` 边。

**去重键与排序**（必须写死，否则生成物会抖、对拍会假失败）：

| 类别 | 去重键 | 排序 |
|---|---|---|
| 代码引用 | `file:line:endLine` | `file` 升序 → `line` 升序 → `endLine` 升序 |
| 笔记引用 | `docId#anchor` | `docId` 升序 → `anchor` 升序 |

**Alternatives considered**：不去重直接拼接 → 否决，父与子引用同一处落点是常态（`hmf.c:502` 会同时挂在 `mmin` 与其步骤上），模块清单会出现重复行、条数与清单长度对不上。用 `JSON.stringify(ref)` 当去重键 → 否决，`label` 不同就会重复。

### D3 笔记承载：一模块一份骨架文档 + 小节锚点

放 `docs/notes/physics-chain/modules/`，文件名额 `M<n>-<slug>.md`（层用 `L0-*.md` / `L1-*.md`）。文档内部：每个**成员**一个 `##` 小节，每个**步骤**一个 `###` 小节；锚点即小节标题的 slug（与 `Graphify/src/lib/slug.ts` 同一口径）。

于是：

- 步骤的笔记引用 = 它所属模块的骨架文档 + **它自己的小节锚点**；
- 成员的笔记引用 = 同一文档 + **它自己的小节锚点**；
- 模块的笔记引用 = 该文档（自身那一条）+ 汇总来的成员小节（见下）。

**为什么按模块切文档**：文档数量与"模块"粒度一致，一屏能读完一个模块的笔记；12 份骨架的维护面也比"一份巨型文档里 40 多个小节"更清楚。

**Alternatives considered**：一份大文档 + H2 分模块 → 否决，12 个模块 + 21 个步骤会让单文件过长，锚点表也更容易被改标题改坏。**每节点一份文档** → 否决，40+ 份骨架文件是噪音。

### D4 L0 / L1 两个层的引用**直接给**，不许靠汇总凑

L0（常数与网格层）只有成员 `tgamma`（是图上节点），汇总即可；**L1（共享内核层）的 16 个成员是头文件名、不是图上节点**——它没有任何 `parent` 子节点可汇总。故：

- L1 的代码引用 MUST 由真源的层声明**直接给出**（16 条文件级落点，`fileWide: true`）；
- L1 的笔记引用 MUST 由真源直接给出（指向 `L1-*.md`）。

自检据此判定"模块至少各一条"时，对 L1 走**直接给出**的分支（否则它必然为空、断言无法通过）。

### D5 补齐 4 个零引用量（`matter_power` / `vcb` / `perturb_field` / `filtered_xray`）

这 4 个量是 `graphify-chain-code-modules` 按"代码模块必有成员"补进来的（`CosmoTables` / `InitialConditions` / `PerturbedField` / `XraySourceBox` 四个盒子的产物），当时只补了节点、没补落点。本次在真源给它们各补真实 `code.sites`（只读 C 代码取行）。

**与既有断言的关系**：`:285-295` 那条"没有代码落点的量必须有身份标签"是**兜底**断言，补上落点后这 4 个量自然不再走兜底分支；兜底断言本身保留（将来新加的量仍受它约束），**不删**。

### D6 新增三类断言（都要求"独立重算"，不许自证）

1. **汇总对拍**：自检从叶子独立重算每个对象的引用，与生成物逐条对拍；不一致时报出**对象 id + 差的那一条**（多一条 / 少一条都要能指名）。
2. **模块非空**：12 个模块各自至少 1 条代码引用 + 1 条笔记引用（L1 走 D4 的直接给出分支）；其余对象**不同时为空**。
3. **笔记引用可开**：把既有的 `:270-282` 那条从"只扫非块节点"**扩到全部节点**，并加一条"锚点能在该文档里定位到小节"。

**反面演练（必做，不许只写在注释里）**：临时删掉某个叶子的一条笔记引用 → 断言 1 必须报"某模块少一条 + 是哪一条"，断言 2 在受影响模块上必须失败；恢复后转绿。再临时把某条笔记引用的 `docId` 改成不存在的路径 → 断言 3 必须指名该 `docId`。

### D7 与 `graphify-chain-code-modules`（27/31，未归档）的关系

本变更**撤销该变更 5.1 的展示实现**（它给属性页加了「代码锚」一行），但**不改它的 delta**：它的规格要求「块的代码锚可证伪」只规定**数据与自检**必须成立，没有任何"属性页要显示"的条款；本变更也**保留**代码锚的数据与断言（D1）。两个变更的 delta 因此不冲突，归档顺序不受约束——但**本变更归档时，主规格里那条"块 MUST 带可证伪的代码锚"必须已在位**（即 `graphify-chain-code-modules` 先归档），否则主规格里"每个块都有代码锚"这句话会暂时没有依据。这一点写进 tasks 的收口项。

### D8 证据入口是**一条小标签页**，卡片只印不带目录的文件名（口径变更 2026-10-01）

D1 撤掉代码锚 / 阶段号之后，`Inspector` 的 `collapsed` 态先用的是两颗全宽按钮「看实现（N）」「看文献（M）」+ 行尾「展开 / 收起」。用户口径（2026-10-01）改成：

- **一条分段标签页**（`role="tablist"` / `role="tab"`）切换两类证据，标签上只有**类别 + 数量**（「源码 12」「文献 3」），不再有「看实现 / 看文献」「展开 / 收起」这些话；数量为 0 的类别**不出标签**（不写「源码 0」把入口藏起来）。
- **两类不同时铺开**：选中一个标签只铺这一类，再点一下取消选择；未选中时一个路径、一个行号都不生成 DOM（D1 的"不是视觉上藏起来"照旧成立）。
- **卡片第二行只印不带目录的文件名**（`SpinTemperatureBox.c:120-145`、`thermal.md#members`）：目录前缀（`src/py21cmfast/src/`、`physics-chain/modules/`）对读的人是噪声。完整路径不丢——退到 `title`，打开仍按完整路径（`onOpenRef` 拿的是 `ref` 本身，与显示无关）。
- `collapsed` 态不再渲染标题与「文档 / 源码」两个**添加**入口：那是画布页的编辑动作，物理链页整页只读，标签页自己就说明是什么。

**落点**：`src/lib/types.ts` 新增 `refLocation`（完整落点，供去重 / 比较 / `title`）与 `refLocationShort`（只留文件名）；`Inspector.tsx`（标签页 + 卡片）与 `NodeTags.tsx`（标签明细）两处显示都走 `refLocationShort`。

**Alternatives considered**：保留两颗按钮只改名 → 否决，两行全宽按钮在窄栏里占掉半屏，而"看哪一类"本来就是单选；两类同时铺开（各自可折叠）→ 否决，正是"话多、占地方"的老问题。

## D9 「源码」清单按文件归并，主行只印文件名（口径变更 2026-10-01）

D8 落地的形态是"一条引用一张卡"：卡片第一行印 `ref.label`（成员名 / 算法名），第二行印 `文件名:行区间`。实测出两个问题：

- 一个模块的落点常挤在同一个文件里（M8 的 19 条里 7 条在 `heating_helper_progs.c`、6 条在 `SpinTemperatureBox.c`；M4 的 15 条里 8 条在 `cosmology.c`），一条一张卡就是十几张前缀相同的卡；
- 第一行的成员名在同一面板的「成员明细」里刚列过，在证据清单里再印一遍是重复。

- **「源码」按 `file` 归并**：同一文件上的多个行区间合成**一条**，主行＝**不带目录的文件名**（`codeRefFileName`，点它开这一文件的第一段落点），下面一行是该文件的行区间（`codeRefLineRange`），**每个区间自己可点**——落点一个不少、都仍可点即开。成员名标题退场。
- **归并只在物理链页**（`collapsed`）：画布页（`inline`）的引用可增删，一条引用一张卡才留得住删除的粒度。
- **「文献」不归并**：锚点就是落点，本来就是一条一个。

**落点**：`src/lib/types.ts` 新增 `codeRefFileName` / `codeRefLineRange`（`codeRefLocation` 复用后者、行为不变）；`Inspector.tsx` 新增 `codeGroups` / `codeCard`；`check-physics-chain.mjs` 加一条反面断言（`codeGroups` / `codeRefFileName` / `codeRefLineRange` 三个记号都在，`check:chain` 204 → 205 项）。

**Alternatives considered**：主行印 `文件名:全部区间`（`cosmology.c:213-231, 273-303, …`）→ 否决，8 个区间连成一行读不了，行区间也不再是独立的点击目标；保留成员名主行、只把同文件的卡并成一条 → 否决，并了之后成员名对不同区间各不相同，印哪一个都是丢信息，而它在「成员明细」里已有出口。

## D10 「进入子图」的数字只数这个对象自己的子对象（口径变更 2026-10-01）

现象：⑨观测量 里的 `P_21` 属性页写着「4 个子节点」，点「进入子图 ↗」进去是一张空画布。

原因：数字与入口都拿 `blockOf(id)` 取块——而 `blockOf` 回答的是「这个量**装在**哪个块里」，不是「它自己有哪几个子节点」。
对成员来说它返回所属块，于是 `block.memberCount` 被当成了成员自己的子节点数：⑨观测量 的成员数恰是 4，
`P_21` / `k_target` 在子图层里一条步骤都没有（44 个个成员节点里只有它们两个的子图为空），数字对不上、入口也开了个空的。
同一条口径对「有步骤的成员」也是错的（`eps_heat` 有 5 条步骤却报 6，＝ M8 的成员数），只是进去至少看得到东西，不容易被发现。

- **口径落一处**：`src/lib/physicsChain.ts` 新增 `subgraphSizeOf(nodeId)`——块＝`enterable ? memberCount : 0`，成员＝`graph.subgraphs[id].steps.length`，再退回按 `parent` 数（步骤子图由生成物直接给出，`ChainGraph` 补 `subgraphs` 字段，视图那处 `as unknown as` 强转随之退场）。
- **数字与能不能进同源**：标签页入口上的数字、`openSubgraph` 的前置判断、双击进去的可见集都由它决定；没有子图的对象拦下说明一句（进空画布比"点了没反应"更糟）。
- **归属反查不动**：`blockOf` / `blockLabelOf` 的语义（这个量装在哪个块里）是对的，`revealNode`（把选中的量摆到它所属块里）继续用它，只是不再拿它当子节点数。

**落点**：`src/lib/physicsChain.ts`、`src/components/PhysicsChainView.tsx`（`childCountOf` 退场）、`scripts/check-physics-chain.mjs`（**真跑** `subgraphSizeOf`，四个代表各钉一个值；另加一条反面断言：视图不再出现 `blockOf(id)` 这种数法，`check:chain` 205 → **210 项**）。

**Alternatives considered**：把 `P_21` 的「进入子图」入口藏掉但保留数字 → 否决，数字与入口是一件事的两面，留着数字就是留着一个假的读数；
换成"数字只显示不给出入口"（点不了）→ 否决，等于"点了没反应"；给 `P_21` 补一层步骤子图让它有东西可进 → 否决，它是后处理统计，图上没有更深一层，补出来是造数据。

## Risks / Trade-offs

- [汇总后模块的来源清单会很长：`block:thermal` = 6 成员 + 11 步骤 ≈ 17 条] → 标签默认不选（不占地方）+ 标签上写数量（主规格既有纪律）；若嫌长，备选是"模块只列模块级 1 条"，但那会削弱"叶子先写"这条纪律的可验证性（叶子不再必然出现在模块清单里）——**不采用**，除非用户改口径。
- [骨架文档 12 份容易写成空文件，等于没写] → 断言 2 之外再加一条骨架自身的形状断言：每份骨架 MUST 有标题 + 逐成员小节（与它承载的成员数一致），空文件判失败。
- [锚点会被改标题改坏] → 断言 3 的"锚点能定位"就是为它设的；锚点 slug 与 `slug.ts` 同口径，避免前端定位与自检判定两套算法。
- [补 4 个量的落点要读 C 源码，有写错行的风险] → 复用既有断言（`:178-193` 打开文件核行区间），写错的落点当场失败。
- [真源 `docs/notes/physics-chain/` 目前**未被 git 跟踪**（`??`）] → 改动无法 diff / revert；沿用上一轮做法，动前落一份备份，`git add` 与否仍是用户决定项（tasks 里列为前置，不静默）。
- [`refs` 从"生成时各写各的"变成"汇总"，若实现漏了某一层，页面会静默少显示] → 断言 1 的对拍是双向的（生成物多一条也失败），漏层必然被抓。
