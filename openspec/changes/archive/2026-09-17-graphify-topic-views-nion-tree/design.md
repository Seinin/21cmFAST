## Context

见 `proposal.md` 的 Why。设计受以下既有实现约束：

- `Graphify/src/graph/cytoscapeSetup.ts` 的 `GraphRenderer` 已用「`collapsedIds: Set<string>` + 给折叠根加类 + 隐藏其后代」实现折叠，且**深度无关**；元素增量同步后必调一次可见性重算，初次挂载另有 `initialFoldDone` 路径。
- 节点位置持久化在 `data/graph.json` 的 `node.position`，由布局落定回调回写；新增无位置节点才触发布局。
- `Graphify/src/lib/types.ts` 的 `cloneGraph()` 已对 `tags/refs/position` 做深拷贝，**新字段漏拷会在保存后丢失**。
- 服务端 `server/lib/schema.mjs` 用 zod 严格校验节点/边/元数据，未知字段策略与字段上限已存在，新增字段必须显式登记。
- 内容是派生视图：`docs/notes/` 为权威来源，`refs` 只写标题文本、slug 一律由 `mdIndex.mjs` 回填。

## Goals / Non-Goals

**Goals:**

- 用最小改动把「话题」做成图谱级视图，且不牺牲位置与折叠体验。
- 层级结构在数据层、生成器层、内容层三处同时保证无环。
- 主图从「按实现位置分类」变为「按物理分解自顶向下」。

**Non-Goals:**

- 不做每话题独立布局（即不引入 per-topic 位置存储）。
- 不引入新的图数据文件（不按话题拆成多份 `graph.json`）。
- 不改 fcose 参数、markdown 阅读器、LaTeX 管线、store 快照逻辑。
- 不改 `docs/notes/` 正文，本次只改 Graphify 的视图与生成脚本。

## Decisions

### D1 话题 = 共享节点池 + 多归属 + 可见性过滤（而非多份图谱文件）

`node.topics: string[]` 作为成员关系的唯一来源，`meta.topics` 作为注册表。切换话题时只计算可见集并把不可见元素置隐。

- **备选：按话题拆成多个图谱文件** —— 被否，同一节点的锚点/摘要会在多份文件里漂移，且导入脚本的 `--replace` 互相覆盖（`docs/DIRECTORY.md` §8.2 已记录过这个隐患）。
- **备选：把话题当节点级标签（tag）** —— 被否，用户要的是「切换后整张画布替换」，标签做不到整图替换的语义，也无法让一张图只承载一个话题。

### D2 可见集 = 话题成员 ∪ 祖先闭包

`visible(t) = { n : t ∈ n.topics } ∪ { ancestors(n) : n ∈ visible(t) }`。

- 必须含祖先：cytoscape 的 compound 父子关系不能有隐藏父节点，否则容器断裂、布局错乱并产生告警。
- 祖先与直接成员在视觉上区分：祖先降透明度，作为「上下文」而非话题内容。
- 不删除元素，因此 `position` 与 `collapsedIds` 天然保留——这是选择「过滤」而非「重建」的核心理由。

### D3 话题过滤与折叠合并为一次可见性计算

在 `applyCollapseState()` 的同一处 `cy.batch()` 内同时套用「话题隐藏」与「折叠隐藏」，避免两次批量改动造成中间态闪烁。切换话题后清空折叠态并按深度 1 重新折叠新可见集（见 spec `graphify-topic-views` 的「切换话题保留位置与折叠状态」）。

- **备选：话题过滤走独立函数、与折叠各改一次样式** —— 被否，会出现「先按旧折叠隐藏、再按新话题显示」的闪烁窗口。

### D4 层级只由 `parent` 表达，主话题零边

主话题为纯 `parent` 多叉树 ⇒ 结构上不可能成环；原有 19 条跨支语义（`depends_on`/`extends`/`relates_to`）改写进节点摘要。schema 与画布保留边能力，供骨架视图继续使用。

- **备选：保留语义边 + 生成器做图环检测** —— 仍被采纳为兜底（生成器统一校验 parent 链），但主话题不使用边，使「禁止成环」成为结构性事实而非仅靠校验。

### D5 大纲格式 v2：话题注册表 + 扁平节点

扁平节点是「一节点多话题」的前提（树形嵌套写法无法让同一节点出现在两个位置）。生成器继续承担「锚点解析 + fail-fast」职责，并新增结构校验（单父、无环、深度 ≤4、话题引用存在、话题闭包统计）与 `--topics` 预览。

- **备选：保留嵌套树写法、另加「引用已有节点」语法** —— 被否，两套寻址方式会让生成器与人工编辑都变复杂。

### D6 未决内容用话题承载，不再用 `question` 节点

`question` 类型定义与图例保留（骨架视图仍在用），但 Nion 图谱不使用该类型；未决条目进入 `pending`「待确认」话题，该话题有本话题自己的顶层根。这不改变「问题」这一概念的表达力，只是把它从节点类型提升为视图维度，避免未决条目混在正题画布上。

### D7 默认折叠深度 = 1

初次加载时折叠深度 ≥1 的容器（可见「根 + 两个乘子」= 3 个方块）；工具条「全部收起」保持「只留顶层」语义。二者是同一机制的两个不同深度参数，不合并成一个按钮。

## Risks / Trade-offs

- [`cloneGraph()` 漏拷 `topics` 导致保存后话题归属丢失] → 在实现任务中把「深拷贝新字段」列为显式验收点，并用一次保存-重载往返验证。
- [隐藏父节点导致 compound 断裂] → 可见集强制含祖先闭包，并在实现后以「成员父级不在话题内」的用例自测。
- [兄弟节点因过滤后位置过散，切换话题后画面不紧凑] → 切换话题后对新可见集跑一次布局；位置仍持久化，往返切换位置不变（spec 已要求）。
- [schema 加严后旧草案导入失败] → `topics` 缺省 `[]`，注册表缺省空数组；旧草案与骨架产物不受影响。
- [40 节点 4 层的摘要文本量较大，人工维护成本高] → 内容源仍是单个 `data/nion.outline.json`，生成器零警告输出统计（各话题规模、顶层方块数、深度分布）便于核对。
- [`--replace` 覆盖主图后回滚依赖快照] → 覆盖前自动快照到 `data/history/`（现 29 份），并在导入前先跑 `--dry-run` 核对统计。

## Migration Plan

1. 先生成并导入新主图，确认三个话题（主树 / 实现 / 待确认）能正常切换；此前的骨架视图可用 §8.2 的命令随时重建。
2. `graph.json` 由导入脚本自动快照，回滚方式为从 `data/history/` 恢复对应快照。
3. 字段新增全部有缺省值，不涉及数据迁移脚本；旧快照在无 `topics` 时按「不过滤」渲染。

## Open Questions

- 「待确认」话题中的条目在解决后如何回填：是移动到主话题对应节点下，还是在该节点摘要中标注「已确认」并保留话题条目？可在后续 change 中定，不影响本次的结构与验收。
