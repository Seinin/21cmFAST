## Goals / Non-Goals

**Goals:**

- 让 `docs/FDM_mcrit_theory.md` 能独立、按顺序读完：从 FDM 晕的密度剖面出发，一路推到方程 (1) 的数值解与它的数值结果，途中不需要打开 `docs/FDM.md`
- 让推导链上每一步的输入、假设、适用范围、失效后果都在正文里写出来，而不是留在表格注释或"关键观察"里
- 让 `docs/FDM.md` 第三篇只剩"现状 + 实现"，并在被迁走的位置留下可解析的导航

**Non-Goals:**

- 不改公式、不重算任何数值、不改动任何结论的方向（数值一律照抄 `fix-fdm-soliton-scalings` 的复算结果）
- 不改 C/Python 逻辑；脚本只改指向文档的注释/帮助文本
- 不新增核对脚本与图；不处理 `fix-fdm-soliton-scalings` 声明的范围外事项（脚本硬编码、旧图重绘）
- 不修 `scripts/merge_fdm_docs.py`、`scripts/prune_fdm_doc.py`

## Decisions

### D1 新文档的位置与命名：`docs/FDM_mcrit_theory.md`

沿用 `docs/FDM_<主题>_*.md` 的历史命名（原 `FDM_mcrit_algorithm.md` 已不存在，不冲突）。该名字不在 `merge_fdm_docs.py` 的 PARTS 列表内，即使该脚本被误跑也不会吞并新文档。

替代方案：`docs/mcrit_FDM_theory.md`——同样安全，但与 `docs/` 下既有命名习惯不一致，弃用；把理论内容放进 `FDM.md` 的新篇章——不解决"两份文档交织"的问题，弃用。

### D5 表述规范（本次的主要验收面）

新文档按下面的规则重写，规则本身可在验收时逐条 grep/抽查：

1. **公式前置说明**：每个公式前写清它要算什么、输入是什么、来自哪一步；公式后交代符号含义与单位（首次出现处）。
2. **假设就近交代**：假设一旦进入推导，紧跟着写它成立的范围和失效后果。例：$\gamma = 0$ 时方程 (★) 无有限解；$r_{\rm cool} \sim 0.1\,r_{\rm vir}$ 的系数只由量级论证给出，其漂移会把 $z$ 幂次带进 $M_{\rm eq}$；$a$ 的幂次若取 $-1/4$，§5 的红移演化方向翻转。
3. **数值表三件套**：表前给输入（$m_{22}$、$z$、$p$、$\gamma$、所用的 $M_{\rm sol}$ 形式）与产生方式；表后给误差范围；指出哪一列不能外推。
4. **禁用词**（含糊或修辞性评价，验收时 grep 检查）：认知地位、坦承、底线、黄金标准、可导出、非假设、自然的变量选择、非平凡、robust、物理上可信、可靠、本质、根本原因、包络。一律换成"依赖哪条假设、范围多大、假设不成立会怎样"的具体陈述。
5. **表格只承载数据与参数对照**，不承载结论评级。原 §10.5 的"可靠 / 物理上可信 / 量级正确性高"表改写为逐项说明每个量依赖哪条假设、误差来自哪里。
6. **要点列表只用于彼此独立的并列事实**，每条自身要带理由；不把单句断言拆成 bullet 冒充结构。
7. **公式与记号照抄**：保留 $u$、$r$、$\eta_p$、$L_k$、$k_{\rm eff}$、$R$、$M_{\rm sol}$ 等既有记号与方程编号 (1)、(3)、(★)。公式改写不属本变更。

## Risks / Trade-offs

- **[外部引用漂移]** 重编号后，`openspec/changes/archive/` 与 `train/` 下的旧引用（"FDM.md §5.12"）会指向不存在的节 → 缓解：新文档卷首与 `FDM.md` 导航段各放一份新旧节号映射表；已知引用点按 D6 清单全部更新，再用 grep 扫尾。
- **[改写过程中动到公式或数字]** 重写容易顺手"顺手改一改" → 缓解：公式与数值按"照抄 + 重排 + 补说明"处理；改完抽样复算 3 个算例（$z=10$、$m_{22}=1$；$z=20$、$m_{22}=1$；$z=10$、$m_{22}=0.5$）与 §6 表比对；任何公式层面的改动另开变更。
- **[改写变成拉长而非讲清]** 只把表格改成长句，信息量不变 → 缓解：验收时逐表检查是否有输入说明与误差说明；抽查 3 处原"关键观察/结论"段落，对比改写后是否给出了理由与适用范围。
- **[与 `fix-fdm-soliton-scalings` 的剩余任务交叉]** 该变更的 5.1/5.2 会动脚本与旧图 → 缓解：本变更只改脚本注释里的文档指针，不动其数值逻辑；并把"脚本更新后其文档引用应指向新文档"写进任务，避免两边反向修改。
- **[失效脚本被误跑]** `scripts/merge_fdm_docs.py` 的输入源已删除，误跑会用"源不存在"重建 `docs/FDM.md`（只剩扉页与附录） → 缓解：本变更不运行它，并在任务中记录该风险；修脚本另开变更。
- **[两份文档重复内容长期存在]** 拆分后若后续只改一份，会出现两处不一致 → 缓解：`FDM.md` 导航段写明"本主题的推导与数值以 `FDM_mcrit_theory.md` 为准"，并在新文档卷首写明同一约定。
