## Context

物理链页（第三页）的参数词条现在挂在画布左上角的浮窗里（`PhysicsChainView.tsx` 里那段 `absolute left-4 top-4 w-[21rem]`），分组写在页面里（`PARAM_SECTIONS`：天体物理参数 / 宇宙学参数），标签高亮走渲染器既有的全局标签机制（`activeTagIds` → `node.tagged` 光晕 + DOM 红点徽标）。

数据侧事实：`meta.tags` 48 条标签挂在 **23 个成员节点**上（驱动量 / 物理量 / 函数 / 工程项），**10 个块一个标签也没有**；块是 `type: 'process'` 的普通节点，但它同时是成员的 `parent`（画布靠它做"焦点只看直系子节点"），所以 `activeTagsOf` 的 `node.isParent()` 判据把它一并挡在标签之外。

## Goals / Non-Goals

- Goals：左侧改真侧栏（与画布页同一套面板机制）；词条按**代码里的参数类名**分组；选中参数时**画布上真的亮**（块亮、进块后产物也亮）；检索项补齐计数 / 代码类 / 阶段号 / 键盘。
- Non-Goals：不动画布页（第二页）的任何行为与数据；不给块**新增**语义标签（块的标签只能是成员并集）；不引入拖拽排序、不做参数收藏、不改状态条口径。

## Decisions

### D1 块的标签 = 成员标签并集，写在生成物里（不是视图现算）

用户口径（2026-09-30）："选中一个参数要能高亮**有此标签的产物或者天体物理过程**"。块没有自己的标签——"这个块涉及参数 X"这件事**完全由成员决定**，所以它是一份**可独立重算**的派生事实，与块已有的 `stages`（成员 `stage` 的并集）同一条口径：**同一份派生事实只写一处（生成物），视图与自检都读它**。

- 写法：块节点与 `graph.blocks.items[]` 各补 `tags`（成员标签并集，去重排序）+ `tagDetails`（一条 `kind: '块'`、note 写明"成员里有 N 个量读它"，与成员上的 `kind` 取同一形状）。
- 自检**独立重算**一遍并集比对（不信任生成器写的），并断言块标签都在 `meta.tags` 注册表里。
- 被否方案：视图现算（`physicsChain.ts` 里按 `blockOf` 反查）——同一件事会在"渲染器要读节点数据"与"视图要查表"两处各写一遍，且块的数据在生成物里就少一块事实。

### D2 渲染器放行"非装饰父节点"，不新增开关

`activeTagsOf` 现在对**所有** `isParent()` 返回空。但两类父节点的性质完全不同：

| 父节点 | 类型 | 该不该亮 |
| --- | --- | --- |
| 画布页的大框（层带 / S09 框 / E lane） | `type: 'group'` | 不亮（装饰，不参与标签与关系——既有纪律） |
| 物理链页的块 | `type: 'process'` | **亮**（它是天体物理过程本身，不是装饰） |

所以判据收紧为 `node.data('type') === 'group'` 才返回空，`check-canvas.mjs` 的"容器不亮红点"断言测的正是 `type: 'group'` 的框，口径不变。

- 被否方案：给渲染器加一个 `setTagRollupToBlock(true)` 式的开关，只让物理链页打开——要新增 `GraphSource` 字段 / `GraphCanvas` 透传 / 渲染器 setter 三处接线，只为了避开"父节点"这三个字；而判据本身（装饰 vs 非装饰）本来就在渲染数据里。

### D3 侧栏复用画布页的面板机制

`usePanelWidth({ storageKey: 'chainSidebar', side: 'left', defaultWidth: 304 })` + `ResizeHandle` + `aside.glass-panel`，收起为 36px 细条（细条上给展开按钮与词条数）。宽度与收起状态只进 localStorage（`graphify.panelWidth.v1`），**不进图谱数据、不进撤销栈**——与 `graphify-panel-layout` 既有四条需求一致。

### D4 选中参数时，选中落在"块"上

现在的做法是 `select('node', 矩阵里第一个成员)`——那个成员在一级的可见集之外（藏在块里），于是"选中了却看不见"。新做法：**先选它作用的第一个块**（右侧栏给过程块的属性页：成员明细 / 阶段号），画布上高亮同一批对象（块亮 + 成员亮）；词条下方那行"作用于 …"里每一项都可点，点它就 `revealNode` + `select` 到那个成员（先把它所在的块摆到眼前，与检索命中的做法一致）。

### D5 词条分组读生成物的 `param.group`

生成物里每个参数都带 `group`（代码里的类名：`AstroParams` / `CosmoParams` / `AstroOptions`），且**同一份参数在不同数组里可以属于不同类**（`R_MAX_TS` 在 `numeric` 数组、`group` 是 `AstroParams`）——所以分组只能按 `group` 字段，不能按数组名。页面里的 `PARAM_SECTIONS`（手写的两栏）随之退场。

### D6 检索项：计数、代码类、阶段号、键盘

- 四类命中的 `counts` 一直算着没人用 → 结果区顶部给一行分组计数，命中项按类分组显示（参数 / 物理量 / 过程 / 文献）。
- 参数命中：写出 `group`（代码类）与它落到哪几个**块**（由 `paramMatrix.nodes` → `blockOf` 反查，不新增数据）；节点命中：写出阶段号（`node.stage`），并让阶段号本身成为命中面（输 `S14` 能找到算在那段代码里的量）。
- 键盘：输入框内 ↑/↓ 移动当前项、Enter 定位、Esc 清空；不做全局快捷键（画布页的 Ctrl+F 仍归顶栏检索）。

## Risks / Trade-offs

- **块亮红点的视觉密度**：一个常用参数（`OMm`、`hlittle`）会点亮多数块，一级会出现一片红晕。这正是"这个参数动了很多过程"的真实读数；红点只画在**亮着**的块左上角，且一级只有 10 个块，密度可控。
- **`tagDetails` 的 note 对块要说清"这是并集"**：否则点块上的红点会读成"块本身有这个参数"。note 里写明"成员里有 N 个量读它：…"。
- **侧栏占宽**：默认 304px + 右侧检查器 336px 会压缩画布，但画布有最小宽度夹紧（`usePanelWidth` 已实现），且侧栏可收起为细条。

## Migration

1. 生成器补块标签 → `npm run build:chain` → 生成物多出块级 `tags` / `tagDetails`。
2. 自检加"块标签 = 成员并集"独立重算 + "块标签都在注册表里"。
3. 渲染器判据改 `type === 'group'` → 跑 `check:canvas` 确认画布页口径不变。
4. 数据层加参数类分组与检索项增强 → 新增 `ChainSearchPanel` → `PhysicsChainView` 改布局。
5. `check:chain` / 六个检查脚本 / `tsc -b` / `eslint` 全绿后写文档记账。
