## MODIFIED Requirements

### Requirement: 模块文档一节点一篇，与子图树同构

物理链的模块文档 MUST 与图上的父子关系同构：**图上每个对象恰好一篇 md**，其路径由「父对象的目录 + 本对象的名字」拼出；目录的嵌套关系 MUST 与对象的 `parent` 关系逐条一致——进入一篇就读到它那一段，再往下才是它承载的子对象。文件名 MUST 只写名字（MUST NOT 出现代码阶段号或单元号这类内部编号），标题 MUST 与图上该对象的标签逐字相同（锚点由标题算出，口径不变）。

- **块**（12 个，一级）：MUST 有自己的那篇，正文 MUST 等于**子对象的并集**——物理一节 = 各成员物理环节按成员次序并集，工程一节 = 各成员落点并集（去重、按文件与行号排序），符号与代码名、口径分野、参考文献三节 = 各成员条目的并集（去重）；它 MUST NOT 另写只属于块这一层的散文。
- **成员**（叶子，图的终点）：MUST 自己写那一段。实现步骤不再单独成篇，它们的核定落点与名字写在成员那篇的工程一节里。
- **共享内核层的文件成员**（`kernel` 的 16 个头文件名）：不是图上节点，但同样是那一层的成员，MUST 各有一篇。

每篇 MUST 是固定的五节，次序固定：`## 物理` → `## 符号与代码名` → `## 工程` → `## 口径分野` → `## 参考文献`。共享内核层的文件成员只保留 `## 物理` 与 `## 工程` 两节。

物理一节 MUST 是**成段叙述 + 不编号的小标题**（按物理环节分）：MUST NOT 用 `1. 2. 3.` 这类编号条目顶替叙述；MUST 给出公式，以及推到该公式的物理推理。**每个成员 MUST 恰好给一个公式**——写成独立成行的 `$$...$$`，多于一个或一个都没有 MUST 判为失败。共享内核层的文件成员是这条的唯一例外：它不是一个可求值的量，物理一节写"它承载什么物理、被哪些块引用"，不给公式。物理一节 MUST NOT 出现代码标识——文件名与目录名、函数名、参数名、行号，以及任何反引号包裹的代码片段；MUST NOT 写计算效率、并行分块、内存拷贝、构建与打包这类实现细节。

工程一节 MUST 贴着物理一节逐条对齐：物理里的哪个环节，落在哪个文件的哪几行，**输入什么、产出什么**。一个成员的工程一节 MUST 逐个列出它的实现步骤（小节标题 = 步骤函数名），每条落点 MUST 是**核定的核心行区间**——一段真的算出该量的行区间，MUST NOT 罗列碰过的整个函数体或整文件；落点同行 MUST 印一句核定说明（落点回答"在哪一行"，说明回答"这一行在算什么"）。核不到核心行的 MUST 判为失败。共享内核层那 16 个头文件成员是唯一的例外：一个头文件本身就是承载单位，没有可核的"核心行"，它们那几篇的工程一节给整文件级落点、不参与核心行核对。

每条落点 MUST 跟着印出该区间的**代码原文**：逐行转录自源码文件本身，单行落点把那一行印在落点同一行，多行落点用代码块逐行印出；MUST NOT 只给 `文件:起-止` 就算写完。印出的代码 MUST 与源码逐字相同（生成时逐行对拍，自检再独立对拍一遍），落点区间与代码行数对不上 MUST 判为失败。共享内核层那 16 个头文件成员按上面那条例外，不印整文件。

文档 MUST 由真源生成，MUST NOT 手改生成物。文中 MUST NOT 出现施工说明、进度叙述、面向作者的口径说明、对话口吻或第二人称叙述。

#### Scenario: 五节齐全且次序固定

- **WHEN** 打开任意一篇块或成员文档
- **THEN** `## 物理`、`## 符号与代码名`、`## 工程`、`## 口径分野`、`## 参考文献` 五节都在、次序与上面一致

#### Scenario: 两节齐全且物理在前

- **WHEN** 打开共享内核层那 16 篇文件成员文档里的任意一篇
- **THEN** 只有 `## 物理` 与 `## 工程` 两节、物理在前；符号与代码名 / 口径分野 / 参考文献三节不出现在这几篇里

#### Scenario: 文档树与父子关系同构

- **WHEN** 对照图上某个对象与它所属的块
- **THEN** 它那篇的路径恰好是块那篇所在目录加上它自己的名字；自检独立重算一遍全部路径并与磁盘逐条对拍，多一篇、少一篇、位置放错都失败

#### Scenario: 块那篇是成员的并集

- **WHEN** 通读一个块那篇
- **THEN** 它的物理一节恰好是各成员物理环节的并集，工程一节恰好是各成员落点的并集（去重、按文件与行号排序），后三节恰好是各成员条目的并集（去重）；把全部成员那几篇按序拼起来，内容逐字相同

#### Scenario: 块不自造散文

- **WHEN** 检查一个块的物理一节
- **THEN** 里面没有任何只属于块这一层、无法由成员重算出来的句子

#### Scenario: 物理节是叙述加小标题

- **WHEN** 通读某篇的物理一节
- **THEN** 是成段的物理叙述，按物理环节分了不编号的小标题；MUST NOT 出现 `1. 2. 3.` 这类编号条目

#### Scenario: 一个成员恰好一个公式

- **WHEN** 数某篇成员文档物理一节里的公式
- **THEN** 恰好一个（独立成行的 `$$...$$`）；两个或零个都判失败并指名该成员

#### Scenario: 文件成员不给公式

- **WHEN** 打开共享内核层里某个头文件成员那篇
- **THEN** 物理一节写它承载什么物理、被哪些块引用，不给公式

#### Scenario: 物理一节无代码与工程内容

- **WHEN** 通读某篇的物理一节
- **THEN** 讲的是这个量读了哪些量、按哪个公式算出什么；MUST NOT 出现代码标识、FFT、并行分块、内存布局、构建流程这类内容

#### Scenario: 工程一节逐步骤列出核心行

- **WHEN** 通读 `thermal/eps_heat.md` 的工程一节
- **THEN** `UpdateXraySourceBox`、`one_annular_filter` 等步骤各占一个小节，每条给核心行区间加一句说明，以及该成员的输入与产出；MUST NOT 展开效率、并行、内存与构建这类枝节

#### Scenario: 落点只给核心行

- **WHEN** 通读某篇成员文档的工程一节
- **THEN** 每条引用都是一段能算出该量的核心行区间（含该区间内必须出现的标识），不是整个函数体、也不是整文件；共享内核层那 16 个头文件成员那几篇给整文件级落点，是这个口径的唯一例外

#### Scenario: 核不到核心行不许留空

- **WHEN** 某个实现步骤没有核定核心行，而生成器照样写出了它的小节
- **THEN** 自检失败并指名该成员与该步骤

#### Scenario: 改了真源没重新生成

- **WHEN** 真源里的散文或落点改了、生成物没跟着重建
- **THEN** 自检失败并报出是哪一篇与真源不一致

#### Scenario: 禁用措辞被拦下

- **WHEN** 文档里出现对话口吻、施工痕迹或第二人称
- **THEN** `npm run check:copy` 失败并指名文件与行

## ADDED Requirements

### Requirement: 符号与代码名对照

每篇块与成员文档 MUST 在 `## 符号与代码名` 一节里给出一张对照表，把公式里的符号接到用户面的代码名上。每一行 MUST 至少给出三样：公式符号、用户面代码名（含默认值）、核定落点。落到代码里的换算 MUST 逐条写明类型——对数存储转线性、dex 转 nats、原样进 C——MUST NOT 只写"有换算"。同一个名字在本块里指两个不同对象时（逐晕量与体密度、对数存储与线性量），MUST 单列一条讲清两义，MUST NOT 只留歧义的那个。

表里的每一行 MUST 来自真源 `symbolMap`，MUST NOT 由生成器从别处猜；落点 MUST 逐个打开源码文件核对（区间合法、跨度内、非整文件、检定标识逐个命中）。

#### Scenario: 每篇都有符号对照表

- **WHEN** 打开任意一篇块或成员文档
- **THEN** `## 符号与代码名` 一节在，表里每一行都有符号、代码名与落点三列；块那篇的表覆盖它全部成员与它们用到的驱动参数

#### Scenario: 换算类型逐条写明

- **WHEN** 读表里某一行的"进 C 时的换算"一列
- **THEN** 写的是三类之一（对数转线性 / dex 转 nats / 原样），并给出做换算的那处代码落点

#### Scenario: 落点核不上就失败

- **WHEN** 表里某行的落点区间核不上（行号越界、或区间里找不到检定标识）
- **THEN** 自检失败并指名该文档与该行

### Requirement: 口径分野逐条列出并给判据

每篇块与成员文档 MUST 在 `## 口径分野` 一节里逐条列出该对象上「论文式与代码式不一致」的地方，每条 MUST 给出四样：对象、论文式、代码式、判据。判据 MUST 只有两种取值：**两码事**（理论与实现不是同一件事）与 **同一算法的细化版**（同一套算法、代码多几项）。两者一致的量 MUST NOT 出现在这一节里。真源 `divergences` 里每条 MUST 归属唯一一个对象；块那篇 MUST 等于其成员各条的并集（去重）。

#### Scenario: 只列不一致的条目

- **WHEN** 通读某篇的 `## 口径分野`
- **THEN** 每一条的论文式与代码式确实不同，并写明判据；论文与代码一致的量不出现

#### Scenario: 判据只有两类

- **WHEN** 写了一条判据不在两类里的分野
- **THEN** 自检失败并指名那条与它的对象

#### Scenario: 归属唯一

- **WHEN** 一条分野同时挂到两个对象，或一条都不挂
- **THEN** 自检失败并报出这条

### Requirement: 参考文献只登记代码给出的论文出处

`## 参考文献` 登记的是**论文出处**——代码注释或参数 docstring 里真的引到论文的那些：作者年份（`Park+2018`、`Watson et al. 2013`）、期刊卷页、arXiv 号，或论文里的节号与等式号（`Sec 2.1 of Park+2018`、`Eq. 7`）。给了就写：注释里引出处的，MUST 登记；没有就不写：注释只写"硬编码""未标出处""口径提醒"这类、一篇论文都没引的，MUST NOT 登记（注释只说代码自身的状态，不是文献）。

每篇块与成员文档 MUST 在 `## 参考文献` 一节里逐条给出四样：对象、代码位置、出处原文（代码注释或参数 docstring 的原话）、**本地有无正文**。"本地有无" MUST 由自检重新核对 `docs/论文/` 与仓内其它正文资源后判定，MUST NOT 由人工填写；每条 MUST 带上那句原文的所在位置，位置 MUST 打开源码或 `inputs.py` 逐个核对（区间合法、检定标识命中）。该节末尾 MUST 汇总这个对象**本地缺正文**的条目：有就逐条列出，没有就写明没有。

#### Scenario: 给了出处的都登记

- **WHEN** 某个对象的落点或它的参数 docstring 所在的那几行里，注释引了论文、节号或等式号
- **THEN** 该条出现在这个对象那篇的 `## 参考文献` 里，原文照抄、位置指到那几行；漏一条判为失败并指名该对象

#### Scenario: 代码没给出处的不登记

- **WHEN** 某条注释只说"硬编码""未标出处""这些平均值是错的"这类，没有引出任何论文
- **THEN** 它不出现在任何一篇的 `## 参考文献` 里

#### Scenario: 每条都指到代码位置

- **WHEN** 通读某篇的 `## 参考文献`
- **THEN** 每一条都有对象、代码位置、出处原文与本地有无四列；代码位置能在源码里核到那句原文

#### Scenario: 本地无正文如实标注

- **WHEN** 某条出处在本仓没有正文（只有代码注释或 docstring 的转述）
- **THEN** 该条标为本地无正文，并出现在这一节的「本地缺正文」清单里

#### Scenario: 本地有无由仓内实际内容重算

- **WHEN** 把一篇论文正文放进 `docs/论文/` 而真源里的"本地有无"没改
- **THEN** 自检失败并指名该条

### Requirement: 逐块深化只写在模块文档里

一个块的公式、符号对照、落点与出处深化 MUST 只写在该块的模块文档（及其成员那几篇）里，MUST NOT 另建平行页——`docs/notes/` 下 MUST NOT 存在按块复述同一套内容的专题页。模块文档的文件名 MUST 是该对象的名字，标题 MUST 与图上标签逐字相同；MUST NOT 带用途后缀、过程词或内部工具名。

#### Scenario: 没有平行页

- **WHEN** 在 `docs/notes/` 下按块名找文档
- **THEN** 只有模块文档一处承载该块的内容；MUST NOT 有第二处按块复述公式与落点的页面

#### Scenario: 名字就是对象名

- **WHEN** 看任一模块文档的文件名与标题
- **THEN** 文件名是该对象的名字（块 id 或成员 id，无后缀、无编号），标题与图上标签逐字相同
