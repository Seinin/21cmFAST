# graphify-physics-map

## Why

现在的图谱是**面向程序员**的：`data/graph.json` 里 65 个节点有 41 个是代码方法（63%），35 个节点唯一的证据是 `file:line`（54%），节点措辞是"k 空间高斯抽样""共轭对称修正"这类**数值实现语言**。而懂天体物理、不熟这套代码的研究者要看的是另外三件事：

1. **某个物理过程在这里是怎么实现的**（用物理语言说，不是读代码结构）；
2. **各物理过程之间怎么编排**（谁先谁后、产物喂给谁）；
3. 用**参数、物理量、物理过程**这些字段**一步定位到代码段**，并**快速索引论文**。

用户明确划了边界：**"评估原作者实现合理性"是他自己的活**——工具只负责"把代码翻成物理语言的图谱 + 代码本身快速定位 + 论文快速索引"，不做审读批注与评估字段。

好消息是**内容已经存在**：`docs/notes/atlas/` 那套分层文档（L0 产物矩阵、L1 的 16 个阶段、L2 的 71 个子过程、L3 的 208 个计算单元含「承担者」＝函数＋源码链接、L4 的 137 条「关键过程与关键量」、INDEX 的"我想知道 → 直达"问句表）本身就是物理语言写成的，`CONVENTIONS.md` 还规定了统一字段契约。缺的不是内容，是**可走的地图**。

## What Changes

新增与「画布」「参数矩阵」并列的第三页**「物理图谱」**，范式如下（本变更的核心交付物是这套范式，先评审再落地）：

- **真源**：`docs/notes/atlas/` 文档是唯一真源，物理图谱由它**单向生成**（改文档 → 图跟着变）；参数默认值/范围从 `src/py21cmfast/wrapper/inputs.py` 的结构体抽；论文出处从**源码注释里真实存在的引用**抽。
- **层级与粒度**：节点 = **16 个阶段**（S01–S16，含 Python 侧装配/编排/缓存）；下钻到 **71 个子过程**；**208 个计算单元不画成节点**，只作为每个过程的「实现落点」（文件 + 符号 + 行区间，一跳进源码预览并高亮）。
- **边**：以产物为枢纽（产出者 → 消费者），标签写产物名与编号——沿用画布"产物写在边标签上"的既有读法，依据来自 L1 的「输入产物 / 输出产物」。
- **字段表**：每个阶段/子过程带 作用与意义 / 关键过程 / 关键量 / 涉及参数（含默认值、是否 log10、范围）/ 上下游产物 / 负责入口 / 实现落点 / 论文出处。**缺就留空，不编造**。
- **四路检索**：参数、物理量、过程名（含 atlas 的"我想知道…"问句）、论文。
- **论文索引**：文献实体去重（作者-年份为键），每篇列出全部引用点（`file:line`），点即跳到那一行。
- **视图隔离**：照抄矩阵页那套（切过去清空画布状态、快捷键按视图隔离、顶栏只留跨视图动作、状态条换成本视图口径、切视图不写盘）。

**不做**：审读批注、评估结论字段、可写标注（评估是用户自己的工作）；不改工程画布图；不改标签政策（标签仍只服务参数）。

## Impact

- **文档**：README / DESIGN 增第三页与生成链说明
