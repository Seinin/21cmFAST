# Graphify · 知识图谱工作台

以 markdown 为知识库、用 JSON 持久化的本地知识图谱构建工具。知识库直接指向仓库根的 `docs/notes/`，左侧面板按文件夹分组列出这些 notes，中间是可编辑的力导向图谱，右侧是属性检查器；节点可以锚定到某篇文档的具体章节，点击即可在界面内读原文，也可以一键用 VS Code 打开。

## 快速开始

```bash
cd Graphify
npm install          # 首次运行需要
npm run dev          # 启动后访问 http://localhost:5178
```

开发模式由**单个 Node 进程**同时提供 API 与前端热更新，无需额外开第二个终端。

生产模式（构建后用静态产物跑，体积更小）：

```bash
npm run build
npm start            # http://localhost:5178
```

### 在 WSL 里使用

服务默认监听 `0.0.0.0`，Windows 侧浏览器访问 `http://localhost:5178` 通常可以直接连通。
若打不开，请检查：

1. Windows 是否开启了 WSL 的 localhost 转发（较新的 WSL2 默认开启）；
2. 若仍不通，改用 WSL 的 IP：在 WSL 中执行 `hostname -I`，用返回的地址访问；
3. 只想本机可访问时设 `HOST=127.0.0.1`；
4. 端口冲突时用 `PORT=xxxx npm run dev` 换端口。

## 功能导览

| 能力 | 说明 |
| --- | --- |
| 图谱画布 | **方框式**节点（文字写在框内），默认**手动摆放**：滚轮缩放、拖拽平移、节点拖拽定位；坐标**手动保存**（拖完按 `Ctrl/Cmd + S` 落盘，未保存时刷新会先确认） |
| 保存 = 另存为 | 前端**没有自动保存**：工作文件只被"点了才发生"的增量操作更新（建/删/改、标签、坐标回写），整图只作为**保留副本**另存进历史目录——不参与 50 份轮转、可单独删除、照常可回滚 |
| 视图切换 | 顶栏「画布 \| 物理链」：画布是**工程视角**图谱（`data/graph.json`，面向实现：模块、数据流、关系）；物理链是**物理语言**的推进链（`src/generated/physics-chain.json`，从观测量往下追到参数：谁产出、谁消费、哪个开关门控哪条边）。当前视图写进 URL（`?view=chain`），可分享、刷新不丢；两页互不影响。**物理链与画布状态隔离**：切过去会清空选中/连线/引用拖拽**与检索词**，隐藏画布专属控件与快捷键（只留另存与帮助），状态条改显示本页自己的口径 |
| 物理链（第三页） | **一级只讲物理**：过程框（物理主链阶段，见下文「分层纪律」）按真源给出的坐标摆放，**边写的是产物**；「旁路与实现细节」（旁路阶段下的诊断出口 + 工程节点）默认收起在底部一条**折叠条**里，条上写明项数与「不属于物理链」，一键展开/收起。左上「检索与参数词条」四路命中：**参数 / 物理量 / 过程名（含文档里"我想知道…"的问法）/ 论文出处**，命中收起层里的对象时标注来源并在选中后自动展开折叠条。右侧检查器**先讲物理**（作用与意义、产物、上下游、开关、参数），代码落点与文献引用收在「看实现（N）/「看文献（M）」两个**默认收起**的入口里——展开前一个路径、一个行号都不渲染。整页**只读**：要改得改真源 `docs/notes/physics-chain/chain.json` 再重新生成 |
| 子图标签页 | 画布上方一条标签栏：主图固定在前；**双击模块**（或属性页「进入子图 ↗」）在新标签页打开它的内容，标签页各自记住缩放/平移/选中，可切换、可关闭，当前位置同步到 URL |
| 层带 = 容器 | `大框` 类型节点是**容器**（①入口层…⑤输出层这五条层带、初始条件那五块产物链框、E1/E2/E3 lane）：子节点直接画在框里，纯视觉分组、不可进入、**不参与关系**（连线手柄 / 右键 / 属性页都不给入口，连上去会被拒绝） |
| 模块 = 类 / 函数 | 层带里的方框就是模块（类 / 函数，如 `compute_initial_conditions`、`_redshift_loop_generator`）；**带子结构**的模块显示 `· N` 徽标、双击进入它的子图标签页 |
| 要素着色 | 节点按**要素种类**取色：函数/过程（紫）、驱动/入口（蓝）、参数/变量（青）、数据/场（天蓝）、交付产物（品红）、容器/层带（墨绿）；图例只列本图出现的类型 |
| 参数（红点与明细） | 图级**参数登记表**（id / 名称 / 说明）；节点按 id 归属，**一个参数一个标签**。顶栏「参数」弹层勾选 → 有该参数的模块**左上角亮红点**；点红点 = 选中该节点并在属性面板展开该参数的明细（参数名 · 用法 · 出处行号） |
| 产物写在箭头上 | 交付产物（种子池、P(k)、密度场、速度场、Coeval/LightCone…）不是方框，名字写在「产出它的步骤 → 消费它的步骤」的边标签上；悬停连线可见，或点工具条的标签开关一次全显 |

## 分层纪律：一级只讲物理

物理链那一页的骨架是**每一层只讲一种语言**——一级不给工程与代码任何位置，但都留一键可达（可核查性不丢）：

| 层 | 只讲什么 | 内容 | 工程 / 代码痕迹 |
| --- | --- | --- | --- |
| 一级（物理链） | 物理过程与它们之间的产物 | 物理主链阶段（`PHYSICS_CHAIN_STAGES`）的过程框，边写「谁产出、谁消费」 | **零**：名字与摘要里不得出现文件行号、`Python`、`后端`（`check:chain` 直接断言） |
| 二级（子过程） | 每个过程里的计算步骤 | 双击过程框进去看该阶段下的量、步骤与开关 | 只有承担者级名称，不含行号 |
| 三级（证据） | 怎么落到代码与论文 | 检查器里的源码落点与文献引用点 | **默认收起**：`看实现 (N)` / `看文献 (M)` 展开前不生成任何路径与行号 |
| 旁路（旁路与实现细节） | 旁路出口与实现细节 | 旁路阶段（`BYPASS_STAGES`，当前 S04 旁路与后处理接口）下辖的诊断出口 + 工程节点（`topic:impl`） | 画布区底部**折叠条**默认收起，标题写明「不属于物理链」，一键展开 |

**判据不新造、只放一处**：`scripts/lib/physicsStages.mjs` 导出 `PHYSICS_CHAIN_STAGES` / `BYPASS_STAGES` /
`stageLayerOf` / `LAYER_LABELS`，注释写明出处（`docs/notes/atlas/L1-stages.md` 的历史口径 + 真源
`docs/notes/physics-chain/chain.json` 里**实际出现**的阶段）。生成器 `build-physics-chain.mjs` 与自检
`check-physics-chain.mjs` import 同一份，所以"一级有哪些过程"只有一个答案：真源里冒出没登记的阶段、
名单里写了真源没有的阶段，自检两边都报。

**判据放数据、视图只读标记**：生成物给每个过程框写 `chain: 'main' | 'bypass'`、给旁路节点挂
`topic:bypass`，视图不写死阶段号，只按标记分组渲染 ⇒ 要调一级范围，改一份名单 + 重跑生成器即可。

```bash
npm run build:chain   # 真源 + 源码 → src/generated/physics-chain.json（内容哈希戳记、幂等、可重跑）
npm run check:chain   # 分层纪律（一级集合 = 主链口径、旁路/工程不进一级、话题纪律、一级零工程痕迹）
                      # + 覆盖 / 落点 / 文献回读 / 幂等，出错退出码 1
```

## 画布怎么用

### 框的大小按内容算

节点宽度由**名称长度**决定（116–240 模型单位，超出就折行加高），不是所有框一个尺寸；
大框的最小尺寸由标题长度决定（标题 18 单位字号 + 14 内边距，只有标题的层带因此只有 52 单位高），
真正大小仍由子节点撑开。因此一屏里框宽高各异、但都与内容成比例。
悬浮放大是**按该框自己的基准等比放大**（不是统一的固定尺寸），所以大小关系不会被放大动作打乱。

### 字号、取景与「整层视图」

文字与方框同为**模型单位**（正文 13、关系名 12、大框标题 18）：缩放时一起变大变小，
和 draw.io / Figma 一致。这里曾经走过一段弯路——为了让文字「在屏幕上恒定大小」而写成
`font-size = 12 / zoom`，再夹一条「两行必须装进框高」的上限；上限一夹，字号就再也不会随缩放变大了，
于是整层取景缩到 0.5 时字只剩 6px，**越是看全局越看不见字**。现在的规则是：

| 机制 | 取值 | 作用 |
| :--- | :--- | :--- |
| 取景缩放下限 | 0.85 | 宁可让内容溢出画布（平移看局部），也不接受「全塞进去但字看不清」 |
| 取景缩放上限 | 1.45 | 一屏只有两个节点时，不要把框撑成一堵墙 |
| LOD 阈值 | 0.5 | 低于此值只留大框标题，小框文字隐藏（留着一层灰雾不如不给） |

配套的是**版面归一化**：位置最初来自画图脚本的 1300×900 画布，间距远大于框尺寸
（3 个大框散在 1885×985 里，而它们自己只有 200×120），任何字号策略都救不了这种空档。
`scripts/normalize-layout.mjs` 逐个父节点把子节点重排成紧凑网格（保持「先 y 后 x」的阅读顺序，
列数取「整层取景后字最大」的那个），把一层的范围收进一屏：

```bash
node scripts/normalize-layout.mjs http://127.0.0.1:5178   # 导入/大改数据后跑一次
```

归一化前后（小屏 1120×620 的画布）：一级视图 1885×985 → 829×120（字 6.1px → 15.1px）、
图一 402×1063 → 748×332（5.6px → 16.7px）、④ 红移循环 1211×207 → 493×302（10.3px → 19.8px）。

### 要素种类与配色

节点颜色表达的是**要素种类**（不是它属于哪一层）：同一层里「函数」与「参数」一眼可分。

| 要素 | 类型 | 颜色 | 例 |
| :--- | :--- | :--- | :--- |
| 函数 / 过程 | `method` | 紫 | `compute_halo_grid`、`_redshift_loop_generator` |
| 驱动 / 入口 | `driver` | 蓝 | `cli`、入口 A、入口 B |
| 参数 / 变量 | `variable` | 青 | `InputParameters`、`evolve_input_structs`、`GlobalEvolution` 容器 |
| 数据 / 场 | `dataset` | 天蓝 | δ_k、密度场、速度场 |
| 交付产物 | `artifact` | 品红 | Coeval 快照 / LightCone / GlobalEvolution、OutputCache 落盘 |
| 容器 / 层带 | `group` | 墨绿 | ①…⑤ 五条层带、初始条件的五块产物链框、E1/E2/E3 lane |

图例只列当前图谱实际出现的类型，不把没用到的类型堆上去。

### 交付产物写在箭头上（不是方框）

产物（种子池、`cosmo_consts 与 P(k)`、δ_k、`HIRES_box_saved`、hires/lowres 密度、ZA 速度、
vcb、φ₂、2LPT 速度……）**不占节点**：它们的名字写在「产出它的步骤 → 消费它的步骤」的边标签上，
和图纸里画在箭头上的青色标签是同一个读法。每个产物名至少出现在一条边上，解散不丢信息。

- 默认：**悬停**那条线（或选中它）才显示标签，画布保持干净；
- 想一次读完整条数据流：点工具条最右边的**标签开关**，当前画布的所有边标签常显（各标签页互不影响）。

### 参数（红点与明细）

这一块解决的问题是「**这个节点碰了哪个参数**」，所以界面上就叫**参数**：**一个参数一个标签**，
勾选即筛出「所有碰这个参数的节点」。

参数是**图级登记**的：`meta.tags` 里登记 `{id, 名称, 说明}`，节点只存 id——所以改名不会让任何
节点的归属失效。顶栏「参数」弹层里勾选某个参数：

- 持有该参数的**模块**左上角亮一个**小红点**（容器不参与，不亮）；
- **点红点** = 选中该节点，并在右侧属性面板展开**该参数的明细**；
- 勾选是**纯视图状态**：不入撤销栈、不落盘，刷新即回到「一个都没勾」。

属性面板的参数区块里可以**从登记表多选**，也能当场新建。自由文本输入已经移除——允许自由文本就等于
允许出现登记表外的名字，「改名不动归属」这条承诺也就不成立了。

命名规则（参数标签）：**一律用原变量名**，如 `PHOTON_CONS_TYPE`、`HII_DIM`、`BOX_LEN`。
（早期规则是"物理量用中文名 + 符号"，只给 `BOX_LEN` 配过「盒子共动边长 L」——当时只有它一个带中文，
读图反而要来回对照变量名，已撤销；`scripts/color-tags.mjs` 里留着这次改名的记录。）

**标签只服务参数**（政策）：注册表里只有一类标签——参数标签，由 `scan-param-tags.mjs` 从节点的
**源码引用**扫出来，一个参数一个标签，带 `group`（`inputs.py` 里 InputStruct 的子类名）与类别色。

> 历史遗留的**自由标签**（`初始条件` / `2LPT` / `C: rng.c` / `仅 CLASS` …18 个）已按
> `scripts/prune-tags.mjs` 的政策全部删除：它们粒度混乱、跟参数筛选混在一起。`npm run check:graph`
> 有一条门——注册表里只要出现无 `group` 的标签就直接失败。
> 需要表达"某个节点属于哪条链 / 哪个专题"时，用**话题**（`topics`，如 IC 链的
> `ic-pre` / `ic-density` / `ic-velocity` / `ic-boundary`）与容器的子图并集，不要再引入标签。

两条 schema 硬规则（写入前强制校验，`npm run check:graph` 也会复查）：

- **每个标签都必须有一篇 notes 文档**（`docId` 非空；没有就先建一篇空壳）——不允许「有标签、没处可查」；
- **标签只长在叶子上**：有子节点的模块不自己挂标签，它的标签是「子图里所有叶子标签的并集」，由前端
  派生展示——所以"给分组节点挂标签"这种写法会被直接拒掉（分组照样能按子图标签筛出来）。

弹层里按**代码里的划分**分组，组名就是 `inputs.py` 里 `InputStruct` 的子类名
（`MatterOptions` → `SimulationOptions` → `AstroOptions` → `AstroParams`，与类定义次序一致）。分类不是手写的：
`node scripts/classify-params.mjs` 每次从 `inputs.py` 解析「字段 → 所属类」写入 `meta.tags[].group`，
同时把注册表按类顺序排好。

**右侧属性面板里的标签按类别上色**（同一类别同色，扫一眼就能分清是四类里的哪一类）：

| 类别 | 颜色 |
| :--- | :--- |
| `MatterOptions` | 蓝 `#1D4ED8` |
| `SimulationOptions` | 绿 `#047857` |
| `AstroOptions` | 橙 `#B45309` |
| `AstroParams` | 紫 `#7E22CE` |
| 未分类（`group` 空） | 中性灰 `#4B5563`（政策下已不存在这类标签，仅作前端兜底） |

配色只有一处定义，但脚本是 `.mjs` 读不了 TS，所以是**两张同值表**：前端渲染看 `src/graph/palette.ts`，
脚本 seed 看 `scripts/lib/tag-groups.mjs`；`npm run check:canvas` 有一条断言要求"每个标签的 `color`
等于它 `group` 的表值"，改一处忘另一处会直接失败。数据里的 `meta.tags[].color` 由
`node scripts/color-tags.mjs --apply` 按同一张表写入（前端取色优先用它、缺省按 `group` 派生）。
**画布上的红点仍是固定玫红**（`TAG_DOT_COLOR`），不按类别变色——免得让人以为"面板里的色 = 画布上那个点"。

参数名清单与明细的口径：

- 参数名清单来自上游权威定义 `src/py21cmfast/wrapper/inputs.py` 里 InputStruct 的子类
  （CosmoParams / MatterOptions / SimulationOptions / AstroOptions / AstroParams，共 136 个名字）；
- 明细逐条给出「参数名 · 用法 · 出处行号」，用法分 **赋值 / 入公式 / 开关** 三类，出处可点开对照源码；
- 只认**源码引用**：节点没有 `file:line` 就扫不出参数（不凭印象填）。所以"给节点补源码引用"是参数标签
  出现的前提——S09 初始条件那批过程节点过去一条源码引用都没有（只锚文档），参数标签自然是空的；
  现在每个步骤都补上了对应的 C 区间，扫描器才能写上 `tag:PERTURB_ALGORITHM`、`tag:USE_RELATIVE_VELOCITIES`；
- C 与 Python 一视同仁：引用落在 `.c` 时按花括号圈函数体、屏蔽表换成 C 的那套（块注释 / `//` / 引号），
  否则 `inputs->matter_options->PERTURB_ALGORITHM` 这类写法扫不到，而注释里提到的参数名又会被误算成命中。

脚本（默认读服务端、写回整图，服务端每次写入都会留快照、可回滚；`prune-tags.mjs` 与
`apply-annotations.mjs` 另支持直改文件的模式，见各自条目）：

- `node scripts/scan-param-tags.mjs`（默认 dry-run，核对后加 `--apply`）：**主脚本**——扫描节点的源码引用，
  按「引用所在的**函数体**」找参数名（跳过 docstring 与注释行，散文里的 `X=True` 不是赋值；
  多行签名必须先跳完，否则函数体只剩签名那几行，函数中段的物理量一个都扫不到），
  逐条给「参数名 · 用法（赋值/入公式/开关）· 出处行号」，并按 inputs.py 的类写 `group`；
- `node scripts/classify-params.mjs`：只刷新 `group` 与注册表顺序（分类没变就不写盘）；
- `node scripts/prune-tags.mjs [--file]`：**政策实现**——只保留有 `group` 的参数标签，其余从注册表、
  节点 `tags` 与明细里一并摘掉（幂等）。默认走 API；`--file` 直接改 `data/graph.json`（服务没在跑、
  或不想惊动它时用：写前留 `data/history/` 快照并用服务端同一份 schema 校验）；
- `node scripts/apply-annotations.mjs <draft.json> [--dry-run] [--tag-doc <docId>]`：把一份"标注草稿"
  （标签 / 可选性 / 源码引用）合并进 `data/graph.json`。**为什么不用 `import-graph.mjs`（走 API）**：
  草案 schema 的 `meta` 不认 `tags`，注册表条目里的 `docId` 会被静默剥掉，而「每个标签都必须有文档」
  是强制规则——所以按 `normalize-tag-rules.mjs` 记录的同一顺序办（**先改文件 → 再重启服务**），
  并在写盘前用服务端**同一份** `graphSchema` 校验；写盘前会留快照。

两条纪律（都是被事故教出来的）：

- **扫描器只增不减**：`scan-param-tags.mjs` 只刷新自己负责的参数标签（`tag:<已知参数名>`），
  其余标签与注册表条目一概不删。过去它把「所有 `tag:` 前缀的 id」当成自己的产物先删后建，
  一次重扫就把整条 IC 链的标签抹掉了——删除现在只有一条通道：`prune-tags.mjs` 的政策清理；
- **「可选」必须是数据**：写 `conditional`（画布虚线的依据），标题里写「（可选）」不算数。
  `build-initial-conditions-graph.mjs` 会拒绝"标题写了、字段没给"的节点。生成器**不声明标签**
  （标签由扫描器从源码引用扫出），所以"没有源码引用的节点没有标签"是正常状态，不是错误。

### 从图纸（图一 / 图二）迁移

`docs/notes/atlas/figures/gen_module_flow.py` 里的图一（主调度链）与图二（三个顶层驱动）
已经搬进图谱，映射规则：

| 图纸 | 图谱 |
| :--- | :--- |
| 层带（① 入口层、④ 红移循环…） | **容器**（`大框`）：带里直接放这一层的模块框；五条带就是主图（外层没有别的框） |
| 带里的方框 | **模块** = 类 / 函数；带子结构的（`compute_initial_conditions`、`入口 B`）可双击进入子图 |
| 剖分图的框（初始条件的五条产物链、E1/E2/E3 lane） | **容器**（`大框`）：挂在对应模块下，同样是带内直接放方框 |
| 方框 | 节点：标题进 `label`（框上只写标题），说明进 `summary`（检查器里看） |
| 方框第三行的 `coeval.py:743 → single_field.py:285` | **源码引用**：点一下在预览抽屉里看那几行 |
| 箭头 | 边；箭头上的青色产物标签 → 边的 `label`（悬浮或打开标签开关显示） |
| 方框的角色 | 按要素分类着色：函数/过程（紫）、驱动/入口（蓝）、参数/变量（青）、交付产物（品红） |
| 虚线（条件步骤 / 条件数据流） | `conditional: true` → 画布上的虚线 |

四个脚本（都在 `scripts/`，可重复运行）：

```bash
npm run build:atlas                                       # 生成草案 data/atlas-pipeline-draft.json
node scripts/reset-atlas-nodes.mjs  [baseUrl]             # 撤掉上一次迁移的节点/边（含初始条件那五块框）
node scripts/import-atlas-graph.mjs [baseUrl]             # 导入 + 把存量 ic: 节点整理成初始条件的五条产物链
node scripts/restructure-ic-product-chains.mjs [--apply]  # 只重组初始条件子树（dry-run 默认；数据改完刷新页面即可）
```

导入是**幂等**的：节点按 id 合并、边 id 由两端推出，重跑只会更新语义字段，
**不动坐标**（所以你手摆过的版面不会被脚本冲掉）。`data/graph.before-atlas.json`
是收拢存量节点前的备份，界面里的「历史」也能回滚。

### 按模块展开（子图标签页）

这张图按图一的逻辑读：**层带是容器，模块是类 / 函数**。

- **主图 = 五条层带**：①入口层、②编排层、③备料层、④红移循环、⑤输出层自上而下排，
  每条带里横排放着这一层的模块框；原来把它们圈起来的 `图一 · 主调度链` 外框是多余的，已去掉。
- **层带是容器**：子节点（模块）直接画在带里，带本身不能「展开」也不能「进入」。
- **模块 = 类 / 函数**：带子结构的模块（本图是 `compute_initial_conditions` 与 `入口 B · 三个顶层驱动`）
  名称后带 `· N` 徽标（N 为子结构数），双击进入它的子图标签页；不带子结构的模块双击只是选中。
- **双击模块 = 进入它的子图**：在画布上方的标签栏开一个新标签页，显示这个模块的内容（里面的装饰框连带框内节点一起铺开）；属性页的「进入子图 ↗」与右键菜单的「进入子图」是等效入口。
- **子图里先给骨架**：模块的内容若分成几块，子图顶层就是那几个装饰框。例：`compute_initial_conditions` 的子图按**产物链**分五块——
  「**前置**（输入 · 种子 · 功率谱）/ **密度链**（高分辨密度 · 低分辨密度）/ **速度链**（一阶 ZA · 二阶 2LPT）/ **vcb 链**（重子-暗物质相对速度）/ **产物与收尾**（交付下游 · 资源回收）」，
  成员表与关系计划见 `scripts/lib/ic-chains.mjs`（重组 / 导入 / 重置 / 断言脚本共用那一份）。
  被两条链共用的抽样与共轭在**各自那条链的框里各有一份**（同名、靠容器区分），所以像「实空间化」这样的步骤不再把四条分支堆在一个节点上；
  产物仍然写在**边标签**上（不新增产物节点），收尾只接"首次出现的那一份"（资源只被创建一次）。
  不允许出现「只挂一个子节点、又不承载分解信息」的空壳层——所以进子图第一眼就能读出这一层分成哪几块。
- **子图只画本层事实**：子图里只有这个模块自己的节点与边，**不派生**父层关系（没有「↗ 邻居」卡、没有虚线派生线）。想看某个模块与外部的关系，回主图看模块级的边，或在属性面板的关系列表里看——同一件事不在两个层级上重复表达。
- **连线太多可以先收起来**：在模块上右键 → 「隐藏它的关系」（属性面板里也有同一个开关），这个模块出入的线就不画了；节点本身、坐标与层级结构都不动，随时点「显示它的关系」恢复。状态记在**本机浏览器**里，刷新后保持，也不会写进图谱数据（换电脑或分享链接不带）。大框是容器、不参与关系，所以没有这个开关。
- **标签页**：主图固定在最前不可关闭；每个标签页独立记住缩放、平移与选中；当前标签页同步到 URL（`?g=<节点id>`），复制链接即可还原现场。
- **整理布局**只重排当前标签页看到的内容：容器自底向上自动合围子节点（主图 = 五条层带竖排、带内模块横排），其它标签页的坐标纹丝不动。
- **布局方式也是每个标签页各一份**：在子图里换成力导向、网格……只影响那个子图；主图与其它子图的版面、视口都不动。新开的标签页从「手动摆放」起步，保留整理好的位置。

### 虚线 = 条件 / 可选

虚线在这张画布上**只有一个含义**：「只在某些配置下才成立」。

- **虚线框**：这一步是可选的（如「仅 lagrangian 源模型时才执行」）；
- **虚线连线**：这条数据流是条件性的（如「halobox 可能是 None」）；
- 在检查器里用「条件 / 可选」开关给节点或关系打标；生成器侧写 `conditional: true`。
  可选性**必须落成数据**，标题里的「（可选）」只是文字——IC 链的二阶修正（2LPT，只在
  `PERTURB_ALGORITHM == "2LPT"` 时执行）当年就因此被画成了必走步骤。

「可以进入子图」**不用虚线**表示（改用名称后缀 `· N` 与一圈柔和光晕），
否则「可选」和「可进入」会变成同一个视觉信号。这条规则由 `npm run check:canvas` 守着。

### 关系名（箭头上的文字）什么时候显示

**默认不显示**：一屏几十个关系名会把方框与箭头压得看不清。三种情况才露出来：

| 操作 | 显示范围 |
| :--- | :--- |
| 指针停在**某个节点**上 | 与它相邻的所有关系名（同时高亮邻居、弱化其余） |
| 指针停在**某条线**上 | 只有这一条（线会加粗提亮，确认「指的是它」） |
| **选中**某条线 | 一直显示，方便对照检查器里的属性 |

弱化档只压线、不压文字；被弱化的关系名保持不显示，不抢注意力。
这四种时机（默认 / 悬浮线 / 悬浮节点 / 弱化）各有断言，见 `npm run check:canvas`。

### 方框、大框与手动摆放

- 节点是**方框**，标题写在框内（按框宽折行）。默认布局是**手动摆放**：切到这个布局后
  任何自动重排都不会发生，位置只由拖动决定。
- `大框` 是容器类型节点（检查器里的「类型」选它，或右键空白处「在此处新建大框」）。
  三种把节点装进大框的办法：
  1. **直接拖进去**——松手时按节点中心判定归属（拖出框外即自动移出）；
  2. 右键节点 → 「新建大框并放入此节点」（新框会自动包住它）；
  3. 检查器里的「所属大框」下拉（适合精确调整与嵌套）。
- 大框的尺寸由子节点撑开（compound 语义），**不需要手调大小**；拖大框会带着整个框一起走。
- **大框是容器，不参与关系**：选中它不会出现连线手柄，右键菜单与属性页也没有「拉出关系」；
  连线模式下点到它会提示「大框是容器，不参与关系」并退出连线。层与层之间的先后不靠连线表达
  ——五条带自上而下排列，跨带的调用靠模块之间的箭头读（如 `cli → 入口 A`）。
- 想自动排一次版面（例如刚导入一张大图），在工具条里换成**分层对齐**／力导向／层级等布局即可；
  换回「手动摆放」后位置就固定下来。

**分层对齐**（工具条布局下拉里的第二项，`graph/ordered.ts`）是给「整齐 + 少交叉」准备的自研算法：

- 行**沿用现状**：装饰框的子节点各成一行（层带里那一排方框）；没有装饰框时按 y 把顶层切成几排；
- 行内顺序由**重心法**决定——每个模块的横向位置取「它与相邻行相连模块位置的平均」，上下各扫两遍，
  交叉会显著减少（分层图绘制的标准做法）；同一次扫描里**每排完一行就刷新下标**，
  否则两行会按彼此上一轮的位置互相追，交叉原地打转（自检里钉着这条）；
- 整齐来自两条硬规则：**一行之内列宽统一**（取该行最宽模块，于是间距处处相等）、**所有行共用中轴**；
- **尺寸红线**：每一行折几列由「一屏预算」定——整块必须在 ≥0.85 的缩放下装进画布。
  这是这张图的老问题：铺得太散就「全局看不到、局部看不清」。踩过的两个坑都写在代码注释里：
  ① 把六行平铺成一竖列 → 整块 2500 高、要缩到 0.24；② 「行里含装饰框就单列」被层带里的一个小框触发
  → 12 层高的一条竖列。现在只有**整行都是装饰框**才单列，其余按预算折行；
- 行的上下顺序与视图中心都不动，所以可以反复点，不会越排越乱。`npm run check:canvas` 里有一组
  交叉样例断言它真的能把交叉拉直。

### 箭头与智能吸附

- 边的两个端点默认吸到**方框边界**（沿两端连线方向投影），所以箭头永远贴着框边，
  不会扎进框心。
- 选中节点后按住右侧手柄拖线：指针靠近某个方框的**四条边中点**时会吸附过去，
  松手后这个端口会随关系一起存下来（`sourcePort` / `targetPort` = `n/e/s/w`）。
  没吸到端口时留空，表示「自动选边」。
- 拖线过程中命中的节点会以吸附色高亮，预览线末端会画成套环，表示「松手就落在这里」。

### 悬浮：一个跳出来，其余退到背景

指针落在**模块**上时：

- 被指着的模块按自己的基准尺寸放大约 **1.32 倍**、描边加粗、带一圈光晕，并抬到最高图层；
- 它的**出入关系一起放大**——线加粗、箭头变大、显示关系名；
- 其余模块**连文字一起虚化**（只压填充会留一屏黑字，被指着的那个反而不好读）。

关系名**一律水平**（不随线的朝向旋转），字号 **12**（与节点标签 13 同档，产物名直接读得清），
并垫一层不透明白色底片——就是图纸里产物标签的样子，线从文字后面穿过也被盖住，横线竖线上都读得清。

**容器（大框）刻意没有悬停特效**：层带 / S09 框 / E lane 是大片背景，悬停时变色既难看又没信息量，
还会顺带触发虚化把别的元素压暗——所以指针划过容器时画布不做任何反应。
这些规则由 `npm run check:canvas` 的断言守着（模块跳出来 / 其余虚化含文字 / 关系放大 / 标签水平 /
容器无悬停 / 容器不写悬停 id）。

### 源码引用与行预览

- 检查器里点「源码」打开选择器：按路径搜文件 → 填起始/结束行 → 右侧直接预览 → 「添加引用」。
- 节点上的源码引用显示为 `路径:起始-结束`，点一下即在**源码预览抽屉**里看那几行
  （带行号、目标行高亮），也可以在 VS Code 中打开并定位到行。
- 抽屉里的源码是**按段连续可读的整个文件**：每段 300 行，打开时落在引用行所在的那一段；
  滚到上 / 下边界会**自动续一段**，向上续段做滚动锚定（读到哪里就还是哪里）。
  工具栏有三个定位按钮——**跳到文件头 / 跳到引用行 / 跳到文件尾**；头部常驻
  「已加载 x–y」与「共 N 行」，读到哪儿一目了然。
- **段只是读取与传输单位，不是显示单位**：已加载的**连续**区间会合成一个代码块、只做一次
  语法分析（跳转造成的空洞才分块）。否则每 300 行的接缝都会把跨行的文档字符串、C 的块注释、
  JS 的模板串切断——表现为接缝之后整片变色。
- 打开的位置若落在某个跨行构造**内部**（例如 `lightcone.py` 的 `r"""` 文档串从 590 行开到
  639 行，而窗口从 601 行开始），服务端会随窗口带回**一行词法前缀**（开启该构造的那一行原文），
  前端把它拼进待分析文本但不显示——它只参与语法分析，所以既不跳行号也不重复行。
  构造的识别按语言分家族（`#` / `//` / `!` 行注释、块注释、三引号、反引号模板串、反斜杠续行），
  见 `server/lib/lexState.mjs`。
- **大文件**（默认超过 2 MB 或 3000 行）照样能分段读完，但抽屉顶部会说明
  「按段加载，完整阅读建议在 VS Code 中打开」并给出具体原因，不会静默只给一小段。
  两个阈值可用 `GRAPHIFY_CODE_MAX_BYTES` / `GRAPHIFY_CODE_LARGE_LINES` 调，单次响应的
  行数上限是 `GRAPHIFY_CODE_MAX_LINES`（默认 400，段大小 300 小于它，所以正常分页不会被夹）。
- 服务端两种取法，语义分开：默认 `start/end + context`（围绕引用行多给一点上下文，
  选择器右侧预览用）、`mode=range&from=&to=`（就要这一段，抽屉分页用）。
  断言见 `npm run check:code`。
- notes 引用（章节锚点）与源码引用共用同一条 `refs` 列表，去重口径分开：
  文档看 `docId + anchor`，源码看 `文件 + 行区间`。

知识库**不放在 `Graphify/` 内部**：`server/lib/paths.mjs` 里的 `MD_DIR` 直接指向仓库根的 `docs/notes/`，
索引层每次调用都用「文件数量 + 大小 + mtime」签名比对，所以文档的新增、删除、修改点一下刷新就会同步，
不需要把文件复制进 `Graphify/`（也就不存在「改了原件忘了同步副本」的问题）。
需要指向别的目录时，用环境变量覆盖即可：

```bash
GRAPHIFY_MD_DIR=/path/to/your/notes npm run dev
```

## 上限开关（节点数 / 边数 / 画布可见数）

四处上限都能调、也都能**关掉**。关掉时写 `0`、`off`、`none`、`unlimited`、`inf`、`infinity`、`-1` 或 `∞` 都行，效果都是**不设上限**；**不设置**则与以前完全一致。

| 环境变量 | 管什么 | 默认 |
| --- | --- | --- |
| `GRAPHIFY_MAX_NODES` | 导入草案与落盘图的**节点数**上限 | 草案 2000、落盘图 5000 |
| `GRAPHIFY_MAX_EDGES` | 导入草案与落盘图的**关系数**上限 | 草案 6000、落盘图 20000 |
| `GRAPHIFY_JSON_BODY_LIMIT` | 单次 JSON 请求体上限（express 要求有限值，不能关） | `8mb` |

```bash
# 关掉节点/边上限：可导任意大的图
GRAPHIFY_MAX_NODES=off GRAPHIFY_MAX_EDGES=off npm run dev

# 只把节点上限提到 2 万
GRAPHIFY_MAX_NODES=20000 npm run dev

# 节点放开后单次请求体积不够时，同步放大请求体
GRAPHIFY_MAX_NODES=off GRAPHIFY_JSON_BODY_LIMIT=64mb npm run dev
```

- `GET /api/graph/schema` 返回的上限会跟着这几个开关走（关掉时该字段直接不出现），不会与实际校验口径不一致。

## 源码索引（哪些文件会被索引）

默认索引**整个仓库根**（`Graphify/..`），只收代码类扩展名，并跳过 `.git`、`node_modules`、
`dist`、`data`、`__pycache__`、`legacy` 等目录，以及仓库根那份构建镜像 `py21cmfast/`
（`.gitignore` 第 79 行的 `/py21cmfast/`；它是 `src/py21cmfast/` 的副本，一并索引会让每个文件出现两份）。
索引是**只读**且不复制文件的：源文件改动后点一下刷新即可同步（索引层按「文件数 + 大小 + mtime」签名比对）。

| 环境变量 | 管什么 | 默认 |
| --- | --- | --- |
| `GRAPHIFY_CODE_DIR` | 源码索引根目录 | 仓库根 |
| `GRAPHIFY_CODE_MAX_FILES` | 最多索引的文件数 | 4000 |
| `GRAPHIFY_CODE_MAX_LINES` | 单次预览最多返回的行数 | 400 |
| `GRAPHIFY_CODE_MAX_BYTES` | 声明大小上限（超过时预览里给出提示） | 2000000 |

接口：`GET /api/code`（列表，可带 `q=` 按路径过滤）、`GET /api/code/content?file=&start=&end=&context=`（行窗口）、
`POST /api/code/refresh`（强制重扫）。`file` 一律是**相对仓库根、正斜杠**的路径；解析后必须仍落在索引根内，
且扩展名在白名单里——`../` 逃逸与 `.passwd` 这类请求一律 400。

## 把文档放进知识库

1. 把 markdown 文件放进仓库根的 `docs/notes/`（可建子目录）；
2. 在界面左侧面板点刷新按钮重新扫描；
3. 选中节点后点击文档（或点章节右侧的 `+`，或把文档拖到节点上）即可建立引用。

文件名建议使用字母、数字、下划线或连字符，避免空格，便于稳定引用。

## 命令行导入

```bash
npm run import -- draft.json --dry-run    # 只预览差异
npm run import -- draft.json              # 合并写入（按 id / label 去重）
cat draft.json | npm run import -- -      # 从标准输入读取
```

## 数据与版本控制

- 根仓库的 `.gitignore` 里有全局 `data/`、`dist/`、`*.png`、`*.csv` 规则，因此 `Graphify/data/` 默认不会被 git 跟踪。若希望把图谱数据入库，用 `git add -f data/graph.json`。
- 需要入库的图形资源请使用 SVG（根规则只忽略 PNG）。
- `data/history/` 会随时间增长，已在 `Graphify/.gitignore` 中忽略。

## 常见问题

**页面能打开但图谱一直转圈？** 说明 `/api/graph` 没有返回。查看启动终端是否有报错；必要时删除 `data/graph.json` 让服务重建空图。

**页面停在「正在启动 Graphify…」，或控制台报 `does not provide an export named …`？** 开发服务里缓存了失效模块（磁盘代码已改、服务仍在提供热更新之前的转换结果，该模块会被当作空模块返回）。先按 `Ctrl/Cmd + Shift + R` 硬刷新；仍是这一屏就在 `Graphify/` 目录停掉 `node server/index.mjs`、删掉 `node_modules/.vite`，再重新 `npm run dev`。这种状态下 `npm run build` 通常是通过的——问题只在开发服务的转换缓存里，不在源码。

**`data/graph.json` 被写坏了怎么办？** 服务读取失败会自动回退为空图并在终端打印原因。可以在 `data/history/` 里找到最近一份快照，复制回 `graph.json`，或用界面里的「历史」面板回滚。

**VS Code 跳转没反应？** 浏览器只有在系统注册了 `vscode://` 协议时才能唤起编辑器。若在远程/WSL 环境需要自定义协议或路径前缀，可设置环境变量后重新构建：

```bash
VITE_VSCODE_URI_TEMPLATE="vscode://vscode-remote/wsl+Ubuntu{path}:{line}" npm run build
```

失败时抽屉内的复制按钮会退化为「复制路径」，可以手动粘贴到编辑器。

**想要 LLM 帮我建图？** 见 `docs/LLM_API.md`，或在界面的「导入」对话框里点「复制 LLM 指令」。
